# 开发与运行时文档规范

> 文档类型：规范
> 状态：生效
> 更新日期：2026-09-26
> 适用范围：Azure Engine 新增及维护中的 Markdown 文档

## 目录与唯一来源

产品总计划位于 `docs/plans/azure-engine-plan.md`。实现说明保存在主题文档中，后续运行时模块文档使用 `docs/runtime/<module>.md`。阶段证据使用 `docs/acceptance/<phase>/<date>.md`。架构决策使用 `docs/decisions/<number>-<topic>.md`。

每项行为只有一个维护入口，其他页面通过链接引用。计划陈述目标，运行时文档陈述已验证行为，验收记录陈述测试事实。中文完整句子为主，代码、路径与约定术语保留原名。

## 文档头

每页包含一个一级标题，随后按顺序列出文档类型、状态、更新日期、适用范围。运行时页面追加源码入口与关联测试。状态采用草案、生效、归档。计划页面使用其阶段状态表。

## 运行时模块模板

二级标题顺序固定如下，各节用完整说明填充：

1. 职责与使用场景：读者目标、输入、输出和模块依赖。
2. 数据与所有权：标识、句柄、持有者、销毁顺序与失效行为。
3. 生命周期与时序：初始化、更新、暂停、恢复和关闭。
4. 接口契约：参数、默认值、前置条件、返回值、错误与副作用。
5. 线程与同步：允许调用的线程、锁、任务依赖及 GPU 同步。
6. 序列化与兼容：格式版本、迁移、未知字段和损坏数据处理。
7. 平台行为：Windows 与 Android 的能力差异和降级策略。
8. 使用示例：最小可运行示例、环境与预期结果。
9. 诊断与排错：症状、日志、复现和处理步骤。
10. 验收与证据：命令、设备、结果、限制和报告链接。
11. 参考来源：上游仓库、版本、文件与本地适配。

确实不适用的章节保留标题并说明理由。公开接口说明从源码和 Schema 核对。生成代码与自动 API 页面注明生成方式。

## 阶段计划模板

阶段页说明目标、状态、依赖、范围和接口设计。随后列出文件级任务、验收矩阵、文档同步、提交、风险及来源。任务写明可观察产出与验证方式。测试预算在实施前确定。

验收矩阵列出测试场景、输入、期望、平台、执行命令和证据路径。结果只使用通过、失败、未执行、阻塞，并记录原因。文档禁止把待实现功能写成现有能力。

## 文档同步与检查

修改公开接口、资源所有权、线程约束、序列化、平台行为或 CLI 时，同步对应主题文档。阶段结束维护总计划状态、模块文档、验收报告、README 入口及适用的 manifest。变更记录负责版本演变。主题页描述现行规则。

每次提交检查本地链接、UTF-8、标题层级、代码围栏和命令有效性。文档站发布同时执行项目既有站点构建与风格检查。API 行为由契约测试验证，人工复核解释准确性。

## 文件卫生

源代码、许可明确的资产、测试基线、构建配置和维护中的文档进入版本控制。构建、站点输出、临时捕获与分析数据进入明确标记的生成目录，并配置忽略规则。

每阶段完成时先检查 Git 状态、引用关系、文件用途与可重建方式。只删除确认属于本阶段的临时产物。用户资产、私有资源、未提交文件和来源不明的目录保留并列入清单。

历史说明由 Git 保存。仍被引用的验收证据保留稳定路径。

删除前记录精确路径，删除后检查导航、脚本和 manifest。仓库迁移与大规模清理单独提交，便于审查和恢复。
