# 反射表面快照

反射生产使用不透明场景的颜色和表面快照。
`CharacterSceneRenderer` 持有逐帧附件及图像视图。
输入几何、材质和相机沿场景公共路径提交。

## 表面布局

| 通道 | 数据 |
| --- | --- |
| R | 沿相机前向的正线性深度 |
| GB | 世界法线的八面体编码 |
| A | 零至一的感知粗糙度 |

非微表面材质和覆盖层使用粗糙度一。
法线输入须为有限的非零向量。
编码使用正零折叠约定，支持两个半球。
编码与解码由 `reflection_surface.glsl` 提供。

## 格式选择

启用屏幕空间反射时，快照优先使用 `RGBA32F`。
选择条件包括采样、附件样本数及源图像预算。
四样点源预算沿 `SceneMultisampling` 检查。
其他条件选择 `R32F` 深度快照。

捕获清单的 `reflectionSurfaceSnapshot` 记录实际格式。
值为真时，表面快照包含完整四通道数据。
深度消费者统一读取红通道。
新反射生产者须检查完整表面数据是否可用。

## 采样与生命周期

单样点快照由不透明绘制直接写入。
快照同时保存独立的硬件深度附件。
该附件在绘制后进入深度只读布局。
资源图登记其生产及前置运动读取。
四样点快照采用 `MinimumDepthSample` 解析。
完整元数据来自红通道深度最小的同一个样本。
相同深度保留样本编号较小者。

宿主持有逐帧资源，复用前等待所属提交完成。
视图及帧缓冲在图像释放前销毁。
共享深度输入继续供折射和其他深度消费者采样。

## 验证入口

`AzureRender.ReflectionSurfaceGpu` 核对法线编码。
方向集合覆盖两个半球和零分量。
`tools/test_reflection_surface_snapshot_gpu.py` 验证实际场景。
该工具覆盖反射开关及单样点、四样点两种路径。
