# 材质输入与实例坐标系

日期：2026-10-23。
本页定义现行布局、资源所有权和新增输入准入规则。
画像版本和材质文档版本分别维护。
特殊表面通过公共解释器形成运行材质。

## 纹理语义

现行每材质有九个索引纹理槽。
固定描述符与索引路径使用相同语义。
下表的绑定号指固定描述符路径。
共享环境、主阴影及宿主目标使用独立输入。

| 槽 | 固定绑定 | 语义与所有者 |
| --- | --- | --- |
| 0 | 1 | 基础颜色；画像决定颜色空间 |
| 1 | 2 | 表面法线；线性数据 |
| 2 | 3 | 金属粗糙度；可由明确画像消费 Alpha 镜面 |
| 3 | 5 | 镜面或自发光；Alpha 来源由 `specularInput` 声明 |
| 4 | 6 | 风格遮罩、漫反射色带、SDF 遮罩或折射扰动 |
| 5 | 7 | Matcap、传统高光色带、二维头发色带或双域 SDF 色带 |
| 6 | 8 | 头发独立双法线；一般材质使用缺省值 |
| 7 | 12 | 面部 SDF 或投影头发参数图 |
| 8 | 25 | 影色查找表或投影头发条纹图 |

眼睛拥有槽 0、4、5 的显式颜色空间与采样规则。
投影头发独占槽 5、6、7 的对应语义。
其可选条纹独占槽 8，与影色查找表互斥。
条纹按线性数据重复采样，上传保留独立 mip 语义。
双域 SDF 拥有槽 4、5、7。
折射和合成分支通过合法组合检查声明所有权。

普通 PBR、服饰和金属保留标准四槽。
`specularInput` 只选择已有 Alpha 来源及倍率。
皮肤和脸部的环境漫反射通过具名参数声明。
非法重叠由加载器拒绝。

## 共享深度输入

纹理绑定布局版本一声明独立的主阴影图像。
绑定 9 使用 `SAMPLED_IMAGE`，绑定 28 使用 `SAMPLER`。
固定路径与索引路径采用相同的深度输入。
深度格式、过滤状态和阴影公式由各自所有者定义。

索引数组的前两槽为共享环境与宿主色带。
材质块仍按九槽排列，起点由宿主常量传入。
基础固定路径使用十六个采样器和十六张图像。
对象阴影使用绑定 29 的独立深度图像。
该档位使用十七张图像，采样器仍为十六个。
容量不足的设备使用基础布局。
显式启用对象阴影时，宿主先检查所需能力。
捕获清单记录绑定布局版本及共享槽数。

## 材质参数布局

绑定 27 使用 `PackedMaterialSurfaceProfile`。
布局版本为 8，大小为 192 字节，对齐为 16 字节。
十二行数据由稳定材质索引读取。
首六行保持基础表面的参数顺序。
CPU 大小、偏移和表面选择均有自动检查。

| 所有者 | 使用规则 |
| --- | --- |
| 投影头发 | 双叶参数、边缘及法线、次级颜色、对象三轴 |
| 径向眼睛 | 形状、高光、散射、Matcap、直接光及 UV |
| NPR 漫反射 | 首行记录阴影和法线策略，第二行选择边缘响应，第三行保存视角色彩 |
| 通用、服饰、金属 | 第六行 ZW 声明独立镜面来源及倍率 |

第七行记录虚拟主灯的启用、混合及对象增益。
第七行 W 分量启用投影头发的显式照明。
投影头发的第五行 W 分量保存显式切线符号。
该输入取一或负一，默认值为一。
第八至十行记录条纹形状、颜色和 UV 变换。
第九行 W 分量选择条纹的漫反射调制目标。
零选择环境项，一选择环境项和已选主灯。
第六行 W 分量保存投影头发的阴影倍率。
第十一至十二行保存其光色、亮度及饱和度。
字段规则见[投影头发照明](projected-hair-lighting.md)。
各材质画像通过显式标志读取有效行。

NPR 漫反射采用独立的光色所有权。
第十一行 W 为一时，两行 RGB 提供环境及主灯颜色。
第十二行 W 保留为零，缺省两行均为零。
头发与 NPR 漫反射的所有者通过加载校验保持互斥。
捕获清单记录 `materialSurfaceProfileLayoutVersion`。
NPR 第二行 X 为零时选择屏幕深度，为一时选择视角带状响应。
第二行 Y 为一时启用有符号主光色带，Z 保存偏置。
省略主光色带输入时，Y、Z 均为零。
首行 Y 的零、一、二分别选择无、纹理、常量接收遮罩。
第四行 X 为零时采用场景可见量，为一时采用主灯阴影图。
取二时采用实例对象阴影，字段值为 `object-shadow`。
对象未启用时，该来源返回完整可见。
第四行 Y 保存局部漫反射下限倍率，默认值为一。
该分量仅由 NPR 漫反射消费，取值范围为零至四。
第三行 RGB 保存视角色彩，W 保存调制倍率。
省略视角色彩时，第三行保持全零。

条纹复用互斥槽，片元阶段采样器数量保持现行预算。
距离描边须有具名输入及显式所有权。
容量扩展同时调整 CPU 布局、程序声明和版本检查。
纹理扩展需要固定与索引两条路径的实际消费证据。
每阶段采样器和集合预算分别核对设备限制。

## 实例坐标系

实例缓冲使用 `SceneInstanceGpuData` 版本二。
大小为 496 字节，对齐为 16 字节。
三个顶点通道共用 `shaders/instance_data.glsl`。
捕获清单记录 `instanceDataLayoutVersion`。

| 字段 | 字节偏移 | 大小 |
| --- | --- | --- |
| 模型矩阵 | 0 | 64 |
| 模型视图投影矩阵 | 64 | 64 |
| 四组级联矩阵 | 128 | 256 |
| 整数元数据 | 384 | 16 |
| 面部光向 | 400 | 16 |
| 两个形变权重 | 416 | 8 |
| 对象阴影索引 | 424 | 4 |
| 保留实例标志 | 428 | 4 |
| 面部实例帧 | 432 | 64 |

矩阵采用列主序，整数元数据保留四个无符号整型。
宿主按冻结实例顺序写入在途帧缓冲。
GPU 按相同顺序读取模型、阴影及描边数据。
字段扩展同步更新共享声明、布局版本及 GPU 对照。

对象阴影索引从一开始，零表示未启用。
逐帧绑定 20 的深度范围之后存放对象记录。
记录区按十六字节对齐，头部为十六字节。
头部依次保存版本、数量、容量及零保留值。
版本二最多容纳八个 112 字节记录。
每个记录包含列主序矩阵、偏置与半径、图集矩形。
末行包含接收像素偏移与表面法线选择。
完整记录区的容量上限为 912 字节。
深度范围与对象记录使用互不重叠的同步区间。
宿主完成当前帧槽退休后更新两类实例数据。

投影头发可声明 `hair.projectedRamp.frame`。
版本 1 字段为 `schemaVersion`、`node`、`basis`。
`node` 指向唯一命名节点，`basis` 是九个列主序数值。
基底必须正交且各轴归一。

双域 SDF 通过 `headNode` 与 `headBasis` 声明同类帧。
同一网格资源中的显式帧必须一致。
缺失节点、重名节点及冲突基底产生加载错误。
材质覆盖后再次检查完整资源的帧关联。

运行帧由实例模型矩阵、当前节点姿态和基底形成。
每个实例分别消费自身姿态。
顶点程序通过派生功能位消费显式头发帧。
未声明显式帧的投影画像使用对象帧。

显式帧与绘制用的 gizmo 变换共同组合。
坐标系机制支持独立头发资产和带 SDF 的完整角色。
源角色节点名称及常量转换归属项目内容。
原生坐标系等价还需实际帧和动态姿态证据。

导入器为退化切线建立确定的正交单位回退。
自定义法线与 UV 导出的切线平行时采用同一规则。
静态变换后的退化切线共用该回退，并保留手性。
有效法线和方向长度在上传前完成检查。

## 资源所有权

图片采样元数据按最终选中的输入源解释。
九个槽共用元数据解析及语义校验。
完整材质与 glTF 加载保持相同规则。
查找表的固定采样与数据图颜色空间由材质拥有。

`SampledTextureCache` 归属单个渲染器和设备。
纹理输入不可变，缓存键包含像素及上传语义。
格式、尺寸、mip、过滤、包裹及 Alpha 规则参与身份。
加载宿主串行访问缓存。

描述符借用缓存拥有的图像和采样器。
命中会释放重复的 CPU 像素，未命中转移像素存储。
上传失败保留输入，临时对象负责回收资源。
所有 GPU 使用退休后，宿主方可销毁所属渲染器。

材质表、实例数据和纹理分别持有生命周期。
预览视图使用宿主的在途提交与退休规则。
跨视图的共享优化以测量为依据。
资源计数、常驻字节和进程峰值分别记录。

场景渲染快照保留节点消费的材质变体。
普通实例引用基础资源时，基础资源参与布局。
全部实例绑定覆盖时，首个变体保留源几何顺序。
原始文档、不可见普通实例及其他声明资源保持完整。
派生标识与声明资源冲突时，快照构建明确失败。
验证范围见[资源与片元核对](../acceptance/nr/character-composite-diagnosis.md)。
