# 渲染资源复用与实时观察

> 文档类型：运行机制与接口说明

## 所有权与容量

宿主持有当前渲染器和一个准备或缓存渲染器。
两项分别拥有其网格、材质和帧资源。
缓存键包含资源路径、指纹和材质绑定。
相同资源集可复用已完成加载的渲染器。

切关交换当前项与缓存项。
缓存记录其最后一次图形提交序号。
复用与淘汰遵守已完成提交的生命周期。
在途资源等待 GPU 完成后释放。

第三套资源进入时，准备槽位按容量淘汰。
窗口重建与资源重载释放准备槽位。
关闭宿主时释放两项及其所有 GPU 资源。
独立 Player 与编辑宿主共用该规则。

驻留容量包含当前项和缓存项。
性能验收同时核验工作集与设备本地峰值。
空场景重开复用其占位后端。
几何文档与全屏效果分别消费所属后端。

## 只读观察

启用受控验证通道后，可查询以下名称。
通道绑定回环地址并校验会话令牌。
查询在宿主线程读取当前生命周期。
输入操作使用现有受控输入接口。

| 名称 | 返回内容 |
| --- | --- |
| `game.state` | JSON 字符串，包含当前游戏与关卡状态 |
| `render.residency` | JSON 字符串，包含渲染器所有权与驻留 |

`game.state` 包含帧号、角色和任务状态。
它还包含当前关卡、加载状态与运行错误。
调用按当前世界读取，切关后查询新世界。
运行报告复用同一状态采集函数。

`render.residency` 的字段如下。

| 字段 | 含义 |
| --- | --- |
| `frame`、`renderer` | 当前帧号与活动后端 |
| `activeResourceKey`、`cachedResourceKey` | 当前项与准备槽位的资源键 |
| `entries`、`cachedReady` | 实际槽位数量与准备状态 |
| `cachedLastSubmission` | 准备槽位最后一次图形提交 |
| `completedSubmission` | 已确认完成的图形提交 |
| `buffers`、`images` | 活动 GPU 资源数量 |
| `bufferBytes`、`imageBytes` | 活动 GPU 资源字节 |

查询结果由调用方按需要保存。
宿主的运行报告使用既定容量上限。
完整预算入口见[性能说明](playable-performance.md)。
