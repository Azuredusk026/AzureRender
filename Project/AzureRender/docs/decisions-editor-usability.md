### 以 Unity 的操作逻辑为主要参考

目标是全面优化人类用户的操作体验。
用户反馈现有功能基本可用，操作逻辑仍不顺手。
优化覆盖以下工作流：

- 创建、选择和操作场景物体。
- 场景导航和视口内的工具操作。
- 顶部、底部工具区及面板布局。
- 为物体附加脚本并编辑相关属性。
- 项目设置与个人编辑器偏好。

布局、鼠标、快捷键和常用流程尽量遵循 Unity。
创建操作、层级操作和入口命名优先处理。
实现继续使用 Dear ImGui、GLFW 和 Vulkan。

### 场景预设与专用能力需要通用化

Gallery 等预设需要明确的内容和模块归属。
专用能力的配置应对应其实际使用对象。
用户指出，无相关对象的场景仍呈现 Face SDF 配置。
该反馈将作为配置归属与可发现性问题处理。

功能职责与源码目录同时体现模块边界。
模块还需声明数据归属、依赖和启用条件。

## 已检查的源码事实

设置面板按注册字段生成配置项。
字段分类依赖名称前缀和项目设置判定。
界面还展示写入来源及配置覆盖顺序。
依据为 `src/editor/panels/SettingsPanel.cpp`。

运行配置处理显式识别 `face-sdf` 功能标识。
依据为 `src/runtime/EngineSettings.cpp`。
完整依赖范围仍需继续检查。

### 示例内容与专用技术的入口

Gallery 以可选模板或示例包交付。
通用编辑器保持简洁，示例内容由用户主动选择。
Face SDF 等专用技术通过代码扩展入口接入。
通用编辑器界面只提供与通用创作相关的设置。
专用技术的参数与装配由对应扩展代码负责。
已有项目的加载与运行兼容性需要保留。

## 实施候选

以下内容是建议，尚待确认。

1. 用完整操作流程组织优化阶段。
2. 先贯通创建、选择、编辑、撤销和保存。
3. 项目设置管理项目共享配置。
4. 个人偏好管理导航、快捷键和个人界面习惯。
5. 专用技术配置归属于对应扩展代码和项目数据。
6. 通用界面呈现通用能力，扩展通过明确契约接入。
7. 场景预设通过模板或示例内容进入项目。

开发期间执行受影响的构建和短检查。
完整工作流复核集中安排在交付节点。
