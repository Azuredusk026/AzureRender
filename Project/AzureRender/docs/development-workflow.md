# 协作与验收

本页说明任务预算、验证范围与自动调度。
仓库执行约束由根目录 `AGENT.md` 维护。

## 自动执行的范围

用户要求完整执行既定计划时，助手连续完成已授权阶段。阶段之间完成检查、同步文档并提交，然后进入下一阶段。常规实现选择、可逆修复和阶段切换由助手处理。

每项任务先确定交付物、依赖和必要检查。代码检查失败时，助手定位原因、修复并复测受影响场景。环境或人工待项写入延期清单，并继续处理独立任务。

用户的新消息用于调整当前任务。状态询问得到简短回答后，执行继续。明确转向文档整理时，当前工作按文档范围进行。实施候选需要明确范围后才能成为自动执行任务。

## 任务单元

每个单元交付一项可独立核验的结果。
开始前在[开发总计划](plans/azure-engine-plan.md)确定顺序。
专项计划记录下表中的任务卡信息。
每次持有一个修改任务，完成后再接续下一项。

| 字段 | 内容 |
| --- | --- |
| 交付物 | 用户能观察的行为或明确的诊断结论 |
| 基线 | 源码提交、实际程序及相关输入指纹 |
| 假设 | 证据支持的单个原因及本次唯一变量 |
| 验证 | 最小复现命令、原门槛及受影响回归 |
| 预算 | 开始时间、排查及验证期限 |
| 结果 | 通过、失败、待调度及下一次启动条件 |

定位默认十分钟，候选修改与短检默认二十分钟。
同一问题的探索总预算默认三十分钟。
已声明的构建及采集命令按各自预算完成。
长命令等待期间可整理证据、读取独立任务。
候选测试期间保持源码、程序及输入来源稳定。

同一问题执行一次根因诊断及一次候选验证。
单次试验只改变一个有依据的因素。
编译错误使用最小修正，并计入当前预算。
新的诊断须声明新证据和预计排除的原因。

达到预算或候选再次失败时，保存最小证据。
记录已证实的事实、剩余未知和重试条件。
未通过候选放入任务产物，生产入口恢复受检基线。
随后执行优先级最高且具备条件的独立任务。

待调度项持续保留失败状态及责任范围。
相关修正、新证据或依赖变化允许重新启动。
全部剩余项存在硬依赖时，报告所需输入。
最终完成仍要求全部适用验收项通过。

## 画质核验

先冻结机位、姿态、灯组、曝光及材质来源。
用户最新指出的可见缺陷优先进入任务单元。
同一部位先完成局部截图和原门槛核验。
局部候选通过后，再进入联合场景和动态核验。

角色依次核对肤色、头发高光、阴影及透明覆盖。
场景分别核对反射细节、间接照明及运动稳定性。
每项保留原图、局部图、测量结果及实际参数。
局部数值通过与整体用户验收分别登记。

## 检查安排

本轮编辑器任务按 ED0 至 ED7 连续推进。
实施范围见[编辑器计划](plans/2026-10-14-editor-generalization.md)。
开发依赖来自交付物，最终验收依赖 ED7。

开发期间执行编译及受影响的短测试。
数据、事务和资源变化需完成对应短检查。
每次提交记录结果、范围和剩余集中待项。
代码失败按依赖修复，独立任务继续推进。

完整回归、双设备发布和候选冻结集中于 P8。
正式性能、长跑、人工和历史归因也集中于 P8。
GPU 空闲门禁用于正式批次的启动条件。
最终通过标准按既有条件与新增工作流共同判定。

| 工作 | 日常检查 | 集中检查 |
| --- | --- | --- |
| 文档与规则 | 事实、链接、文风及差异 | 导航变化时构建文档站点 |
| 局部功能或修复 | 所属目标构建、受影响用例和既有场景 | ED7 交付后在 P8 执行完整回归 |
| 渲染与资源 | 对应可见、同步和释放检查 | 设备路径或性能机制变化时测量相关指标 |
| 长时稳定性与性能 | 失败场景短检及有假设的诊断 | 冻结交付候选后执行正式批次 |

日常检查使用主开发配置，配置差异和交付节点覆盖 Debug 与 Release。GPU、性能和长跑串行执行，完整双设备发布集中在交付节点。已有结果按源码、产物指纹、环境和场景范围复用。

## 长跑启动

正式十五轮性能和三十分钟长跑属于集中交付验收。启动前记录候选来源、待解决问题、新变化及预期结论。同时列出可复用的结果和需要重新验证的范围。

相关修复或环境改善使候选具备重试资格。正式批次在集中交付节点安排，同一候选针对同一问题执行一次完整批次。失败后的后续批次需要新的修复、环境变化或用户明确要求。

环境门禁首次失败后保存诊断，继续独立工作。每个失败最多追加一次有新假设的诊断。再次失败后登记结果、负责人和重试条件，等待具体条件成立。

验收预算与失败记录保持有效。短检通过只支持对应场景，完整门禁仍按真实结果填写。人工操作、听感和制作效率使用集中复核表记录。

## 外部输入

只有缺少不可替代的输入、需要范围外授权或存在不可逆风险时，助手才请求用户决定。提问必须说明缺少什么、影响哪项任务，以及已完成哪些可推进工作。若仍有独立任务，助手在等待期间继续处理。

已授权工作完成后，助手提交结果和剩余待项。全部剩余工作都依赖外部输入时，报告硬阻塞及恢复条件。常规阶段切换和环境待项通过进度记录说明。

## 进度记录

每次更新先说明本轮完成什么，再说明正在做什么，最后给出剩余工作或可行动阻塞。使用功能名称解释任务，阶段编号用于证据索引。进度消息保持简短，详细日志存入相应验收页。

| 状态 | 含义 |
| --- | --- |
| 实现完成 | 代码或文档交付物已落盘 |
| 自动检查通过 | 指定配置与场景的机器检查通过 |
| 待集中复核 | 正式批次、设备条件或人工结果待补齐 |
| 阻塞 | 当前任务缺少继续执行的必要条件 |

阶段清单保留自身状态字段，报告时同时说明实现和验收范围。当前状态统一见[项目现状](project-status.md)，优先级统一见[开发总计划](plans/azure-engine-plan.md)。
