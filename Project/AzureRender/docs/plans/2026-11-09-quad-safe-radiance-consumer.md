# 四像素组照明消费

状态：机制与严格四帧检查通过，显著收益条件未通过。
实验入口默认关闭。

## 问题与依据

逐绘制候选已经在原生采集中启用轻量绘制。
现有记录包含十四个单色阶像素差异。
精度原因尚未完全归因，零差异标准保持有效。
本单元采用已有四像素组资格处理边界。

现有轻量程序省去普通材质的重复照明。
历史消费计数的四像素组接受率约为 85%。
逐绘制候选的轻量网格见证约占 85.5%。
相关修改完成后，统一验证兼容及净成本。

## 实现契约

轻量程序检查同帧四像素组身份。
资格不符时丢弃片元，并保持原深度。
合格消费先写入颜色和深度。
随后完整着色使用原始命令及严格 LESS 比较。

完整着色负责其余片元，保持原始绘制顺序。
快路径使用延迟深度更新语义。
资源、帧槽及缓存预算沿用既有契约。
投影、双面、回退及缺失能力继续受检。

## 检查顺序

1. 用实际 GPU 图案复现完整绘制先行的失败。
2. 实现轻量丢弃及完整绘制补充顺序。
3. 核对完整命中、混合失配及三角形边界。
4. 集中执行所属机制、同步及独立视图检查。
5. 通过后执行一次原生严格四帧。
6. 合格且覆盖达到门槛时，执行一次短时成对计时。

普通任务保留一天，全部产物写入 D 盘项目。
当前任务登记原生项目的活动输入引用。
主构建沿用现有目录，任务总预算为 2 GiB。

## 参考与边界

四像素组依据 [Vulkan 四像素组控制](https://docs.vulkan.org/features/latest/features/proposals/VK_KHR_shader_quad_control.html)。
丢弃与深度更新依据 [Vulkan 片元操作](https://docs.vulkan.org/spec/latest/chapters/fragops.html)。
CPU 八毫秒及 GPU 16.6 毫秒标准保持有效。
整体画质、正式采样与人工验收继续待通过。

## 集中兼容结果

实际 GPU 图案覆盖完整命中、混合失配及三角形边界。
两设备的针对性独立视图输出一致。
原生四帧保持 RGB 零差异，PNG 摘要也相同。
同步错误及卸载分配残留均为零。

十六个轻量程序保持延迟深度语义。
静态可达指令量至少减少约 94.2%。
这些数量表示程序规模，帧收益使用集中计时判断。
正式帧预算与整体画质状态保持原验收要求。
