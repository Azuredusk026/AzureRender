# 照明复用与接收面入口核对

## 范围与依据

生产入口为 `136dd99`。
同帧照明复用属于 RenderCore，使用既有精度、身份及整组回退契约。
原成本剥离控制推断可节省约 3.28 毫秒，实际收益仍需验证。
原候选的少量一字节差异记录见[照明复用](../acceptance/nr/surface-radiance-reuse.md)。

[阴影接收面入口](../acceptance/nr/shadow-receiver-entry.md)提供独立的导数失效证据。
本单元核对该修复与照明复用差异的关系。
假设为生产者及消费者在覆盖退出前准备接收面导数，可使缓存照明保持一致。
该关系属于待证推断，浮点收缩等其他原因继续保留。

## 执行

- [x] 核对原候选源与生产源，限制差异为接收面入口计算。
- [x] 在隔离目录编译实际生产及消费程序，执行 SPIR-V 校验。
- [x] 核对主程序、冻结资产及原有程序摘要。
- [x] 执行一次原生四帧，沿用原零像素门槛。
- [x] 根据兼容结果决定生产集成或保留隔离诊断。

仅兼容通过后，才安排与当前运行实现一致的收益对照。
正式 CPU 八毫秒、GPU 16.6 毫秒及整体画质要求持续有效。

## 产物与预算

隔离任务预留 320 MiB，完成后保留一天。
程序和项目资产引用既有路径。
独立着色器目录用于隔离旧宿主的单目录加载边界。
该目录包含约 197 MiB 的生产程序及约十二 MiB 的候选程序。
全部生成内容位于 D 卷并计入受管池。
构建及原生进程分别采用二百四十秒和六百秒上限。
精简证据只保存源码、命令、结果及必要诊断，至多 8 MiB。

## 结果

四帧与原候选的 PNG 摘要完全一致，变化像素仍为零、二、二、一。
该入口修复没有消除本候选的差异，生产集成与性能配对均未启动。
候选保持隔离，具体浮点原因继续待定位。
