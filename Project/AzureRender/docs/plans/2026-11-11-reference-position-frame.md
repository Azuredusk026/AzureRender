# 参考坐标帧实施计划

目标是让公开深度生产直接消费世界坐标流。
依据为[实际位置来源](../acceptance/nr/actual-world-depth-source.md)。
实现使用 C++、GLSL 与现行 Vulkan 渲染接口。
按本页逐项执行，由当前工作树持有单元修改。

## 接口与文件

`src/render/ReferencePositionFrame.hpp` 声明版本一坐标帧。
输入包含三个有符号轴编号及三个单精度偏移。
轴编号的绝对值为一到三，并构成完整置换。
转换先选择及反射分量，再完成一次单精度加法。

`shaders/reference_position_frame.glsl` 提供相同操作。
有限加法复用现行参考算术，保留非规格化数及符号零。
CPU 和 GPU 都按最近偶数规则核对结果。
版本、保留字段、非法轴及非有限偏移在使用前拒绝。

`ReferenceDepthConfig` 的版本二接收可选坐标帧。
`ReferenceDepthPositionFrameShaders` 持有两个顶点程序。
调用方将该程序束赋给所属深度着色配置。
默认配置继续采用相对坐标，原有程序摘要保持一致。

深度生产的推送参数占 128 字节。
轴编号编码进入控制字段，偏移使用独立的四分量行。
构造前校验坐标帧及程序集，容量符合 Vulkan 的最低推送保证。
输出和借用输入沿用深度生产的槽位与在途工作契约。

## 边界与预算

两个用途分别为实际角色世界流与独立轴向组合。
GPU 资源由调用方和所属深度生产器持有。
场景相机、剔除及拾取按后续统一视图契约接入。
Intel 九十六处深度超差继续按原门槛处理。

探索预算为三十分钟，候选实现预算为二十分钟。
正式双配置构建预算为二十分钟，GPU 批次预算为十分钟。
产物预算为 96 MiB，精简证据至多为 8 MiB。
程序集总数至多为 1024，原四帧按同来源及程序身份核对。
