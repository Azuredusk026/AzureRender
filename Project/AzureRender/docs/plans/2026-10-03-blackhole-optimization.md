# G0 前置任务：黑洞性能优化

> 文档类型：实施计划
> 状态：Complete
> 更新日期：2026-10-03
> 依据：azure-engine-plan.md、黑洞实时性能评估

## 目标与范围

在引擎基础库拆分前，完成黑洞电影档性能优化与引擎开销核验。目标为当前本机 Release、1280×720、正面相机的整帧 GPU 平均时间低于 20 ms。

任务归属于 G0 准入准备，执行顺序为 R4 完成、黑洞优化验收、G0 基础库拆分。阶段状态由开发总计划统一管理。

电影档保留四射线、1800 步上限、厚体积盘、现行分辨率和后处理。优先消除必定无贡献的采样计算。其他相机记录性能边界，并执行画面与运动回归。

## 诊断依据

现有电影档 CPU 录制约 0.24 ms，GPU 主场景约 40 ms。隔离实验采用保守盘外高度判断后约为 19 ms，四帧截图字节一致。引擎流程和效果算法的成本分别测量。

常量追踪实验约为 0.17 ms，但该结果包含简化输入下的后处理成本。它用于排查此场景的固定开销，通用引擎架构还须结合角色场景与调度数据判断。

## 文件与职责

- `shaders/blackhole.frag`：保守高度排除、重复计算与积分循环优化。
- `tools/run_blackhole_optimization.py`：固定输入、对照采样、图像比较和证据汇总。
- `tools/test_blackhole_optimization.py`：验证预算边界、样本完整性与错误退出。
- `src/scenes/BlackholeSceneRenderer.cpp`：在需要时提供内部 Pass 计时。
- `src/app/AzureRenderCapture.cpp`：维护现有 GPU 查询与分段统计。
- `docs/acceptance/blackhole/`：保存环境、源码哈希、预算和视觉回归证据。

## 验收条件

性能使用固定正面相机、固定 1/60 秒模拟步长和电影档。渲染任务独占 GPU，环境跟随本机。每轮采集 300 帧，执行三轮，分别报告整帧 GPU 平均值与百分位。

正式预算为三轮 GPU 平均值的中位数严格低于 20 ms。第一轮筛查用于选择实现方向，最终三轮仅对完成实现执行。全部采样原始值保留，GPU 波动单独说明。

五个相机的四帧截图与 60 帧运动序列均须逐帧一致。数学等价优化以输出像素比较为准。涉及视觉模型变化的候选单独建立质量门禁后再安排合入。

Debug Validation、Release、透明、能力降级及角色场景回归通过。资源卸载与窗口恢复保持现行验收条件。通用引擎问题记录具体场景、指标和修复范围。

## 目标口径与影响

20 ms 对应约 50 Hz 的 GPU 渲染预算，整机帧率还包含 CPU、呈现和调度。默认正面构图是本次性能验收场景，其他构图的成本在报告中列示。

三轮中位数降低短时设备波动对判定的影响。四射线和现行电影档参数约束画质取舍，图像一致性限制低风险优化的范围。

本任务为 G0 库拆分提供性能与同步依据。已完成阶段的验收结果保留，新增结论由本任务证据支持。

## 完成结果

正式三轮 GPU 平均值中位数为 18.071215 ms。五相机与 60 帧旋转序列共 80 对图像像素一致，Debug 与 Release 各 38 项回归通过，发布门禁通过。

结果见 [黑洞优化验收](../acceptance/blackhole/2026-10-03.md)。本任务完成后，G0 基础库拆分为 Ready。
