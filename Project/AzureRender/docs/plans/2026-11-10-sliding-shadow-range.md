# 滑动阴影范围表

目标为精确查询阴影深度块的最小值与最大值。
当前阴影过滤在每个片元中遍历矩形内的基础块。
隔离原型先核对查询语义和局部成本。
生产采用与原生整帧准入分别按既有门槛决定。

## 数据与查询

基础表的每项保存一个 8×8 深度块的范围。
附加两张表分别保存滑动 2×2、4×4 基础块的范围。
三张表保持相同宽高，按层连续保存。
范围合并使用完整单精度最小值与最大值。

矩形查询选择不大于短边的最大已存块。
当四角块完整覆盖查询区域时，读取至多四项。
其他矩形继续逐项合并基础表。
非法尺寸、溢出或越界坐标须明确拒绝。

每张表由调用方持有，查询计划只保存索引。
原型覆盖普通矩形及阴影图集边缘的窄矩形。
随机范围和独立逐项参考共同验证精确性。
基础深度域为有限的零至一单精度值。

## 隔离核对

- [ ] 先取得缺失查询接口的预期失败。
- [ ] 按独立逐项参考验证全部合法和非法边界。
- [ ] 核对 GPU 构表、查询及完整位值。
- [ ] 比较直接遍历和范围表的局部成本。
- [ ] 记录内存、构表开销及适用查询范围。
- [ ] 按原准入标准决定生产接入范围。

原型源和程序保存在所属受管任务。
当前原生四帧与整帧计时的新增次数为零。
局部查询速度只解释查询夹具的工作量。
整帧收益须由实际热点范围和成本共同支持。

## 预算与回归

CPU 定位及接口核对预算十分钟。
原型实现与所属短检预算二十分钟。
GPU 单批预算五分钟，任务预留 192 MiB。
重编译及 GPU 工作使用共享锁。

原生候选须保持原四帧严格零差。
默认行为、同步、失败恢复和资源卸载均需回归。
正式八毫秒及 16.6 毫秒门槛保持有效。
未通过准入的原型保持隔离，并保存具体原因。
