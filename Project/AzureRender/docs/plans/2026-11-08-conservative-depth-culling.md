# 保守层级深度剔除

本单元入口为 `a6d16c1`。
目标热点的已有成本约为 5.0581 毫秒。
保守候选覆盖该热点约 27.88% 的成本。
本批范围为公共剔除机制及合格场景的适配。

## 公共契约

`GpuConservativeOcclusion` 属于 RenderCore。
调用方提供逐命令的局部包围盒及裁剪矩阵。
输入矩阵与实际顶点阶段使用的矩阵保持相同字节。
包围盒覆盖当前变形、编辑偏移及材质位移。

深度输入复用 `DepthPyramidGpu` 的最大值层级。
基础层采用同帧、同相机、完整尺寸的前向深度。
深度有效值位于零至一，清除值为一。
调用方发布深度采样及输入命令的读取依赖。

剔除保留命令的顺序、索引及实例身份。
符合条件的命令将实例数量写为零。
多实例命令、跨相机平面及数值资格不足时保持可见。
矩形、深度和浮点误差采用保守扩张。

资源按帧槽拥有，调用方负责全部消费退役。
一次准备返回一次录制凭据。
内部 GPU 缓冲逻辑总池至多为 128 MiB。
索引及其他外部消费的依赖由调用方发布。

独立可见性工具与普通场景共用公共机制。
阴影及特殊投影采用各自明确的资格规则。
场景只消费已完成的不透明覆盖。
深度来源与主颜色绘制按渲染图建立顺序。

## 预算与验证

关联实现预算为九十分钟，构建与所属检查为二十分钟。
本次预留 32 MiB，普通任务产物保留一天。
场景资产、捕获及主构建沿用共享路径。
所有临时内容及证据均位于项目目录。

先通过缺失公共契约的编译检查登记预期。
集中检查容量、凭据、帧槽及释放行为。
双设备验证保守性、奇数尺寸和实际命令字节。
场景工作量具备收益依据后再核对原生画面。

局部热点工作量减少目标为 20%。
正式帧预算继续采用既有交流供电条件。
整体画质、CPU 八毫秒及 GPU 16.6 毫秒门槛有效。

## 阶段结果

公共机制通过两配置及双设备检查。
实际深度工具核对 491 项输入，保守剔除 268 项。
场景候选通过严格四帧，局部成本未证明净收益。
场景生产源码与本阶段入口保持相同字节。

后续接入需复用已有主通道深度预填。
结果与归档见[机制验收](../acceptance/nr/gpu-conservative-occlusion.md)。
