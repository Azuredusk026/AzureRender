# 阶段状态与收尾流程修复

本计划解决阶段状态分散和收尾条件不清的问题。
阶段使用完成、Ready、开发中、待完成四种状态。
检查结果、历史失败与执行条件分别记录。
正式验收继续使用原有预算和实际结果。

## WF1：统一阶段状态

总计划链接统一状态表，状态表由机器清单生成。
专项清单保存实现范围与原始验证结果。
移交到 P8 的条件声明来源、归属与完成要求。
完成判断覆盖阶段自身检查及有效移交记录。

涉及 `stage-status.json`、状态页和专项清单。
校验器为 `tools/check_stage_status.py`。
行为测试为 `tools/test_stage_status.py`。

- [x] 建立状态、依赖、移交和完成判断的失败用例。
- [x] 实现统一清单、状态页及一致性校验。
- [x] 同步总计划、专项清单与文档检查入口。
- [x] 检查文风、链接及状态，提交 WF1。

## WF2：建立验收执行队列

验收队列以 P8 为唯一最终收尾阶段。
每项记录操作者、输入、来源和原有通过条件。
执行准备先核对候选及待项，随后安排实际批次。
每次运行保留通过、失败或未执行的真实结果。

涉及验收执行说明及 `acceptance-readiness.json`。
准备报告区分已有来源与需要更新的来源。
实体操作、听感和设备条件按实际可用情况登记。

- [ ] 核对全部延期项与 UI8 的新增待项。
- [ ] 给出候选准备、修复复测与集中人工复核顺序。
- [ ] 核验已有来源，记录下一次运行的必要条件。
- [ ] 同步收尾说明、证据和阶段状态，提交 WF2。

## 验证范围

本批修改文档与状态工具。
工具使用独立夹具验证错误拒绝和状态一致性。
运行时证据按已核对的源码与产物范围引用。
完整性能和长跑由对应验收队列安排。
