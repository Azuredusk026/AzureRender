# 有界开发缓存

状态：机制接入完成，所属验证通过。

## 范围与依据

原生任务读入约 127.34 MiB 的管线缓存。
新增管线后的保存状态为 `size-limit`。
同一程序的后续任务继续承担重复编译成本。
本单元处理开发准备与磁盘预算。

管线数据归属于 RHI 的可选持久缓存。
设备、驱动和缓存标识继续核对兼容性。
程序文件名称和内容决定缓存代次。
全部代次共享原有目录、锁及容量上限。

程序目录至多检查 2048 项及 1024 个 SPIR-V 文件。
单程序至多 16 MiB，读取总量至多 512 MiB。
检查失败时采用仅内存缓存。
独立视图及正式应用共同消费缓存接口。

受管工具的临时文件和 SDK 缓存归属于任务。
路径均位于项目内，并按任务期限回收。
日志采用有界头尾保存，并及时刷新进度。
原画质、CPU 和 GPU 帧预算继续有效。

## 验证范围

先验证程序内容、代次隔离与共享容量。
再核对工具环境、实际设备缓存与生命周期。
双配置构建须保持全部着色程序摘要一致。
一次冷启动与暖启动核对实际保存及重用。

本单元沿用既有着色与画质证据。
原生启动只检验缓存持久化及准备耗时。
正式帧采样与长跑按交付门禁安排。

环境变量依据为 [.NET 官方说明](https://learn.microsoft.com/en-us/dotnet/core/tools/dotnet-environment-variables)。
NuGet 路径依据为[缓存目录说明](https://learn.microsoft.com/en-us/nuget/consume-packages/managing-the-global-packages-and-cache-folders)。

## 验证结果

两配置构建及六项设备、存储检查通过。
受管环境和实际 SDK 查询确认 D 盘缓存路径。
原生暖启动的 645 次创建全部命中应用缓存。
两次保存均成功，载荷约为 26.04 MiB。

五十二项维护检查通过，一项符号链接权限用例跳过。
两份技能入口通过格式验证。
正式帧预算与整体画质继续按原条件推进。
实际记录见[验证报告](../acceptance/nr/bounded-development-cache.md)。
