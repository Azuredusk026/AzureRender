# P5-A 设备环境测量实施计划

> 文档类型：测量条件实施计划。
> 日期：2026-10-11。
> 状态：实现、回归与实测完成，阶段门禁分别维护。
> 执行方式：当前会话连续执行。

## 目标与依据

正式测量依据实际设备状态判断启动条件。
温度、热限制与降频状态来自显卡驱动。
后台负载与空闲温度趋势共同进入判断。
本计划落实用户对温度规则的明确要求。

性能预算见[收口计划](2026-10-10-p5-closure-and-user-experience.md)。
GPU、CPU、物理、内存和长跑预算继续适用。
历史批次保留原始条件、来源和判定。
新规则的结果具有独立候选身份。

## 模块与契约

实现使用现有 Python 测量工具。
环境观察归属于工具层，运行时保持既有契约。
正式测量和长跑共用设备状态解释。
驱动原始观察与测量前后来源校验分别保存。

| 文件 | 职责 |
| --- | --- |
| `tools/gpu_environment.py` | 驱动状态解析、就绪判断与有限等待 |
| `tools/performance_budget.py` | 数值预算及环境证据校验 |
| `tools/run_playable_performance.py` | 正式批次的环境观察与记录 |
| `tools/run_playable_long_run.py` | 长跑启动条件与结束观察 |
| `tools/test_performance_budget.py` | 合理初温、降频与环境失败断言 |
| `tools/test_gpu_environment.py` | 驱动解析、采样窗口和等待期限 |

公开入口包括 `snapshot` 和 `wait_until_ready`。
`environment_errors` 解释观察与测量策略。
策略、原始观察和实际判断一起写入结果。
驱动读取失败形成明确诊断。

## 默认判断条件

空闲窗口至少十秒，至少三个观察点。
窗口内温度范围至多四摄氏度。
后台 GPU 占用默认至多百分之十。
占用上限可按设备的桌面环境显式配置。

启动时保留两摄氏度的设备热余量。
热上限由运行上限与降频阈值确定。
驱动提供两者时，采用其中较低者。
驱动未提供阈值时，记录缺失及降频观察。

现代驱动提供相对热余量 T.Limit。
它直接与相对运行、降频阈值比较。
启动热余量按该相对阈值计算。
驱动目标温度单独记录为调节目标。

核心温度用于记录实际热状态。
绝对阈值与相对阈值各用对应的驱动读数。
驱动定义见[NVIDIA 测量说明](https://docs.nvidia.com/deploy/nvidia-smi/index.html#temperature)。

热降频处于活动状态时，等待环境恢复。
普通功率限制、空闲降频与热降频分别解释。
等待期限为一百八十秒，每五秒观察一次。
期限耗尽保留全部观察，并报告条件未就绪。

测量结束登记温度、负载与热降频状态。
结束观察存在热限制异常时，该轮标记失败。
启动与结束观察的覆盖范围在报告中说明。
实体体验与完整内存归因各有独立门禁。

## 重点失败输入

| 输入 | 预期行为 |
| --- | --- |
| 初温六十五度，设备稳定且有热余量 | 允许测量并保存原始温度 |
| 软件或硬件热降频活动 | 拒绝就绪，保留降频来源 |
| 后台占用超过声明上限 | 有限等待并报告负载干扰 |
| 温度持续变化或观察不足 | 等待稳定窗口 |
| 设备阈值、读数或状态无效 | 记录缺失或失败，维持证据边界 |
