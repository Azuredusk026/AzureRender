# 资产依赖索引实施计划

执行方式：当前会话自主实施，按检查项连续推进。
前置候选为材质特化提交 `286809a`。
目标：索引常驻内容以引用及文件指纹为主。
依据为[恢复计划](2026-10-30-development-recovery.md)中的启动诊断。
技术采用 C++17、nlohmann/json 和现有资产数据库。

## 结构与契约

`runtime/AssetDatabase` 负责目录、引用和缓存索引。
文件在扫描时完成 JSON 解析及已有格式校验。
依赖引用在完整路径清单建立后解析为资产身份。
运行场景由所属加载器消费完整内容。

`SourceState` 持有时间、大小、元数据及文件指纹。
结构文档的引用使用紧凑字符串列表保存。
依赖提取函数接收当前文档、扩展名及虚拟路径。
输出为尚待解析的引用，公共接口保持现行契约。

私有函数命名为 `discoverAssetReferences`。
参数依次为 `const Json&`、两个 `const std::string&`。
最后一个参数为 `const Project&`，返回字符串向量。

`AssetDatabase::refresh` 继续返回变化的资产身份。
已有内容、传递指纹及缓存载荷保持字节兼容。
新快照在完整校验成功后发布。
失败及取消保留当前记录、版本和共享快照。

## 约束

- 构建并行度为二，GPU 程序串行运行。
- 构建期间保持生产源码、头文件和着色程序稳定。
- 当前四个 P5 工作区文件保持独立。
- 实际资产及硬链接内容保持原始来源指纹。
- 正式图像、持续性能及阶段状态采用既有门槛。
- 测试项目含四份各四 MiB 的合法 JSON 文档。
- 上述索引的新增常驻分配预算为二 MiB。

## 重点输入

嵌套数组中的引用按现行遍历规则提取。
空引用与引擎内置引用按公共规则处理。
相对 glTF 资源及二维图像按所属目录解析。
数据 URI 保留为文件内容，其依赖由格式规则确定。

探针和材质槽分别保留已有字段及类型要求。
托管脚本的版本、类型和程序集继续校验。
热刷新及共享快照应保留同一引用闭包。
丢失引用、损坏 JSON 和取消均保持事务边界。

- `src/runtime/AssetDatabase.cpp`：依赖提取及扫描。

- [x] 验证四份大型文档使现行索引超出二 MiB 预算。
