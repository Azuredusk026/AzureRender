# 当前验收自主执行

## 授权与完成条件

用户要求持续自动执行，直至当前验收项全部解决。
阶段切换、常规修复及 Git 提交按当前授权直接推进。
每批交付后继续处理最高优先级的剩余项。
所有必需门槛通过后，才登记最终完成。

用户原有十二份修改标记及 `.workbuddy/` 持续保护。
CPU P95 八毫秒、GPU P95 16.6 毫秒保持有效。
正式性能、画质、交付及来源条件各自记录。
局部机制通过和短时改善具有明确的证据范围。

## 工作顺序

| 顺序 | 验收范围 | 执行与依据 |
| --- | --- | --- |
| 1 | CPU 与 GPU 主导成本 | 按[性能计划](2026-11-06-performance-bottlenecks.md)完成有收益依据的批次 |
| 2 | Q1 角色与反射画质 | 按[画质计划](2026-10-31-projected-footprint-quality.md)核对来源及可量化误差 |
| 3 | Q2 场景、动作及照明 | 完整联合场景、独立入口及受影响动态回归 |
| 4 | Q3 保存、移动及发布 | 冻结候选，验证独立包和既有可玩路线 |
| 5 | Q4 与 P8 正式条件 | 同一候选执行正式性能、双设备及长跑 |
| 6 | 集中操作复核 | 整理实际桌面输入及原清单要求的操作者结果 |

阶段依赖及状态由 [stage-status.json](stage-status.json) 持有。
Q1 至 Q4 的状态见[开发总计划](azure-engine-plan.md)。
正式遗留条件见 [P8 清单](p8-deferred-acceptance-manifest.json)。
集中操作范围见[复核清单](manual-review-manifest.json)。

## 集中验证

实现前使用阶段计时、操作量或已有捕获选取热点。
预期热点工作量减少至少 20% 时进入集中评估。
预期整帧节省 CPU 2 毫秒或 GPU 3 毫秒也可进入。
关联实现完成后统一执行所属检查、兼容及短时计时。

收益未成立的候选隔离保存，生产回到受检内容。
相同来源、产物和输入的证据按范围复用。
正式一千八百帧与完整长跑保留在合格候选阶段。
失败重试以实际修正、新证据或环境变化为前提。

## 阻塞处理

外部应用占用先核对实际负载及窗口。
可逆的环境整理与独立开发持续推进。
原始失败、用途、来源及重试触发条件完整保存。
全部剩余任务均依赖不可替代输入时，统一说明所需输入。

最终记录区分机器结果、桌面操作和操作者结论。
提交前核对差异、暂存、检查及文档同步。
最终交付绑定同一源码、资产和发布包摘要。
