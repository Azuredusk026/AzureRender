# CPU 准备批次

本单元入口为 `0a0429c`。
热点为渲染器更新，约占 CPU 工作的 56.5%。
依据见[消费范围](../acceptance/nr/cpu-consumed-preparation.md)。
更新的诊断均值为 3.628 毫秒。

本批包含三个关联措施。
透明顶点及图元分阶段处理，共用既有工作池。
静态共享姿态复用本帧局部包围盒。
运动通道仅更新发生变化的描述符。

透明准备约为 1.028 毫秒。
运动绑定准备约为 0.219 毫秒。
包围盒及材质位移边界合计约为 0.275 毫秒。
局部计时包含装饰开销，收益以集中评估为准。

批次预期节省约 0.8 毫秒，占更新成本约 22%。
目标来自透明并发及重复求值、绑定工作的减少。
实施后集中检查顺序、资源变化和异常恢复。
实际收益不足时，候选保存到任务证据。

公共透明批处理属于渲染准备机制。
调用方提供不可变拓扑、位置函数及互斥输出区间。
工作池只由拥有线程调度，内部任务使用独立工作区。
单实例及小规模输入使用现行串行路径。

运动描述符按已退役帧槽维护。
缓存比较缓冲句柄、范围、视图和采样器。
资源重建和合法输入变化触发对应绑定更新。
包围盒复用限定于本帧相同共享姿态及形态权重。

开发使用既有构建和共享资产。
新增产物预算为 128 MiB，普通保留期为一天。
一次集中短评估核对冻结输出和 CPU 局部成本。
正式供电、画质和整帧预算保持既有标准。

## 单元结果

分阶段调度的更新均值降低约 7.46%。
本批 20% 收益门槛继续有效，候选保持隔离。
生产源码及受影响检查源码均按原字节恢复。
