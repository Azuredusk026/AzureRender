# 阴影深度范围分层

## 目标与依据

源码基线为 `9a9d9aa`。
阴影接收的[成本分项](../acceptance/nr/shadow-receiver-cost.md)保留热状态失败。
本单元验证深度范围分层的保守提前返回。
正式 PCSS 的采样位置、权重及偏置保持既有规则。

[NVIDIA 软阴影资料](https://developer.download.nvidia.com/presentations/2008/GDC/GDC08_SoftShadowMapping.pdf)介绍最小最大深度层级。
该资料用于选择保守范围结构，具体布局由本项目实现。
本单元保留八像素细分块，并追加三十二像素粗分块。
粗分块只决定能否返回全亮或全暗，否则执行既有过滤。

## 资源与布局

`ShadowTileBounds` 拥有细分范围、粗分范围及对象记录。
两层范围在同一次计算调度内独立读取深度图并生成。
各工作组写入互不重叠的位置，共享内存归约具有组内屏障。
渲染图按完整深度范围同步计算写入及片元读取。

细分范围保持逐分块的实际最小值及最大值。
粗分范围覆盖合法图像中的完整分块，边界采用钳制。
对象记录从两层范围之后的十六字节对齐位置开始。
CPU 上传及片元读取共同按当前深度范围总量定位记录。

资源由帧槽持有，退休围栏及卸载顺序沿用所属契约。
支持八的整数倍图集，并检查跨分块和薄遮挡输入。
合成深度图及角色对象阴影共同验证布局和消费。
正式接入由图像、同步及成本证据共同决定。

## 验证与预算

先记录缺少层级接口及数据时的失败。
原细分范围的逐值检查继续执行。
追加粗分层、边缘、对象记录偏移及释放检查。
双设备、两配置的阴影及运动机制按原门槛回归。

四帧原生图像按原冻结参考逐字节核对。
程序变化逐份记录，未受影响的程序保持原字节。
CPU 八毫秒、GPU 十六点六毫秒及热状态条件保持有效。
单候选计时用于诊断，正式整帧收益需独立比较。

定位十分钟，候选与短检二十分钟，探索三十分钟。
两配置着色及宿主构建分别九百秒。
原生四帧九百秒，短时计时三百秒。
同一假设按一次候选执行，失败后按证据隔离或修复。

## 执行结果

状态为隔离候选，正式入口使用受检的单层深度范围。
两配置各二十项 CPU 及二十四项双设备 GPU 检查通过。
原生四帧与冻结参考逐字节一致。
具体来源及布局范围见[观察记录](../acceptance/nr/shadow-depth-hierarchy.md)。

单候选 GPU 帧均值为 32.21 毫秒，P95 为 33.65 毫秒。
热降频及热余量条件失败，成对收益资格未成立。
生产输入按候选前受检来源的字节核对。
完整画质及性能预算继续按原条件验收。
