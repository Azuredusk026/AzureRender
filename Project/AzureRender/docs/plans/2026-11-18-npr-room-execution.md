# 聪音复刻执行计划

以 Recovery Windows 1.17.3 为验收基线，完成五场景、可达玩法、界面、角色与画面，再交付本机独立包。源文件、资产身份和测试门槛沿用[原实施计划](2026-11-16-npr-room-reproduction.md)。本计划按实施依赖展开原计划 P0 至 P7，并以[功能矩阵](../acceptance/npr-room/feature-matrix.md)登记每项覆盖。

## 开始状态

工作树在提交 `cdf23b1` 时干净。日历翻页、日工时、待办同屏与七种语言已在 1280×720 和 960×540 的完整房间回放，83 项房间测试和 Lua 回归通过。启动、计时、开场两组剧情、城市窗景、部分环境及房间设置已有各自证据。源目录登记 610 个剧情组、29 个窗景、46 个环境、99 个装饰、七种语言、27 项设置和八类平台场景。全量范围以实际可达、来源证据和授权条件逐项确定。

状态使用四种证据口径。**源盘点**登记原条目和引用。**已实现**登记实现入口和当前测试边界。**已实测**要求匹配的候选、运行产物与实际回放。**外部待验**登记所需参考、设备或授权。一个条目的多种证据可以并存。

## 推进与记录

先执行 1.1，保留已有回放并补齐原关卡加载和候选绑定的可复验对账。随后推进最早可独立验收的条目。重写入预约主工作区的 D 盘和受管配额，GPU 与构建通过共享队列。空间不足登记目录、命令、预计新增字节、实际门禁和下一次复测条件。回收请求走既有协作说明。

每项完成后记录源码提交、证据摘要、输入和范围。优先将同候选的变更一起验证。状态同步到对应验收文档和功能矩阵，达到阶段门槛后提交 `feat(pN): 中文摘要`。资源、设备和外部条件按证据登记待项，继续独立工作。
