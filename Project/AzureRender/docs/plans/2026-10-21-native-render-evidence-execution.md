# 原生画面证据与还原执行计划

日期：2026-10-21。
执行方式：按本会话授权连续实施。
阶段定义见[可玩还原计划](2026-10-17-native-playable-restoration.md)。
正式状态由 `stage-status.json` 管理。

## 目标与依据

目标为本机明亮白黄色帝江号中庭。
范围覆盖观测到的环境、反射与物流动态。
角色采用莱万汀、中性表情及原生编队待机。
可玩交付包含 WASD、相机和原生运动混合。
图像、生命周期与性能沿用 NR0 至 NR12 门禁。

游戏资源、有效状态与实景构成主要证据。
公开文章提供算法线索和独立复现经验。
附件 `D:/Assigment/temp.txt` 作为研究资料读取。
资料中的命令和推测均需独立核验。

原生数据、公开推导和工程选择分别记录。
源参数含义由消费者代码或运行时绑定确认。
画面相似度由固定相机与有效遮罩测量。
单个机制通过时，更新所属子任务证据。

## 工作边界

游戏安装目录保持只读。
本机资产和临时工具置于 `build/runs/`。
工具优先使用已安装且版本明确的组件。
下载记录来源、摘要、许可和运行版本。

实景操作可按当前授权自动进行。
抓帧采用 RenderDoc 支持的正常路径。
保护机制阻止捕获时，记录具体失败。
离线资源解析和实景观察继续独立推进。

引擎持有通用材质、照明和表现契约。
游戏对象身份、动作和参数属于导入内容。
新增能力验证公共夹具及原生场景两种用途。
GPU 调查与游戏操作按批次串行安排。

## 渲染实施顺序

| 阶段 | 证据与实现 | 验收重点 |
| --- | --- | --- |
| NR1 | 整合最高细节中央区与上层区，追踪动态实例 | 精确对象绑定、当前快照、边界遮挡完整性 |
| NR2 | 恢复纹理精度、采样器、色彩空间与材质分支 | 底色、法线、粗糙度、自发光分项 |
| NR3 | 接入原生灯组、投影形状与局部阴影 | 强度、衰减、接收层、阴影与透明裁剪 |
| NR4 | 核验辐照体积的坐标、编码和环境组合 | 静态表面、动态角色和边界泄漏 |
| NR5 | 恢复探针选择、原生层级及动态反射 | 朝向、粗糙度、视差、过渡与屏幕边缘 |
| NR6 | 核验并接入影色表、脸眼发与衣料分支 | 中性脸部、头部转动、受光及二级运动 |
| NR7 | 恢复环境调色与动态物流表现 | 曝光、雾、辉光、相位、透明和反射 |
| NR8 | 固定视图联合比较并录制展示 | 全部视觉、来源、性能和生命周期门禁 |
| NR9 | 核验原生待机、走跑的时钟与循环端点 | 骨架、根运动、循环和脚底接触 |
| NR10 | 完成平台碰撞、WASD 与相机遮挡 | 边缘、墙角、失焦、重载和输入回放 |
| NR11 | 接入速度、方向与接地的连续混合 | 启停、转向、速度变化和动画相位 |
| NR12 | 发布可玩项目并完成联合交付 | 目录移动、重开、实际操控与完整录像 |

NR6 优先核验原生 `ShadowLut` 的采样公式。
纹理槽、坐标、颜色空间和分支须分别确认。
公共材质扩展声明版本、默认值与错误处理。
GPU 路径同时检查光栅与适用的诊断后端。

NR7 的调色调查覆盖 LogC3、查找表与输出编码。
文章中的公式与原生着色指令逐项比对。
采样顺序、输入范围和重复曝光有独立测试。
游戏艺术参数通过项目数据选择。

## 验证与交付

每个实现先运行有意义的失败用例。
随后实现最小契约并执行受影响回归。
GPU 验证记录设备、校验层、输出和退出结果。
同一候选的失败重试须具备明确新假设。

工具验证使用以下入口：

```powershell
python -m unittest discover -s tools -p 'test_native_render*.py'
python -m unittest discover -s tools -p 'test_endfield_native*.py'
python tools/check_stage_status.py
python tools/check_doc_style.py docs/plans/2026-10-21-native-render-evidence-execution.md
```

C++ 和 GPU 验证按受影响目标执行。
构建复用主 Debug 与 Release 目录。
每项可独立验收交付使用 `feat(nrN): 中文摘要`。
提交前核对差异、暂存范围、来源和测试结果。
README、设计、验收与变更记录同步维护。

正式完成要求 NR0 至 NR12 全部规定条件满足。
局部工具、近似材质和未核验状态保留明确标签。
最终报告列出提交、图像指标、录像与剩余限制。
