# 构建范围与产物核验

## 目标与状态

状态：实现及两配置工程增量核验完成。
日常短检构建运行产品、契约及明确选择的测试目标。
集中交付执行全部配置目标与正式回归。
每次收据明确列出构建范围、源码及产物摘要。

本轮公共头修改触发 247 个构建步骤。
Release 完整构建耗时约 893 秒，Debug 约 732 秒。
这些数据说明本次构建成本，不作为新范围的收益承诺。

## 接口与产物

`build_provenance.py build` 执行全部配置目标。
`--runtime-only` 选择运行产品及契约目标。
`--test-target` 可重复指定本轮验证的可执行目标。
测试目标与运行产品共同构建并进入收据。

运行产品包含编辑器、Player、元数据及几何工具。
资产交换、材质验证及平台启动器共同进入构建。
着色程序与已启用模块的输出进入产物摘要。
引擎契约共同核验文件清单与字节。
托管原型启用时，托管产物及完成标记共同核验。
配置、源码变化及任何已记录产物篡改均使验证失败。

验证模式直接读取收据所列的构建产物。
构建选择参数仅用于构建模式。
目标名称使用合法的单一可执行目标名称。
失败构建、缺失产物或途中源码变化均保留原收据。

## 执行与检查

1. 在隔离目录补充命令行缺失的失败控制。
2. 检查完整目标、运行目标及所选测试的实际产物。
3. 检查托管、契约、源码变化与产物篡改。
4. 检查失败及非法输入的收据保留行为。
5. 完成隔离测试后，等待当前工程回归结束再接入。
6. 使用实际工程验证目标选择、产物与配置。

隔离测试替代外部构建器，验证完整编排和文件产物。
实际工程检查使用真实 CMake 与生产构建目录。
两类结果分别标注，完整 GPU 与性能门槛保持有效。

定位十分钟，候选与短检二十分钟。
完整构建和实际工程核验按所属命令预算执行。
