# 静态变形输出复用

## 状态与范围

状态：机制及定向兼容检查通过，完整性能和画质未通过。
源码基线为 `76e91b3`。
渲染器按帧槽持有变形输出缓冲区。
静态输入可复用同一缓冲区中已经提交的输出内容。

保留现行计算程序及全部五百三十五份生产程序字节。
首次生成继续执行当前归一化与位置计算。
复用只改变后续的重复计算调度。
实际输出依照原图像及深度兼容标准验收。

## 内容有效性

输入要求无蒙皮、无动画片段及形变范围。
当前实例还需缺少动画呈现输入，且旧式形变权重为正零。
模型世界矩阵由后续顶点程序消费。
同一局部输出可适用于世界变换变化的实例。

每个帧槽按网格、顶点起点及顶点数记录内容身份。
分配或重建输出缓冲区时清空内容记录。
动态写入、范围变化及来源变化均令原记录失效。
待提交标志只在实际录制并成功提交后生效。

准备过程为每个帧槽生成单调版本。
录制回调保留对应版本及帧槽的值票据。
提交事件须对应录制结果的真实队列提交。
工作线程通过受锁队列记录实际生产票据。
同一帧槽存在多准备版本时，提交按保守失效处理。

取消保留已有效的内容，并丢弃待提交记录。
未录制的准备结果保持未生成状态。
旧图回放及不同帧槽的提交独立验证。
读写依赖继续由现有渲染图与帧围栏持有。

同步依据为 [Vulkan 同步规范](https://docs.vulkan.org/spec/latest/chapters/synchronization.html)及[官方示例](https://docs.vulkan.org/guide/latest/synchronization_examples.html)。
规范用于核对可见性与资源生命周期，具体缓存规则属于本项目设计。

## 验证与预算

先验证冷内容、提交、取消、动态覆盖及范围变化。
实际渲染器覆盖帧槽、未录制提交、旧图和缓冲区增长。
独立 GPU 夹具比较完整计算与复用的原始输出字节。
两配置、两设备及实际原生四帧保持对应范围。

完整 CPU、GPU、热状态及用户画质标准保持有效。
定位十分钟，候选及短检二十分钟。
探索三十分钟，构建每配置九百秒。
原生四帧九百秒，短时诊断每进程三百秒。

采集清单分别记录准备的调度、顶点数及已复用的实例与顶点。

实际结果、工作量及热状态失败见[验证记录](../acceptance/nr/static-skinning-output.md)。
