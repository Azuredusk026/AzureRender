## 目标、架构与技术

目标是构建可配置、可扩展和可组合的引擎。核心管理契约与生命周期，共享机制提供独立能力。应用通过配置、组件、脚本和模块装配具体玩法。AI 协作使用文本内容、生产操作和可验证结果。

技术基础为 C++17、Vulkan 1.3、GLFW 和 Dear ImGui。运行时沿用轻量 ECS、Jolt、Lua、sol2 与 RmlUi。工具沿用 CMake、Ninja、Python 和现有脚本。技术扩展由专项原型与兼容证据决定。

设计依据为[架构借鉴评估](../research/2026-10-06-gknextengine.md)。完整参考路径与哈希见[检索清单](../research/gknextengine-source-map.json)。仓库根目录的 `AGENT.md` 是开发约束。本文将全部 18 项纳入正式计划。

## 全局准入规则

1. Windows、Intel 核显与 RTX 的既有范围保持有效。Android 状态为 Deferred。
2. 引擎机制与应用规则分别拥有职责。新增公共能力提供两个不同使用场景。
3. Player 保持独立于编辑器。可选服务关闭时，核心和既有项目仍能运行。
4. UI、脚本和自动工具共享生产操作契约。输入回放另行验证控件路径。
5. 组件、设置和文档具有类型、范围、版本与错误规则。兼容变化进入迁移测试。
6. 模型输出经领域校验形成候选结果。应用通过授权范围内的生产操作完成。
7. 参考文章用于定位线索。采用依据为固定源码、实测和本项目需求。
8. 代码引用保留版权、许可和适配记录。现有开源库优先承担其成熟职责。
9. 私有动画及派生素材保持本机范围。公开证据使用许可明确资源。
10. 验收失败自行修复并复测。阶段预算、负载与断言保持有效。

采用结论分为正式采用、适配采用和原型保留。每种结论附带契约、测试与收益证据。原型保留须交付可运行原型及约束说明。其产物保持独立于正式项目装配。

## 两种复用工作流

第一种为现有探索项目，覆盖 3C、任务与发布。第二种为场景装配与资产检视工具。后者使用静态场景、注册组件和独立相机控制。其核心启动与运行调度保持应用中立。

工具项目可按需关闭角色、任务和模型服务。两种工作流共享类型、资产、编辑操作与发布能力。输入、动画、模型和玩法规则在各自配置中声明。P3 使用两个可移动项目完成交付验收。

## 性能、视觉与设备门禁

既有口径见[可玩关卡计划](third-person-playable-plan.md)。标准负载为 100 实体、4 动画角色和 8 灯。压力负载为 500 实体、16 动画角色和 16 灯。正式视觉功能按既有质量配置启用。

标准、编辑器和压力负载分别测量三轮。每轮预热 300 帧，采样 1800 帧。GPU 验收串行，采样期间冻结生产源码。记录设备、驱动、窗口、实际视口和面板状态。

| 指标 | 门禁 |
| --- | --- |
| GPU P95 | 至多 16.6 ms |
| Player CPU 工作 P95 | 至多 8 ms |
| 编辑器 CPU 工作 P95 | 至多 10 ms |
| 物理单步 P95 | 至多 2 ms |
| 预加载提交额外 P99 | 至多 8 ms |
| 提交帧 P99 | 至多 33.3 ms |
| 稳定驻留与工作集增长 | 至多 5% |
| 峰值工作集 | 至多 2 GiB |
| 设备本地峰值 | 至多 1.5 GiB |

RTX 使用既有 1080p 验收范围。Intel 使用 540p 完整任务、重开与释放范围。编辑器实际视口尺寸单独记录。新多视图和专项负载同时提供开启与关闭的对照。

视觉覆盖三场景、七个角色视角和默认渲染路径。透明、阴影、描边、蒙皮、镜像和固定描述符路径分别回归。正式长跑使用真实时钟，至少持续 1800 秒。公开交付含 20 次切关、20 次重开与正常释放。

## 通用实施与验证流程

各任务先补充有意义的失败用例。确认失败原因后实现最小公共契约。专项与受影响回归通过后同步文档。每阶段还执行完整 Debug、Release 和相关门禁。

以下命令从 `Project/AzureRender` 执行。环境变量按本机安装配置。新增测试名在子计划中标为计划注册项。通过条件为构建返回零、测试零失败和预算满足。

```powershell
$env:VULKAN_SDK = 'C:/VulkanSDK/1.4.350.0'
$env:VCPKG_ROOT = 'C:/Users/23587/Tools/vcpkg'
./tools/msvc_env.bat cmake --preset msvc-debug
./tools/msvc_env.bat python tools/build_provenance.py build --build-dir build/ninja-msvc-debug --config Debug
ctest --test-dir build/ninja-msvc-debug -C Debug --output-on-failure
./tools/msvc_env.bat cmake --preset msvc-release
./tools/msvc_env.bat python tools/build_provenance.py build --build-dir build/ninja-msvc-release --config Release
ctest --test-dir build/ninja-msvc-release -C Release --output-on-failure
cmake -DBUILD_DIR=build/ninja-msvc-release -DCONFIG=Release -P tools/run_release_gate.cmake
python tools/build_provenance.py verify --build-dir build/ninja-msvc-debug --config Debug
python tools/build_provenance.py verify --build-dir build/ninja-msvc-release --config Release
python tools/run_playable_performance.py --player build/ninja-msvc-release/AzurePlayer.exe --editor build/ninja-msvc-release/AzureRender.exe --output build/evolution/performance
```

文档通过中文文风、链接、仓库审计与严格站点构建。门禁目录按阶段保存，命名为 `build/evolution/<phase>/`。验收记录写入 `docs/acceptance/<phase>/<date>.md`。可公开证据保存在该阶段的 `evidence/<date>/`。

测试执行前检查发现列表，确认计划注册项实际存在。CTest 匹配为空时视为验收失败。构建来源工具在编译后生成并核验清单。预期失败用例必须检查断言及失败原因。
