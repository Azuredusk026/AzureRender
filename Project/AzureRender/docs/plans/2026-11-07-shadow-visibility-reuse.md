# 同帧阴影可见度复用

## 目标与依据

状态为诊断候选隔离，生产已完成恢复核验。
兼容及分支执行通过，整帧 GPU 收益未成立。
结果见[候选评估](../acceptance/nr/shadow-visibility-reuse.md)。

本批减少同帧不透明表面的重复阴影接收求值。
原私有接收控制的整帧差值约为 9.78 毫秒。
该观察有热状态限制，作为热点依据使用。
目标为消除主绘制中符合条件的重复过滤工作。

源码基线为 `8c78732`。
原生 GPU 短检均值约为二十四毫秒。
预期热点工作减少至少百分之二十。
整帧节省三毫秒为本批评估目标。

## 公共机制

RenderCore 持有按帧槽分配的阴影可见度表面。
表面包含 R32 浮点结果及四个无符号整数身份值。
身份覆盖深度位、GPU 实例、索引三角形及材质。
匹配使用同一帧、同一像素的完整整数身份。

不透明快照中的普通完整覆盖材质写入结果。
其他快照管线保持相应附件的零写入掩码。
主绘制只在身份与有效结果均匹配时复用。
未命中时执行原始完整阴影算法。

原导数计算位于缓存分支之前。
过滤样本、偏置、级联混合及浮点精度保持原入口。
动态姿态仍由同帧已准备几何决定。
帧槽内容在快照开始时清空，随后由渲染图建立依赖。

## 能力与所有权

适用条件包含单样点、片元图元身份及四个颜色附件。
纹理格式、描述符及显存预算共同决定启用资格。
缓存默认最多二百五十六 MiB。
超出预算或能力不足时使用完整算法及原附件布局。

身份顶点接口及片元程序具有独立变体。
片元图元身份所需的设备特性按实际支持启用。
新增图像、视图及帧缓冲在宿主退役后释放。
重新加载及视口重建均创建对应的新存储。

## 检查与评估

独立夹具覆盖身份冲突、相交表面及无效缓存。
单样点和能力回退共同检查资源释放。
固定描述符及绑定数组分别核对实际绑定。
关联机制完成后集中执行所属构建与检查。

冻结四帧继续采用 RGB 零像素差门槛。
实际分支覆盖及操作量达到目标后执行一次成对短检。
收益成立且环境合格后安排正式一千八百帧采样。
整体画质及原 CPU、GPU 预算保持有效。
