# 场景变换与透明准备

## 目标与范围

状态为诊断候选隔离，生产源码及程序已核对恢复。
候选通过兼容检查，整帧收益未成立。
实际结果见[批次评估](../acceptance/nr/static-transparent-preparation.md)。

本批减少 CPU 透明几何的重复准备。
同时复用输入相同的场景局部和世界矩阵。
源码基线为 `95f0f38`，使用已恢复的生产程序。
当前渲染器更新的阶段参考约为 6.69 毫秒。
既有联合帧包含 39431 个透明三角形。

关联实现包含变换缓存、静态索引、可见项及图元分类。
静态输入命中时复用完整排序结果，按帧写入 GPU 索引。
工作量核对与整帧收益分别记录。
实际收益与原 CPU P95 八毫秒门槛分别判定。

首轮透明工作量核对的避免比例为 17.7%。
主要剩余透明工作来自动态角色。
手工向量原型逐位一致，但局部成本高于标量。
本批继续针对实例准备的完整场景变换重算。

## 公共机制

新增 `StaticTransparentIndexCache.hpp`。
缓存由场景渲染器持有，主线程更新。
默认索引容量为十六 MiB，最多四千零九十六个条目。
超出容量或无法分配时执行完整准备路径。

键包含不可变几何和姿态身份、模型矩阵及形变权重。
相机位置及观察方向共同参与精确输入匹配。
浮点输入按字节匹配，非有限输入采用完整准备。
缓存只接受所属加载周期的固定姿态输入。

加载内容在周期内保持不可变。
卸载及重新加载清空缓存和图元分类。
变形、质心、深度算术及稳定排序规则保持原入口。
相机、实例、形变或资源变化时重新计算。

## 可见性与生命周期

透明主绘制仅消费当前视图的可见实例。
不可见实例保留完整索引偏移布局，按需准备内容。
重新进入视图的实例以当前输入计算或匹配。
阴影、轮廓及反射源继续消费各自既有几何。

GPU 索引缓冲仍按帧槽拥有。
宿主完成帧槽栅栏等待后写入当前内容。
CPU 缓存保存索引数值，GPU 资源沿用原退役规则。
独立玻璃夹具和联合场共同覆盖不同用途。

## 场景变换

新增 `scene/SceneTransformCache.hpp`。
缓存拥有节点身份、父链、局部输入和矩阵存储。
精确匹配局部输入，按父节点到子节点传播失效。
矩阵构造及乘法继续使用原公共函数。

重复标识、缺失父节点及自身父链保持原解析规则。
可达循环和非有限输入采用完整解析。
返回数组由缓存持有，引用有效期至下一次查询。
发布到帧快照的实例矩阵继续独立拥有数值。

默认缓存至多六万五千五百三十六个节点。
更大输入或缓存分配失败时采用完整解析。
卸载清空拓扑、矩阵及统计。
