# 加载资源身份映射

## 目标与契约

源码基线为 `e0ecf1a`。
实例准备的[阶段观察](../acceptance/nr/instance-preparation-cost.md)记录分组范围约 2.20 毫秒。
本单元按加载生命周期保存资源身份到网格键的映射。
当前帧节点通过该映射取得稳定的已加载网格键。

所属模块为场景渲染器及场景资源布局。
资源路径、材质绑定及网格顺序由加载后的场景持有。
帧输入刷新节点、照明及环境参数。
资源集合的装配通过所属加载及重载入口完成。

映射采用 `ResourceLayout` 的身份解析结果。
同一资源键的别名、重复标识和未知标识保持现行解析规则。
不可见或范围外网格键按现行分组规则筛选。
卸载清空身份映射，重新加载建立当前资源内容。

兼容场景复用以网格键及现有资源条件判定。
该入口按当前场景身份表刷新映射，并保持已加载网格顺序。
失败的兼容判定保留当前场景及映射。

## 验证与预算

先使用实际渲染器复现未使用资源别名导致的逐帧分配。
夹具保留原不透明顶点容量检查及绘制命令对照。
追加一千零二十四个未使用别名，绘制输入保持一致。
别名带来的逐帧分配增量应在四千零九十六字节以内。

两种描述符路径分别检查，重载核对当前别名映射。
场景复用覆盖更换别名后的实例解析及可选对象数量。
原生四帧按冻结参考的零像素差门槛判断。
生产程序保持原字节，帧图及 GPU 同步保持所属契约。
CPU、GPU、热状态及完整用户画质保持原验收条件。

候选修改与短检二十分钟，探索三十分钟。
两配置构建分别九百秒，原生四帧九百秒。
短时原生命令三百秒，设备预检按既有预算执行。
只验证当前分配假设，整帧收益由独立计时判断。

## 执行结果

两配置各二十项 CPU 及十二项双设备 GPU 检查通过。
一千零二十四个别名在两种描述符路径均增加零字节逐帧分配。
场景复用的资源标识变更先取得失败，映射刷新检查通过。
原生四帧与冻结参考逐字节一致。

短时 CPU 工作 P95 为 30.29 毫秒，GPU 帧为 33.96 毫秒。
驱动热余量条件失败，整帧成对收益资格未成立。
详细范围见[验证记录](../acceptance/nr/loaded-resource-identities.md)。
