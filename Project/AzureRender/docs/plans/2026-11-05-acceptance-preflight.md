# 验收入口恢复

## 目标与范围

当前执行采用[任务预算](../development-workflow.md)。
目标为恢复可追溯的构建、跨设备检查与正式测量入口。
完整画质及历史归因继续使用所属门禁。
运行证据归入本机 `automatic-acceptance` 任务目录。

## 执行单元

| 单元 | 交付物 | 检查与当前范围 |
| --- | --- | --- |
| 构建来源 | Debug 与 Release 的完整关联清单 | 两配置完整构建及产物校验通过 |
| 着色模块 | Slang 2026.8 及原型检查注册 | 启用正式检查所需配置，两配置各八项定向检查通过 |
| 纹理容量 | 实际槽数与硬件容量约束的检查 | 七项 CPU 检查通过，颜色上限保持 0.008 |
| 终端诊断 | 返回前提交完整输出行 | 失败控制与两配置的同步检查通过 |
| 图像稳定性 | Intel 的严格整图对照 | 保留重复输入的少量差异，等待新的归因证据 |
| 编辑预览 | 满足十秒预算的资源复用 | 按[管线计划](2026-11-05-pipeline-reuse.md)接续 |
| 正式测量 | 同源负载、原始计时及设备状态 | 功能候选冻结后执行原预算 |

## 构建与设备

源码及产品通过 `build_provenance.py` 关联。
完整验收配置启用 `AZURE_ENABLE_SHADER_MODULE_PROTOTYPE`。
Slang 使用 SDK 已安装的 2026.8。
模块程序位于 `shader-modules`，生产程序保留所属目录。

Intel 使用已登记驱动的筛选入口。
参数为 `VK_LOADER_DRIVERS_SELECT=*igvk64*`。
NVIDIA 的对应参数为 `*nv-vk64*`。
筛选语义见[加载器说明](https://github.com/KhronosGroup/Vulkan-Loader/blob/main/docs/LoaderDriverInterface.md)。

## 判据与证据

颜色误差上限保持为 0.008。
固定绑定须来自显式请求或已证实的容量约束。
无法解释的固定绑定及超容量索引绑定均拒绝。
整图逐字节条件和全部原始失败持续保留。

终端诊断在返回前提交完整输出行。
结构化日志、进程退出及资源计数分别核对。
同输入重复的图像差异按独立稳定性任务处理。
历史失败需要其自身证据支持因果结论。

当前结果及严格失败范围见[核验记录](../acceptance/recovery/acceptance-preflight.md)。
