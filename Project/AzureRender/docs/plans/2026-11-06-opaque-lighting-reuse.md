# 同帧不透明照明复用

## 状态与依据

状态：原型像素与分支检查通过，性能收益未成立。
当前生产保持受检实现。
基线为 `a5f4d86`，完整帧预算与热状态保持未通过。
当前原生四帧保持冻结参考 RGB 字节。
候选继续使用完整的材质、阴影、反射及 GI 输入。

既有实际帧回放中，四份通用程序合计约 18.29 毫秒。
其中两份不透明快照程序约为 6.72 毫秒。
这些数字来自回放事件，范围独立于原生 P95。
快照和主场景的共享着色提供复用候选位置。

## 借鉴与边界

Godot 固定提交为 `8cc3a574e26e`，许可为 MIT。
其分离高光合成与反射重投影用于核对职责和来源边界。
[源码及许可](../acceptance/nr/evidence/2026-11-06/opaque-lighting-research/sources.json)保存完整提交、文件摘要与原件。
本候选使用 Azure 的当前帧不透明颜色。

颜色来源关联同一视图、帧、机位及场景版本。
图依赖保证源写入先于消费，重建和来源失效时回退。
普通不透明材质按严格条件使用缓存。
角色、选中状态及诊断模式保持完整入口。

## 私有原型

私有目录只替换两份主场景通用片元程序。
源快照及所有生产着色程序保持原有字节。
普通场景材质的当前反射贡献为零时，尝试读取源颜色。
子组投票要求整个活动组满足复用条件。
该规则用于保持后续导数计算的控制流条件。

子组能力与 SPIR-V 目标由设备和编译记录共同核验。
公共实现需提供能力回退及显式的来源有效性。
原型结果只用于决定公共实现是否继续。

## 验证与预算

先检查原生四帧与原冻结参考 RGB 逐字节一致。
任何像素变化均保持失败并隔离候选。
通过后测量同一负载，并记录基线漂移与热状态。
正式验收继续使用原有一千八百帧统计。

公共实现另需验证多视图、失效、遮挡及来源归属。
两配置、两设备及不同内容共同覆盖能力回退。
定位十分钟，候选与短检二十分钟。
原生图像命令持有九百秒期限。
短时成本命令持有三百秒期限，环境预检另按原期限执行。
同一问题的探索预算为三十分钟。

实际结果见[原型记录](../acceptance/nr/opaque-lighting-reuse.md)。
