# 不透明网格的透明排序开销

## 状态与范围

状态：两配置构建及各十二项 CPU 检查通过。
源码基线为 `dea7006`。
本单元归属于 Character 场景渲染器的通用透明提交。
适用输入为同时具有不透明网格和透明网格的场景。
资源、材质和关卡身份通过现行场景配置传入。

## 依据与候选

当前透明排序先为每份网格分配按顶点数计的数组。
随后检查该网格是否具有透明图元。
候选在准备透明临时数据前筛选实际透明网格。
图元排序、变形取样和提交顺序保持原有算法。

## 失败控制与回归

CPU 夹具使用实际渲染器及 NullRHI。
同时装载小型透明网格和不透明网格。
只扩大不透明网格的顶点容量，绘制索引保持一致。
预热后统计帧更新的动态分配量。
大容量输入的增量预算为六十四 KiB。
该预算定位透明临时分配，完整帧预算保持有效。

两种描述符路径共同核对实际录制命令。
卸载后检查全部缓冲和图像资源释放。
受影响检查覆盖透明提交、节点透明度及材质。
Release 与 Debug 分别构建并核验生产着色程序。
每配置构建期限九百秒，短检查期限三百秒。
GPU 对照及实际帧收益按用户安排延期。

定位十分钟，候选与短检二十分钟。
夹具错误先做最小修正，并计入本单元预算。
候选再次失败时隔离并继续独立单元。

实际分配及延期范围见[透明排序分配验证](../acceptance/nr/opaque-transparency-scratch.md)。
