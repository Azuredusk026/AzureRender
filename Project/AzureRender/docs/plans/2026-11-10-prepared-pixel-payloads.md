# 预备像素载荷

目标为减少加载期间同时持有的解码像素。
容量依据见[无损容量核查](../acceptance/nr/texture-payload-compression-scope.md)。
原生加载记录约 6.37 GB 解码材质字节。
工作集峰值观察约为 7.45 GB。

## 所属与所有权

Foundation 提供共享不可变字节载荷及弱引用池。
载荷保存长度、完整内容分桶及可选无损压缩表示。
内容相等按完整表示或还原字节确认。
压缩失败、申请失败及碰撞保持明确的失败状态。

RenderCore 的采样缓存接收不可变载荷输入。
上传时还原所需字节，身份阶段引用原载荷。
向量入口继续保持成功移交及失败保留契约。
封存解除身份引用，清空回收 GPU 对象。

资产层记录材质像素的预备载荷。
场景及关卡准备使用相同的公共打包与还原操作。
材质绑定使用完整源像素，上传消费对应预备槽。
共享源、取消、重载及失败恢复保持独立所有权。

- [x] 验证空值、原始载荷、压缩载荷及独立所有权。
- [x] 核对双配置构建及双设备 GPU 输入等价。
- [x] 保存来源、资源释放和统计语义，并单独提交。

[入口验收](../acceptance/nr/immutable-byte-payloads.md)记录定稿结果。
两配置各十三项回归与十七个缓存用例通过。
双设备、双配置各 648 组输入逐位一致。
本阶段范围为公共载荷与缓存入口。

- [ ] 接入渲染器加载作业及后台关卡预备。
- [ ] 验证完整绑定、参数覆盖和原共享源保留。
- [ ] 回归取消、失败、重载及分步完成边界。
- [ ] 核对冻结四帧、加载峰值及实际载荷容量。
- [ ] 同步运行说明、构建收据及证据并单独提交。

像素布局、颜色、mip、采样器及 GPU 绑定保持现行契约。
身份字节与实际存储分别统计，共享引用按所有权解释。
原四帧零差及现有正式门槛持续有效。
整体内存达标需要实际加载结果确认。

每阶段实现及短检预算二十分钟。
每配置实际构建预算六百秒，检查批次三百秒。
双设备夹具预算二百四十秒，原生核对六百秒。
重任务使用共享锁，任务预留 192 MiB。
