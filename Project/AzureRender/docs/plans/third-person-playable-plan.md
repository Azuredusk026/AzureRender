# 第三人称角色与可玩关卡开发计划

> 文档类型：实施计划
> 状态：实施中，F2 为 Active
> 更新日期：2026-10-04
> 适用范围：Windows 编辑器、独立 Player 与本机角色验收

## 目标与交付

本轮交付一个可编辑、可运行、可分发的第三人称小型关卡。主角采用莱万汀，完成面部、眉毛和头发渲染。角色在关卡中播放 idle、walk，并通过基础 3C 完成移动与交互。

3C 指角色（Character）、控制（Control）与相机（Camera）。关卡包含其他角色、场景实体、障碍和交互对象。玩家完成收集、开门、触发目标与重新开始的流程。

工程交付包括可复现构建、独立动画实例、资产加载、性能观测与发布回归。产品范围和阶段状态以 [开发总计划](azure-engine-plan.md)为准。本文维护本轮接口、任务和验收要求。

## 素材准入与项目结构

### 素材状态

本机主角位于 `assets_private/laevat_skinned/`。准入模型为 `laevat_skinned_material_face_sdf.glb`。用户提供的 `Idle.fbx` 与 `Walking.fbx` 位于本机输入目录。眉毛、面部与头发通过 R5 实测定稿。

源码提供 Face SDF、Hair HN/P、Kajiya-Kay 与眉毛 Overlay 接口。角色完成度由实际素材和运行画面验收。历史截图、功能开关和统计次数用于定位，最终结果检查可见输出。

| 素材 | 最低要求 | 用途 | 当前准入状态 |
| --- | --- | --- | --- |
| 莱万汀主模型 | glTF/GLB、蒙皮、完整纹理与材质来源 | 主角外观与关卡运行 | 本机 GLB，准入报告记录复杂度 |
| 主角 idle | 同骨架、可循环、独立片段名称 | 待机表现 | 已完成 Mixamo FBX 离线重定向 |
| 主角 walk | 同骨架、可循环、原地行走 | 移动表现 | 已完成 Mixamo FBX 离线重定向 |
| run、jump、fall | 同骨架、明确循环与根运动信息 | 扩展表现 | 按素材可用性安排 |
| 第二角色 | 与主角不同的蒙皮资源，含 idle/walk | 多资源动画验收 | 自制 CC0 guide，含独立片段 |
| 场景实体 | 地面、墙体、坡道、门、箱体、收集物 | 关卡与交互 | 可使用自制资源和许可明确的模型 |

素材清单记录来源、许可、文件哈希、单位与坐标轴。还需记录骨架指纹、关节数、顶点数、材质和纹理尺寸。每个动画记录时长、采样方式、循环规则和根位移。

主角原始素材与派生模型放在本机私有项目。其绝对路径保存在被忽略的本机配置中。公开工程提供参数化路径入口和自制测试资源。

主角本机验收与公共替代资源验收分别记录。R5 和 G5 的主角完成条件包含莱万汀实测。公共角色承担 CI 与公开游戏包的素材职责。

### 动画导入契约

运行时资产格式采用 glTF 2.0 或 GLB。FBX、Unreal 动画或其他源格式先由离线工具导出。导出产物保留网格、骨架、绑定矩阵、动画名称和材质映射。

首期使用原地移动动画，世界位移由角色控制器产生。模型单位统一为米，Y 轴向上。角色正向、根节点和骨盆节点在资产配置中显式声明。

相同骨架的片段通过稳定关节名称映射。不同骨架先完成离线重定向并检查绑定姿势。片段映射使用语义名 idle、walk，运行时解析对应资源和片段。

导入验证时间键递增、有效 TRS、归一化权重与有效关节引用。采样支持 STEP 和 LINEAR。CUBICSPLINE 在离线导入时重采样为 LINEAR，并保留采样率与误差报告。

缺失片段、骨架不兼容和根位移异常产生明确错误。合成摆动动画用于管线测试。idle/walk 最终验收使用真实角色动作。

jump/fall 素材可作为扩展导入。首期跳跃的动画配置允许使用明确标注的空中姿势回退。idle/walk 的循环与移动表现属于 G5 必需验收项。

### 关卡与分发

公开示例计划放在 `assets_public/third_person/`。私有项目通过 UUID 和虚拟挂载引用主角素材。两类项目共用组件、动画图、3C 和交互接口。

关卡以 `.azurelevel` 保存，常用实体以 Prefab 保存。实体模型通过材质配置选择风格化或通用材质。角色、静态物体与灯光共用世界坐标和公共渲染流程。

独立公开包使用已确认可再分发的素材。私有主角的本机项目保存本机验收与完整性清单。新增模型进入发布任务前，先登记许可和分发范围。

## G5 独立动画与基础 3C

### 目标与接口

动画资源与实体播放状态分开持有。资源保存不可变骨架和片段，实体保存状态、时间、混合参数和姿态。GPU 关节与蒙皮输出按实例及在途帧分配。

扩展 `NodeAnimationFrame` 或等价姿态快照，携带实体身份与姿态索引。角色头部基底、Morph 和透明排序读取对应实例姿态。渲染录制只读已经准备好的快照。

角色采用相机相对移动、加减速、转向与胶囊碰撞。固定模拟步更新角色，渲染阶段插值位置、朝向和相机目标。动画根据实际移动速度切换 idle/walk，并支持交叉淡化。

第三人称相机独立于编辑器相机。相机围绕跟随目标旋转，支持俯仰限制、距离调整与平滑跟随。遮挡查询采用带半径的形状扫掠，接触时缩短距离，空间释放后平滑恢复。

### 默认操作与参数

| 操作 | 默认行为 |
| --- | --- |
| WASD | 按相机水平朝向移动，斜向输入归一化 |
| 鼠标移动 | 控制相机水平与俯仰角 |
| 滚轮 | 在配置范围内调整相机距离 |
| Space | 按角色落地与跳跃规则触发跳跃 |
| E | G6 的当前目标交互 |
| Esc | 释放游戏视口输入焦点与鼠标捕获 |
| 点击游戏视口 | 获取游戏输入焦点 |

角色配置包括速度、加速度、制动、转向速度、坡度与台阶高度。相机配置包括距离、肩偏移、俯仰范围、灵敏度和碰撞半径。默认跳跃采用 100 ms 落地宽限与 100 ms 输入缓冲。

角色与相机引用使用可验证的实体句柄。相机碰撞层覆盖关卡遮挡物，角色自身通过过滤规则排除。姿态插值处理角度绕回，保持变帧率下的连续表现。

编辑器文本输入、游戏 UI 和游戏视口按焦点分配输入。暂停冻结模拟与动画，单步推进一次固定步。失焦清理按键与鼠标状态，切关重建跟随目标。

## G6 关卡实体与交互玩法

### 目标与接口

交付一个 3 至 5 分钟的第三人称探索关卡。场景包含主角、第二角色、NPC、场景实体和交互对象。路线覆盖开放区域、狭窄通道、坡道与室内遮挡。

玩家与 NPC 交互获取目标，收集三个物件并开启一扇门。玩家通过门到达目标区，获得完成反馈。重新开始恢复对象和目标状态，可继续游玩。

交互对象使用稳定实体句柄、距离、视线和可用状态判定。多个候选按距离与稳定标识选定目标。一次按下沿触发一次操作，失效目标及时清除。

组件计划包含可交互、收集物、门、检查点和任务状态。Lua 通过受控实体查询与事件接口访问目标。对象删除、生成、切关和重启通过帧边界事务执行。

## 性能预算与测量口径

预算使用 Windows x64 Release、相同设备与驱动。每轮预热 300 帧，再采样 1800 帧，共三轮。固定路线与随机种子，记录各轮均值、P95、P99 及三轮中位数。

首轮参考设备为本机 i9-13900HX 与 RTX 4060 Laptop。F1 核对实际设备、驱动和电源模式，固定采样条件。每轮以 GPU 温度至多 55°C 开始，预算检查应用于每轮有效结果。

Player 按 1920×1080 与 60 Hz 目标验收，限制呈现等待单独记录。编辑器同时记录界面开销，标准场景 GPU 使用相同预算。CPU 提交、整帧工作与等待分别统计。

| 负载 | 内容 | GPU P95 | CPU 工作 P95 | 其他门禁 |
| --- | --- | --- | --- | --- |
| 标准关卡 | 4 个独立动画角色、100 个实体实例、8 个点光与方向阴影 | ≤ 16.6 ms | Player ≤ 8 ms，编辑器 ≤ 10 ms | 固定模拟单步 P95 ≤ 2 ms |
| 压力关卡 | 16 个独立动画角色、500 个实体实例、16 个点光 | ≤ 25 ms | Player ≤ 12 ms | 记录可见比例、Draw、蒙皮顶点和透明覆盖 |
| 预加载切关 | 公共关卡已准备并上传 | 提交帧 P99 ≤ 33.3 ms | 主线程额外停顿 ≤ 8 ms | 失败与取消保持有效关卡 |
| 30 分钟长跑 | 游玩、切关与重开循环 | 标准预算有效 | 标准预算有效 | 无持续增长，资源恢复与退出释放通过 |

标准关卡保留四级方向阴影、有效角色材质与完整游戏 UI。质量配置记录阴影尺寸、灯光、分辨率和动画档位。压力关卡属于容量验收，标准关卡承担交互帧率目标。

公共性能夹具固定为每角色至多 5 万蒙皮顶点。标准可见实体合计至多 30 万三角形，压力关卡至多 150 万。夹具、纹理和路线通过 manifest 冻结。

莱万汀的实际复杂度在 F1 登记，并参加标准关卡测量。预算失败通过实现优化、经验证的 LOD 和资源配置解决。角色外观与玩法验收保持有效。

标准公共关卡峰值专用显存目标为 1.5 GiB，进程工作集目标为 2 GiB。私有素材超过容量目标时，F2 建立纹理与网格分级并复测。图像缓冲、关节缓冲和共享资产分别统计。

10 次切关与重开后，活跃资源恢复到稳定关卡水平。允许有容量上限的缓存驻留，并记录上限。预热稳定后，相同关卡的驻留增长须在 5% 以内。

黑洞电影档继续执行现行 20 ms 三轮门禁。Character、Sample、固定描述符、CPU/GPU 蒙皮与并行路径执行适用回归。新增角色视觉参考按 R5 的验收范围登记。

## 工程规则与文档同步

每个阶段完成实现、回归、性能记录、使用说明与清理检查。状态与提交登记在总计划。完成提交使用 `feat(<phase>): <中文摘要>`，只包含该阶段相关改动。

阶段同步对应运行时文档、README、CHANGELOG、Schema 和 manifest。模块说明写明所有权、线程、失效行为、版本与诊断。文件清理核验精确路径，保留用户资产和来源未明文件。

全部阶段结束执行完整 Debug/Release 回归和实际包验收。交付汇总列出阶段、提交、测试、素材范围、预算和剩余问题。完成条件以本文和既有回归门禁共同判定。
