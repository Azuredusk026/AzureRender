## 全局准入规则

每项修复先定位职责、所有权和公共契约。
菜单、快捷键和自动工具共用生产操作。
公共能力验证两个不同项目或制作工作流。
第三方借鉴记录版本、许可与适配边界。

正式性能参数如下：

| 项目 | 固定要求 |
| --- | --- |
| GPU P95 | 至多 16.6 毫秒，包含五百实例负载 |
| Player CPU P95 | 至多八毫秒 |
| 编辑器 CPU P95 | 至多十毫秒 |
| 物理 P95 | 至多两毫秒 |
| 稳定工作集增长 | 至多百分之五 |
| 峰值工作集 | 至多 2 GiB |
| 设备本地峰值 | 至多 1.5 GiB |
| 正式采样 | 三百帧预热，一千八百帧采样 |
| 轮数 | 每类负载三轮，每轮独立通过 |
| 分辨率 | 1920 × 1080 |
| 设备环境 | 驱动热限制、降频状态与稳定空闲窗口 |

正式负载为标准、编辑器和五百实例压力场景。
探索与平台关卡各增加三轮同预算测量。
质量、光源、角色和输入轨迹沿用 P5 基线。
GPU 测试与正式测量串行执行。

工作集公式沿用 P5 的正式脚本。
有效观察至少十个，每个值大于零。
取观察序列后半段为稳定区间。
增长为区间最大值除以区间首值，再减一。

调试追踪与正式性能测量分别保存。
性能结论绑定源码、内容、工具和产物指纹。
失败、超时与中断保留原始结果。
重试需记录修复或环境变化的具体原因。

人工结果由实际操作者填写并绑定包哈希。
自动输入、截图与音效事件分别标注覆盖。
候选包在必需项通过后取得完成状态。
各阶段保持原有用户修改与未提交文件。

## 重点失败输入

| 条件 | 预期结果 | 负责阶段 |
| --- | --- | --- |
