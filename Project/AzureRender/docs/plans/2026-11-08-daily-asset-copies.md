# 每日重复资产回收

## 目标与范围

历史任务内的整套工程副本具有大量重复模型。
日常入口按天回收与存活原件完全一致的 `.glb` 副本。
目录清单在声明的历史范围建立一次，日常复用清单及已核对证明。
项目数据、记录和恢复依据均位于 D 卷的项目目录。
当前输入锁、版本管理、活动工作及嵌套工作树受到保护。

公共工具为 `tools/artifact_asset_cleanup.py`。
输入是声明根目录的清单及当前工程输入锁。
输出是完整路径、存活原件、摘要、删除状态和实际卷余量。
维护在 `artifact_maintenance.py daily --apply` 装配，沿用本机目录维护技能。
原件在回收前核对完整摘要，变动或未匹配的文件保持原状。

单日上限为 32 GiB、512 个模型文件。
每日全部维护共用一百二十秒，原缓存分项上限为 10 GiB。
活动开发进程结束后执行维护，达到预算即继续下一天。
逐文件证据在删除前持久化，日配额在删除前预留。
累计来源映射用于查询原件与回收位置。

## 执行与检查

- [x] 编写重复副本、当前输入保护、摘要差异及跨次日配额检查。
- [x] 实现完整摘要回收及每日入口装配。
- [x] 建立单个历史范围的模型清单，预览并执行有界批次。
- [x] 核对工具检查、主产物摘要、空间余量和技能部署。
- [x] 同步规则、证据及独立提交。

测试使用独立临时工程，临时目录位于 D 卷。
第二种使用方式为同一工具在独立历史根及当前工程之间的模型副本回收。
链接、目录越界、Git 跟踪内容、非有限预算及变动文件均有拒绝规则。
工具的删除范围限于清单中的模型副本。
主渲染程序及原始采集的来源和字节保持原有状态。

## 结果

一次清单登记 13668 份候选，逻辑合计约 83.10 GiB。
实际回收 313 份，卷余量增加约 11.35 GiB。
文件标识核对确认硬链接导致逐路径大小重复计数。
每日入口、累计日配额和同文件内容证明复用均进入工具检查。
详细范围见[每日模型维护](../acceptance/nr/daily-asset-copies.md)。
