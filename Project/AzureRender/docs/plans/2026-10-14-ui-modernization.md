# AzureRender 界面改进计划

日期：2026-10-14。
状态：VD0 完成；VD1 至 VD6 待完成。
本轮交付为研究、视觉提案和可执行计划。
引擎界面的实施从 VD1 开始。

## 先看要做成什么

打开程序后，先看到简洁的标志和项目中心。
选择项目后，进入层级、场景、属性和资源工作区。
常用操作容易找到，低频操作有明确入口。
菜单、按钮和快捷键表达同一个操作结果。

视觉采用中性深灰、清楚的层级和少量天蓝强调色。
操作沿用已确认的 Unity 式场景容器和编辑习惯。
基础控件与工作区组织吸收 gkNextEngine 的做法。
样式语义、焦点和项目选择参考 UE Starship。

直接打开[视觉提案](../design/ui-modernization/preview.html)。
页面可切换项目中心、工作台和设计规范。
其中的项目和场景均为示意数据。
研究依据见[参考分析](../research/2026-10-14-gknext-ui.md)。

## 本轮明确的技术选择

| 方案 | 内容 | 成本与风险 |
| --- | --- | --- |
| A：逐个面板调整样式 | 修改颜色、间距和按钮 | 首批成本低，跨面板一致性依赖持续人工维护 |
| B：公共基础层与工作台逐步迁移 | 统一控件、外壳和领域呈现 | 成本适中，阶段可以独立交付 |
| C：移植完整参考 UI 模块 | 引入参考平台、渲染和宿主适配 | 成本高，涉及 SDL3 与定制 Vulkan 后端 |

推荐方案 B，沿用 ImGui 1.92.8 停靠分支。
平台为 GLFW，渲染为现有 Vulkan 后端。
项目、资产、场景、脚本和发布继续使用既有服务。
维护范围是本地 C++、资源和布局配置。

应用支持本地离线使用，无云服务与密钥依赖。
核心界面开发无需增加桌面 UI 框架。
原生窗口标题栏继续承担系统窗口管理。
应用客户区统一绘制品牌、菜单和工具栏。

自绘系统标题栏属于后续独立平台任务。
该任务须覆盖拖动、缩放、吸附、最大化和辅助功能。
本轮的现代外观通过客户区设计完成。

## 视觉规范

以下值是本计划的首版设计参数。
全部尺寸为 100% 缩放下的逻辑像素。
界面使用统一缩放源，文字与点击范围共同缩放。

| 用途 | 首版值 | 使用规则 |
| --- | --- | --- |
| 窗口底色 | `#141414` | 外壳与结构留白 |
| 面板底色 | `#1B1B1B` | 层级、属性和资源区 |
| 浮层与分组 | `#242424` | 弹窗、下拉与组件标题 |
| 输入控件 | `#2C2C2C` | 输入区域使用稳定底色 |
| 悬停底色 | `#343434` | 普通控件悬停 |
| 分隔线 | `#393939` | 只在结构边界使用 |
| 正文／次要文字 | `#E7E7E7`／`#ACACAC` | 说明文字保持可读对比度 |
| 品牌与焦点 | `#63B3FF` | 标志、选中指示与焦点轮廓 |
| 主操作填充 | `#4B9BE8` | 配深色文字 `#101820` |
| 选中底色 | `#263E53` | 配文字、图标或轮廓共同表达 |
| 成功／警告／错误 | `#79C99A`／`#E8BB6B`／`#F28585` | 同时显示文字说明 |
| 正文／辅助／页标题 | `14`／`12`／`24` | 使用现有 Noto Sans CJK |
| 间距 | `4 / 8 / 12 / 16 / 24` | 面板统一使用间距阶梯 |
| 控件与工具条 | `28`／`36` 高 | 紧凑模式仍保留可点击范围 |
| 圆角 | 控件 `4`，卡片与弹窗 `6` | 停靠边缘保持整齐 |

普通文字对比度目标至少为 4.5:1。
交互状态覆盖悬停、按下、选中、禁用和键盘焦点。
图标按钮提供名称、快捷键及禁用原因。
主要面板使用不透明底色，视口浮层保持文字清晰。

### 标志与启动页

首版标志名为“视窗 A”，见 [SVG 源文件](../design/ui-modernization/azure-mark.svg)。
形状由字母 A 与中心三角视窗构成。
使用单色天蓝，并提供单色明暗背景呈现。
16、24、32、48 和 96 像素均需保持辨识度。

标志用于项目中心、应用图标与关于页面。
启动页显示品牌、版本和当前实际初始化步骤。
获得首个可绘制帧后显示，项目中心就绪即切换。
加载时间较短时直接显示项目中心。

进度能够计量时显示百分比。
只有阶段信息时显示步骤文字与等待指示。
失败时提供原因、日志和返回项目中心的入口。
窗口图标、启动页标志和安装资源来自同一份源图。

### 工作台布局

```text
品牌与菜单                         项目名称／未保存标记
保存与制作操作             运行／暂停／单步          发布
┌────────────┬────────────────────────┬──────────────┐
│ 场景层级   │ 场景标签与视口工具     │ 属性         │
│ 搜索       │                        │ 对象名称     │
│ 场景容器   │       场景视口         │ 组件与字段   │
│ 物体列表   │                        │ 附加组件     │
│            ├────────────────────────┤              │
│            │ 资源／日志／问题       │              │
└────────────┴────────────────────────┴──────────────┘
项目与保存状态                 后台任务／错误摘要／帮助
```

场景区域是最大单一区域。
1440×900 时，左右栏建议从 220 与 320 像素起步。
资源区建议高 200 像素，并可折叠。
这些值是默认布局，拖动后的用户布局按原规则保存。

视口左上放变换工具、坐标空间与吸附。
右上放观察方向、投影与显示选项。
低频选项收进“更多”，保留快捷键与工具提示。
视口工具只占用其实际点击区域。

窄窗口优先压缩空白并收起低频工具。
层级和属性可切换为可恢复的侧栏。
资源区保留展开入口，活动编辑字段保持可见。
布局重置与版本恢复使用稳定面板 ID。

## 功能与目录怎样分开

| 层次 | 负责什么 | 目录与约束 |
| --- | --- | --- |
| 公共界面基础 | 颜色、尺度、字体、图标、控件和容器 | 新建 `src/ui/`；只依赖 ImGui 与必要基础类型 |
| 平台与后端 | 系统窗口、输入、DPI 与 Vulkan 提交 | 保留 `src/platform/` 与当前后端实现 |
| 编辑器外壳 | 菜单、工具条、停靠和状态区 | 新建 `src/editor/shell/`；调用编辑器服务 |
| 领域控件 | 属性字段、引用选择与编辑事务事件 | `src/editor/properties/` |
| 业务面板 | 层级、属性、资源和制作界面 | `src/editor/panels/`；逐个迁移状态与绘制 |
| 业务服务 | 项目、资产、场景、撤销、脚本与发布 | 沿用现有服务目录与接口 |
| 品牌资源 | SVG、窗口图标与安装资源 | `assets_public/brand/`，由资源定位器解析 |

新建 `AzureUi` 构建目标承载公共界面基础。
`AzureEditor` 使用 `AzureUi`，依赖方向保持单向。
公共控件接收值、呈现状态和回调。
属性编辑事务事件由领域控件定义和返回。

项目中心与编辑器是基础控件的两个实际宿主。
`UiContext` 只持有字体、设计参数与缩放信息。
项目文档、渲染设备与任务线程由原所有者持有。
面板通过 `PanelContext` 和明确服务引用访问业务。

面板迁移同时检查文件位置与实际成员所有权。
独立面板持有搜索、展开、选择呈现等界面状态。
文档修改继续经过 `EditService` 与 `EditorSession`。
临时输出遵循[产物管理规则](../development/artifact-retention.md)。

## 重点风险与处理

| 风险 | 所属阶段 | 处理方式 |
