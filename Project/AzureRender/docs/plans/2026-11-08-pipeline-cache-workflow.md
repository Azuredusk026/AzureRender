# 管线缓存与迭代效率计划

## 目标与范围

管线准备在最近诊断中耗时约一百一十七秒。
RHI 的图形与计算创建入口消费设备缓存。
代表管线及原生场景分别核对跨进程缓存命中。
缓存仅保存驱动生成的管线数据，项目资产和程序按既有路径引用。

机制依据为 [Vulkan 管线缓存](https://docs.vulkan.org/samples/latest/samples/performance/pipeline_cache/README.html)。
缓存对象由设备所有者持有，RHI 消费借用句柄。
文件归属于共享开发缓存或安装项目缓存目录。
当前工程数据保持在 D 卷。
设备、驱动、缓存标识、数据完整性及容量属于持久化边界。
读写失败采用可重建缓存的恢复规则，功能及画质门槛持续有效。

## 验证与预算

初步试验只创建管线，队列提交数为零。
空缓存与跨进程读取采用相同程序、设备及创建配置。
初步文件至多十六 MiB，任务上限为 2 GiB，保留三天。
持久机制的总池及过期规则见下文。
整帧性能与整体画质继续按原正式条件验收。

## 持久机制

代表管线在跨进程读取后获得驱动的应用缓存命中反馈。
禁止即时编译的创建调用成功，队列提交数为零。
该结果允许实施持久机制，整场景启动收益继续单独验证。

开发构建共享 `build/cache/vulkan/`，跨任务及场景复用设备缓存。
安装宿主使用项目文件所在目录的 `.azure/cache/vulkan/`。
没有项目的宿主采用进程内缓存。
文件上限为 128 MiB，总池为 256 MiB，最多八项，闲置七天过期。
单个写入者使用同目录临时文件，磁盘峰值至多为 384 MiB。
文件锁在进程退出时由系统解除，写入采用原子替换。

`PipelineCacheStore` 持有格式、身份、完整性及文件池规则。
`VulkanPipelineCache` 持有设备缓存句柄，RHI 借用该句柄。
设备所有者在创建工作结束后保存，并在销毁设备前释放缓存。
损坏、设备不匹配、文件超额及文件系统错误采用空缓存恢复。
缓存内容包括设备、驱动、UUID、载荷长度与校验值。

测试先固定格式拒绝、跨设备拒绝、损坏恢复、配额及期限。
实际 Vulkan 检查覆盖图形或计算创建、跨运行读取及完整释放。
实现后合并双配置编译、受影响设备与原冻结四帧核对。

## 结果

原生四帧及跨进程复用的一帧均保持 RGB 零像素差。
两次管线准备分别为 21.732 秒及 0.140 秒。
后次创建的 636 项全部取得应用缓存命中反馈。
文件约为 26 MiB，位于共享开发缓存目录。
十二项双设备、双配置相关检查及五十一项产物工具检查通过。
正式帧预算及整体画质继续按原条件验收。
完整来源见[管线缓存验收](../acceptance/nr/pipeline-cache-workflow.md)。
