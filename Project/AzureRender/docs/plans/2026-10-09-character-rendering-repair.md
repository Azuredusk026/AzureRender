# 终末地角色渲染修复计划

> 类型：实施计划
> 状态：P0、P1 与 P2 已完成验收
> 日期：2026-10-09
> 执行方式：按任务逐项验证，每项保留独立证据

**目标：** 修复白块、材质解释和时间稳定性问题。
在受控光照下，接近参考图的层次与材质表现。

**架构：** 资产管线定义材质语义，渲染模块实现共享机制。
RHI 管理采样与资源生命周期，应用资产提供角色参数。

**技术栈：** C++、Vulkan、GLSL、Python、Node.js。

**依据：** [根由报告](../research/2026-10-09-character-rendering-diagnosis.md)与仓库根目录的 `AGENT.md`。

## 全局约束

1. 引擎机制使用材质类型与配置，角色数据保存在资产中。
2. 新参数包含单位、范围、默认值、来源及版本。
3. 格式升级提供迁移或明确拒绝，并重建派生资产。
4. 生产操作、编辑器与诊断工具使用一致配置。
5. 修复先建立失败夹具，再逐项实现和复测。
6. 已有用户改动保持原有状态，提交范围单独核对。
7. 每项保存输入、程序、着色器及输出哈希。
8. 原有性能预算与既有验收标准保持有效。

## 抗锯齿方案与质量档

抗锯齿作为重点验收项贯穿 P0 至 P2。
共享后处理提供关闭、边缘自适应及超采样三个档位。
实时默认采用边缘自适应过滤。
角色交付视频采用横纵各 2 倍的超采样。

超采样覆盖场景着色、细发片及结构描边。
每个输出像素合成四个子像素的着色结果。
颜色、法线与遮罩分别生成纹理层级。
各向异性过滤及像素导数处理高频采样。

该方案采用空间采样，无跨帧历史资源。
换资产、镜头切换及尺寸变化验证资源重建。
时间稳定性由阴影过滤和材质过滤共同验收。
运动序列保留闪烁、细节与性能的独立指标。

质量档进入 `RenderSettings` 和关卡保存格式。
编辑操作、设置覆盖、命令行及捕获清单共享该契约。
离屏场景尺寸与输出尺寸分别记录。
超出设备图像范围的配置需明确诊断。

以下是比较后插值的基本公式。
假定标准深度、固定接收深度且四点位于同级联。
当前手动过滤通过真实 GPU 夹具。

```glsl
float compare4(vec4 depths, float receiverZ, vec2 weight) {
    vec4 visible = step(vec4(receiverZ), depths);
    return mix(mix(visible.x, visible.y, weight.x),
               mix(visible.z, visible.w, weight.x), weight.y);
}
```
