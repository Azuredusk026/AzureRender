# 材质显示变换实施计划

日期：2026-11-01，归属为 Q1。
状态：机制与受影响检查通过，Q1 整体画质继续验收。
执行方式为当前会话自主实施。
最终目标及门槛由[开发总计划](azure-engine-plan.md)持有。

## 输入与目标

角色源显示使用线性输出及负二档曝光。
联合场景使用原生调色表及零档曝光。
材质倍率负责两档曝光换算，已通过原生对照。
机制与范围见[辐亮度验证](../acceptance/nr/material-radiance-normalization.md)。

单变量采集仅替换 `renderSettings.gradeLut`。
固定姿态、材质、光源、机位及其他显示参数相同。
五个内部矩形的亮度变化仍约为 16% 至 44%。
头发、皮肤及眼睛继续按来源外观验收。

材质声明自己的显示变换策略。
场景材质继续消费视图的调色及色调映射。
线性显示材质消费曝光后的线性颜色。
项目数据负责选择角色及其他风格化内容的策略。

## 公共契约

版本二画像提供可选 `displayTransform`。
枚举字符串为 `scene` 及 `linear`，缺省为 `scene`。
非法类型、未知值及版本一的显式字段触发加载诊断。
完整材质文档、编辑器与 Player 共用消费规则。

`scene` 使用所属视图的完整显示变换。
`linear` 使用曝光后裁切至零至一的线性颜色。
显示输出继续采用目标表面的颜色编码。
诊断数据保留各自的物理单位。

倍率、照明、反射及雾在显示变换之前计算。
反射表面按自身策略显示反射后的辐亮度。
乘法及加法覆盖继承已有表面的显示归属。
普通透明覆盖按实际覆盖权重组合显示归属。

具名轮廓采用所属材质的显示策略。
视图预设轮廓采用视图的显示配置。
背景及缺省材质采用场景显示策略。
全部缺省路径须通过严格图像兼容检查。

## 模块与资源

资产输入归属于 `src/assets/GltfLoader.*`。
公共画像通过新增尾行保存显示策略。
画像布局版本递增，原生数据与公共夹具分别记录来源。
纹理及几何资产保持各自的导入契约。

RenderCore 使用独立的单通道显示归属附件。
附件记录场景显示的覆盖权重，清除值为一。
不透明、裁切及透明输出共用实际片元覆盖。
各类颜色管线在同次绘制中写入该附件。

主视图与编辑视图通过同一资源契约消费附件。
多重采样的归属权重按覆盖样本平均解析。
时间重建及空间抗锯齿须验证材质边界。
资源尺寸、使用、同步与关闭顺序进入运行收据。

相关入口为以下文件与模块。

| 范围 | 入口 |
| --- | --- |
| 输入与 GPU 画像 | `GltfLoader.*`、`MaterialSurfaceProfile.hpp` |
| 主视图附件 | `AzureRenderResources.cpp`、`AzureRenderPipeline.cpp` |
| 图形任务与描述符 | `AzureRenderFrame.cpp`、`AzureRenderDescriptors.cpp` |
| 编辑视图 | `RenderViewService.*`、`RenderViewOutput.*` |
| 多重采样 | `SceneMultisampling.*` |
| 材质及轮廓 | `CharacterSceneRenderer.*`、`mesh.frag`、`outline.frag` |
| 最终显示 | `inner_outline.frag`、`view_resolve.frag` |

公共验证使用风格化检视与普通表面混合两种工作流。
核心通过类型、资源和配置消费策略。
角色名称、项目路径及参考身份由项目数据持有。
既有内存及帧时预算保持有效。
