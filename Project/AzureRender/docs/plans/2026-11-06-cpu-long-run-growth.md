# CPU 长时增长定位

## 来源与目标

源码基线为 `a295e09`。
完整联合场景的一千八百帧记录显示 CPU 后段增长。
每三百帧的 CPU 均值约为二十至四十六毫秒。
对应 GPU 分组均值约为三十一毫秒。

本单元定位增长的所属阶段及输入规模。
先记录宿主、场景准备、渲染器更新及命令录制。
计时收集、命令池重置及 CSV 写入单独记录。
私有插桩保持生产源码、资源及运行产物的冻结字节。

## 验证与预算

诊断覆盖第三百至第二千零八十余帧。
四组各二十帧的细分记录用于比较阶段增长。
采集两千一百帧，原生总时间按插桩诊断解释。
生产修复由实际阶段及调用证据决定。

定位十分钟，私有构建三百秒，原生诊断六百秒。
候选及短检二十分钟，探索总预算三十分钟。
涉及运行机制的改动需通过受影响检查。
图像、设备、长跑及帧预算保持既有门槛。

## 执行状态控制

阶段采样显示节点及资源数量保持稳定。
多个 CPU 阶段同步变慢，处理器性能计数同时下降。
计时文件写入及命令池重置占比很小。
本单元继续验证进程执行状态的单变量控制。

控制使用相同私有程序及冻结输入。
通过 Windows 进程接口请求 `HighQoS`。
策略仅作用于本任务拥有的测试进程。
系统电源计划、线程优先级及亲和性保持原有配置。

设置前后的状态及目标进程身份进入记录。
下一次诊断持有六百秒期限。
方法依据为[微软 QoS 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/quality-of-service)及[进程信息接口](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-setprocessinformation)。

## 诊断结果

两批输入规模保持稳定，多个 CPU 阶段同步变慢。
系统处理器性能计数在后段下降。
显式高性能进程状态仍未消除末段增长。
本候选保持诊断用途，生产及正式工具保持受检字节。

后续复测条件及独立任务见[诊断记录](../acceptance/nr/cpu-long-run-growth.md)。
