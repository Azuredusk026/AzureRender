# 帧场景来源复用计划

## 当前状态

候选保持隔离，生产源码采用 `c3def68` 的受检输入。
局部两千轮对照的复制成本约为 0.037 毫秒。
来源读取约为 0.000014 毫秒，绝对节省约为 0.037 毫秒。
该结果未达到集中原生验证的热点门槛。
原生采集、整帧计时及 GPU 回归未调度。

## 目标与契约

本单元归属于 RenderCore 的帧输入准备。
`SceneFrameData::sceneSnapshot` 已持有只读场景的共享所有权。
渲染器复用这份所有权，节点、灯光、反射和间接光按当前快照读取。
资源布局及加载配置继续由已加载场景持有。
Player 与独立资产检视视图共同验证该机制。

空帧输入沿用最近的有效场景输入。
成功切换场景及卸载时释放帧来源。
失败的场景复用请求保留当前来源。
多个快照持有者可分别保留所属输入，公开后的内容保持只读。

`tests/SceneFrameSourceTests.cpp` 及 `CharacterSceneRenderer`。
源码、测试和构建注册补丁保存在任务证据中。

`retain` 接收 `shared_ptr<const scene::SceneDescription>`。
有效输入替换所持来源，空输入保持当前来源。
`resolve` 返回所持来源或调用者提供的加载场景引用。
`reset` 解除来源所有权。
源持有器的复制保留对应版本，用于独立消费者。

## 验证与预算

重点覆盖发布者释放、来源替换、独立消费者和场景复用失败。
测试同时核对节点、灯光及光照字段的当前值。
保留加载时的资源身份及材质布局。
局部评估要求输出一致，并消除四类动态场景字段的完整复制。
完整 CPU 收益按原功率条件及八毫秒 P95 门槛验收。

定位预算十分钟，候选和短检预算二十分钟。
主配置先完成局部工作量评估，达到门槛后合并受影响检查。
正式 GPU、十五轮和长跑沿用冻结交付阶段。
原冻结四帧、GPU 16.6 毫秒及整体画质标准持续有效。
任务产物遵循每日维护规则，项目数据存放在 D 卷。
