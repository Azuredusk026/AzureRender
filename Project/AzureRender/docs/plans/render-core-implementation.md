## 验收与预算

验收环境使用执行任务的本机 Windows 设备。报告记录 CPU、GPU、驱动、编译器、Vulkan SDK、配置和源码版本。串行与并行比较在同一设备、同一配置和同一轮次进行。

R3 性能标准编号为 `r3-budget-v2`。分辨率为 1280×720，固定相机与模拟输入。每路径采样 300 帧，四组合顺序运行，结果取三轮中位数。采样期间保持渲染任务独占，保存逐轮结果及范围。

| 场景 | CPU 录制门禁 | GPU 门禁 |
| --- | --- | --- |
| 32 个独立公共网格资源 | 并行 GPU 路径中位数 < 0.5 ms，且较串行 GPU 路径增加 ≤ 0.1 ms | 并行 GPU 平均时间较串行增长 ≤ 5% |
| 同网格 256 实例 | 并行 GPU 路径 CPU 录制中位数 < 0.5 ms | 并行 GPU 平均时间中位数 < 3 ms |

CPU 录制指标使用 `recordingMilliseconds / frames`，包含图准备、工作等待和主图执行。GPU 指标使用 `totalAverageMs`。三轮中位数应用于每轮的上述指标。

图像对照要求五条路径逐帧哈希一致，透明夹具也须通过。串行路径实际工作线程 Pass 数为零，并行路径必须产生工作线程录制。CPU 路径的间接调用数为零，GPU 不透明路径须实际消费间接参数。

完整门禁包括 Debug/Release CTest、Validation、安装、隔离运行和打包。报告列出实际 API 次数、实例数、可见比例与分段耗时。能力降级须真实执行，证据对应当前源码版本。

R3 交付目标是并行录制与 GPU 提交的正确性和有界开销。0.5 ms 约占 60 Hz 帧预算的 3%，0.1 ms 约占 0.6%。这两个上限约束总开销及并行附加成本，适用于当前阶段的公共测试负载。

并行收益以实测值报告。负载较小、线程唤醒及命令缓冲管理均会影响收益。R4 负责复杂场景、质量档位和长跑的整帧性能验证，记录各路径适用负载与瓶颈。

R1 与 R2 基础采样采用 1280×720、150 帧。结构验收覆盖七视图与黑洞冻结输出。性能记录区分 CPU 提交、GPU Pass、整帧与可见比例。

新增接口先编写会失败的行为测试，再实现与验证。Debug/Release 都执行完整 CTest。发布执行 `tools/run_release_gate.cmake`。每次提交检查差异、暂存范围、文档与测试结果。
