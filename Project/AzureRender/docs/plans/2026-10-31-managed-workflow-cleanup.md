# 托管发布目录恢复计划

日期：2026-10-31。归属为发布工具验证。
执行方式为当前会话自主实施。
实际失败来自 Release 的两种托管后端。

运行及完整性检查通过后，目录恢复报告 Windows 错误五。

## 职责与契约

`tools/test_managed_workflows.py` 负责验证工作流及清理。
测试移动由自身创建的发布包，并在结束时恢复目录。
生产发布、运行及完整性规则继续使用公共工具。
临时占用者的实际身份仍待确定。

目录恢复允许两秒内等待 Windows 临时共享冲突。
可等待的错误码为五、三十二和三十三。
其他错误及期限耗尽均向调用方报告失败。
目标目录已有内容时，保留源与目标。

独立夹具使用真实 Windows 目录句柄。
共享模式允许读写，目录租约释放后才允许移动。
夹具同时覆盖限时释放、持续占用及目标已存在。
实际工作流覆盖 CoreCLR 与 NativeAOT。
