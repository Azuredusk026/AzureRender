# 运行时节点快照复制

## 状态与目标

状态：两配置构建及各十五项受影响 CPU 检查通过。
源码基线为 `2db21ba`。
目标是减少每帧场景节点的深复制和临时分配。
既有输出顺序、世界状态及快照值所有权保持有效。
该单元归属于 Runtime 的场景快照机制。

## 依据与候选

当前 `snapshotScene` 先复制整个场景。
随后清空副本节点，再逐个复制源节点。
已有原生采样包含该函数及内存分配调用。
采样用于定位，实际帧耗时保持既有测量范围。

候选在场景副本上更新活动节点。
已移除节点通过稳定压缩处理。
资源、灯光、材质、父子关系及阴影配置共同保留。
结果继续具有独立值所有权。
该机制服务 Player 呈现及编辑器运行预览。

## 验证范围

先记录同一输入场景的一次值复制分配量。
快照用例使用含材质槽和长字符串的节点集合。
分配预算用于定位重复复制，完整帧预算维持原值。
内容检查覆盖顺序、移除节点和父节点失效。
变换、可见性、阴影及快照隔离共同检查。

Release 与 Debug 按所选目标构建并核验来源。
生命周期、相机、运行预览及场景检查共同回归。
构建期限按每配置九百秒执行。
定位十分钟，候选与短检二十分钟。
GPU 四帧及性能检查按用户安排延期。

## 本轮分配控制

Release 的一千零二十四节点夹具完成失败控制。
完整场景值复制分配 4,301,847 字节。
原快照分配 8,512,487 字节，超出本单元工作预算。
候选快照分配 4,301,847 字节，通过内容和隔离检查。

工作预算为一次文档值复制加六十四 KiB。
该预算定位重复分配，完整帧 CPU 预算保持八毫秒。
原生输出和实际帧成本按原场景另行验证。

完整结果及延期范围见[节点快照验证](../acceptance/nr/runtime-snapshot-copy.md)。
