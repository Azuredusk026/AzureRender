## 目标与架构

场景采用明亮白黄色帝江号中庭。
范围包含周边遮挡、中枢传送仓、导轨与环带。
还原范围覆盖本机观测到的全部可见环境与动态效果。
莱万汀初始位置为 `(0, 1.035, 9)`。
该位置位于平台中轴线，世界原点位于深井。

默认保持中性表情，静止展示使用原生编队待机 01。
WASD 按相机方向移动，角色朝移动方向转身。
移动、停止和转向具备连续运动动画混合。
鼠标控制第三人称观察，场景提供安全可行走区域。

游戏原资产通过离线导入器进入项目数据。
缺少的采样、光照、动画和控制能力进入通用模块。
运行时负责输入、物理、姿态和渲染之间的数据传递。
每项公共机制使用合成场景验证第二种用法。

技术栈沿用 C++17、Vulkan、Python 与 Blender。
主验证设备为 RTX 4060 Laptop GPU。
源游戏目录只读，游戏资产保存在 `build/runs/`。
公开仓库保存工具、合成夹具、设计和验收摘要。

## 执行节奏与证据

每个阶段分为证据、实现、实景接入和验收任务。
任务代号采用 `NRn-T1` 至 `NRn-T4`。
每项实现先写有意义的失败用例，再实现并回归。
每个可独立验收交付使用 `feat(nrN): 中文摘要` 提交。

每个交付记录源码提交、源摘要、配置和运行入口。
同时保存截图、日志、失败项与后续任务。
本机证据统一存入当前任务的 `build/runs/` 目录。
验收摘要写入 `docs/acceptance/nr/`。

每次调查明确一个待证明问题及其实现消费者。
取得足够证据后立即接入对应引擎分项输出。
外部条件影响某项验收时，登记重试条件并推进独立任务。
最终完成要求全部适用门禁通过。

## 量化验收与主要风险

近乎原生由来源完整性、视觉对照和交互表现共同判定。
原规格的全部门禁继续适用。
NR0 在调参前记录并冻结正式参考与误差预算。
低分辨率参考的比较只覆盖其有效分辨率。

| 检查 | 目标与测量方式 | 责任阶段 |
| --- | --- | --- |
| 静态画面 | 有效区域 SSIM ≥ 0.95，关键区域亮度中位误差 ≤ 10% | NR0、NR8 |
| 局部外观 | 脸、发丝、衣料和聚光逐项对照，无未归因显著差异 | NR2、NR3、NR6 |
| 动态场景 | 核对物流数量、轨迹、周期和可见相位；保存时间序列误差 | NR1、NR7 |
| 移动速度 | 斜向与直向速度差 ≤ 1%，不同帧率终点差 ≤ 1 厘米 | NR10 |
| 输入反馈 | 运行视口的按下与释放在下一固定步生效 | NR10 |
| 碰撞 | 平台边缘、墙角和台阶持续运行无穿透或掉入深井 | NR10 |
| 动画混合 | 权重和误差 ≤ 1e-5，无姿态跳变及位移重复应用 | NR11 |
| 脚底接触 | 平地支撑段漂移目标 ≤ 2 厘米，剔除源动作主动滑步 | NR9、NR11 |
| 实时预算 | 本机 1080p 原生分辨率目标 60 帧，记录 CPU/GPU p95 与显存 | NR12 |
| 运行稳定 | 十分钟连续移动无资源持续增长，退出无验证层错误 | NR12 |

性能目标与画面门禁同时保留。
达不到预算时记录瓶颈，按机制优化后复测。
DLSS 平衡参考与引擎原生分辨率的差异单独记录。
画面总体分数通过后仍逐项检查角色与动态遮挡。

重点检查混合中的反向输入和暂停恢复。
重点检查探针边界、透明发丝与动态阴影。
