# 照明复用管线选择实施计划

## 目标与依据

本批入口为 `a62b206`。
目标是使合格帧采用独立的轻量照明消费管线。
任一真实片元条件不符时，采用完整着色管线。
已有画质及帧预算保持有效。

依据为[消费计数](../acceptance/nr/radiance-consumption-counters.md)。
三十个回收帧槽的合格真实片元全部匹配身份。
原消费程序的完整四像素组接受率约为 85.06%。
这些数据支持构建独立管线的资格核验机制。

当前计数并未证明缓存具有整帧收益。
独立管线预期完整省去合格帧的重复照明。
额外的资格绘制、附件读写及命令提交计入净成本。
正式评估使用关闭侵入计数的普通程序。

## 架构与约束

机制归属于 RenderCore，沿用 Vulkan 和现有 RHI。
GPU 先产生完整着色回退标志，再选择间接命令。
选择保持几何参数、实例范围和命令顺序。
设备资格、帧槽及失败状态各有明确所有权。

调用方持有原始命令及谓词缓冲的有效生命周期。
选择器拥有每帧的两组间接输出。
帧槽复用以现有完成栅栏为前置条件。
默认许可为关闭，非零谓词始终选择完整路径。

窗口宿主与独立视图共享照明资格及回退规则。
公共命令选择器也适用于 GPU 细节层级选择。
普通输入及能力不足设备采用所属完整着色行为。
严格四帧、CPU 八毫秒及 GPU 16.6 毫秒均保持有效。

所有产物及临时文件位于 D 卷。
普通任务保留一天，预留三十二 MiB。
主构建目录持续复用，资产通过原路径引用。
单问题定位及接口预算为三十分钟。

## GPU 命令选择

文件为 `src/render/GpuPredicateDrawSelection.hpp` 及 `.cpp`。
着色程序为 `shaders/predicate_draw_selection.comp`。
CPU 与 GPU 用例分别位于同名的 `tests/` 文件。
构建及登记归属于 `CMakeLists.txt`。

构造接收 RHI、容量、帧槽数及有界 SPIR-V。
`prepare` 接收帧槽、原始命令、谓词、数量及许可。
`record` 消费一次性票据并记录计算分派。
`output` 与 `fastOffset` 提供输出缓冲及轻量区域偏移。

## 场景管线接入

资格绘制使用同帧几何、身份和保守深度条件。
任何新增可见量都必须包含在资格核验范围。
GPU 标志在核验完成后发布给命令选择阶段。
主颜色绘制保持原有材质及实例的提交顺序。

- [x] 独立轻量片元程序只消费已生成的照明数据。
- [x] 核对几何、节点透明度及特殊材质的资格边界。
- [x] 处理图记录和直接记录共用相同依赖契约。
- [x] 全部匹配、故意失配及特殊材质各验证回退。
- [x] 窗口与独立视图核对输出、同步及释放。

辅助片元的投票参与依据 [Vulkan 四像素组控制](https://docs.vulkan.org/features/latest/features/proposals/VK_KHR_shader_quad_control.html)。
独立消费程序采用无隐式导数的取样操作。
真实片元资格与辅助片元执行范围分别解释。
