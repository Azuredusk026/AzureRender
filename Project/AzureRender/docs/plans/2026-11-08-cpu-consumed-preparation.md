# CPU 消费范围与准备成本

## 目标与输入

渲染器更新约占既有诊断 CPU 工作的 56.5%。
实例、透明索引及运动准备分别约为 1.28、1.11、0.63 毫秒。
既有窗口的实例可见比例约为 64.87%，透明工作量按顶点和索引另行核对。
先确认实际可省成本，再组织相关实现及一次集中评估。
源码入口为 `254cd03`，输入沿用当前冻结联合项目。

## 方法与判据

私有渲染器对象记录实际消费范围和主要准备步骤。
透明索引按可见、不可见实例分别累计顶点、索引及时间。
实例准备细分姿态、包围盒、材质元数据及 GPU 数据填充。
运动准备细分姿态输入、历史打包、资源绑定和绘制列表。
实际执行八帧，统计第三至八帧，结果用于成本归属。
计时装饰的开销及短窗口波动分别记录。
原生完整图像及正式性能采样由成本门槛调度。

更新范围的候选须具有至少 20% 的工作减少依据。
CPU 八毫秒及 GPU 16.6 毫秒、既有画质门槛持续有效。
源码、运行时和项目输入在诊断期间保持原字节。

## 预算与执行

临时源码、程序及数值记录位于 D 卷，预留六十四 MiB，完成后保留一天。
资产、主构建及着色程序按共享路径读取。
编译至多三百秒，功能进程至多二百四十秒。
本单元定位预算十分钟，输出作为后续实现的准入依据。

## 结果

不可见部分仅占透明顶点约 4.99%、索引约 3.08%，局部约为 0.072 毫秒。
运动绑定准备及历史打包合计约为 0.461 毫秒。
两项完全省去的上限约为本轮更新的 12.70%。
单独围绕上述范围的候选未取得本批次准入依据。
