# 项目启动快照实施计划

执行方式：当前会话自主实施，按检查项连续推进。
目标：Player 与运行会话消费同一份启动快照。
依据为[恢复计划](2026-10-30-development-recovery.md)的启动待项。
技术采用 C++17、现有资产数据库和关卡会话。

## 结构与契约

`ProjectStartup` 属于 Runtime，声明位于关卡会话头文件。
构造时持有项目，刷新资产索引并解析启动关卡。
只读接口提供项目、资产索引和关卡。
构造失败通过异常报告，调用者获得完整快照。

`LevelSession` 接收只读启动快照并持有自己的会话状态。
初始提交消费快照，后续请求及热刷新独立执行。
原有项目构造入口通过同一准备过程装配。
编辑预览与独立运行测试共同验证契约。

公共构造接口如下。

```cpp
explicit ProjectStartup(Project project);
LevelSession(const ProjectStartup& startup, RuntimeLifecycle& runtime);
```

`Project::loadScene` 增加资产索引参数重载。
参数为场景路径及 `const AssetDatabase&`。
索引须已完成刷新，项目文件、身份和挂载须一致。
格式、引用及资源路径继续使用已有校验规则。

Player 在命令行解析前准备启动快照。
配置保存 `shared_ptr<const ProjectStartup>`。
应用装配核对快照与项目入口路径后创建会话。
项目检查使用同一份索引和场景。

## 约束与重点输入

- 构建并行度为二，GPU 程序串行运行。
- 构建期间保持生产代码及构建配置稳定。
- 当前四个 P5 用户文件保持独立。
- 原生图像、正式预算和异常根因状态保持真实。
- 传统场景覆盖材质或雾引用引发的索引消费。
- 文本关卡覆盖组件安装及不同会话间的状态隔离。
- 错误项目、未刷新索引及损坏文档按异常处理。
- 快照创建后的源文件变化在后续刷新中处理。
