# 性能瓶颈归因与定向优化

## 目标与范围

当前任务定位完整联合场景的性能限制。
分别记录 CPU 工作、同步等待及 GPU 工作。
GPU 继续区分着色、缓存、显存带宽和传输。
画质、分辨率及原有验收预算保持有效。

运行源码基线为 `f224da9`。
提前深度测试候选已保存至隔离目录。
候选通过受影响检查后才能进入生产入口。
用户的材质改动与验收记录保持原有范围。

## 当前状态

GPU 场景着色及 CPU 场景准备已有实际阶段证据。
静态实例共享姿态已通过对应 CPU 及原生图像检查。
厂商计数采样被驱动性能分析权限拒绝。
一次管理员分析会话的用户确认保持待处理。

## 执行顺序

1. 核对设备、供电、来源及现有事件数据。
2. 完成提前深度测试的原生图像检查。
3. 安装官方分析工具并检查硬件计数器。
4. 对高耗时通道取得算力及存储层级指标。
5. 补测当前 CPU 阶段，选择最大可控成本。
6. 按单变量实施，并执行兼容和成对测量。

RenderDoc 的当前重放记录用于定位事件。
原生帧时间独立统计，保持原采样要求。
实验中的分辨率或功能扰动只用于归因。
交付候选保持完整场景和既定画质。

## 归因规则

| 对象 | 所需证据 | 结论范围 |
| --- | --- | --- |
| CPU | 工作及等待分布、当前阶段采样 | 主线程工作或同步成本 |
| GPU | 通道耗时、片元及计算调用 | 优先优化的工作通道 |
| 着色单元 | SM 吞吐、占用及停顿 | 算术吞吐或延迟限制 |
| 缓存与纹理 | L1、L2、纹理吞吐及命中 | 访问局部性或纹理延迟 |
| 显存 | VRAM 吞吐及读写计数 | 设备显存带宽限制 |
| 主机传输 | PCIe 传输及上传阶段 | CPU 与 GPU 之间的传输限制 |

显存容量和带宽分别判断。
NVML 的内存忙碌比例仅作设备状态记录。
指标缺失时登记限制及替代实验的适用范围。
成对测量核对热状态、频率、供电和输入。

## 来源与预算

方法参考 [NVIDIA Shader Profiler](https://docs.nvidia.com/nsight-graphics/UserGuide/shader-profiler.html)。
计数接入参考 [RenderDoc 性能计数器](https://github.com/baldurk/renderdoc/blob/v1.46/docs/window/performance_counter_viewer.rst)。
工具使用官方安装包，并记录版本及摘要。
借鉴代码另行核对许可、固定提交和适配范围。

定位十分钟，单候选修改和短检二十分钟。
下载五分钟，工具安装五分钟，单次捕获十分钟。
重放及硬件计数各五分钟，原生四帧十五分钟。
正式性能保持三百帧预热及一千八百帧采样。

## 通过条件

结论列明来源、指标、限制及下一项措施。
采用的优化通过受影响构建与机制检查。
原生图像保持当前严格兼容条件。
收益资格由有效成对计时及完整帧预算决定。
