执行方式：当前会话自主实施，按检查项连续推进。

依据见[反射接入计划](2026-10-28-reflection-filter-integration.md)。

## 结构与契约

本阶段使用来源夹具及现有 Vulkan RHI。
来源编号归属导出脚本及证据清单。
生产公共内核按后续独立接口接入。
比较覆盖颜色、过滤足迹和可信度的完整原始字节。

导出工具固定原始捕获及程序指纹。
采集派发前的常量、纹理、瓦片及输出初始内容。
派发后的输出按既有参考指纹核对。
派发前后的采样输入、常量和活动瓦片集合分别核对。

独立夹具复用 `VulkanComputeFixture` 和 `ComputeTexture`。
输入视图由夹具持有，派发使用现有命令录制接口。
存储图像持有初始内容、读回缓冲及同步屏障。
所有 GPU 资源在完成读回后释放并检查计数。

来源程序通过 DXC 编译为 SPIR-V。
编译声明显式存储格式及互不重叠的绑定范围。
编译器、动态库、源文件和输出均记录指纹。
数值顺序调整须由完整 GPU 输出验证。

## 文件职责

- `tests/NativeRayReferenceGpuTests.cpp`：来源重放及独立 GPU 夹具。
- `tests/fixtures/native_ray_vulkan/`：参考程序与编译来源。
- `tools/test_native_ray_reference_gpu.py`：独立案例及任务目录管理。
- `tools/native_render/ray_fixture.py`：载荷范围、长度与指纹核对。
- `tools/test_native_ray_fixture.py`：真实文件的校验契约。
- `CMakeLists.txt`：诊断目标及 GPU 检查注册。
- `docs/acceptance/nr/`：结果、可复现脚本及来源记录。

工具接口接收数据目录、计算程序及新输出目录。
载荷使用清单声明的格式、尺寸、层级及长度。
读取范围为所属目录，输入大小总预算为一百二十八 MiB。
版本、长度、瓦片范围和派发数量在 GPU 使用前检查。

## 重点输入与约束

- 构建并行度为二，GPU 程序串行运行。
- 构建期间保持生产代码、测试代码及构建文件稳定。
- 存储颜色使用 `R11G11B10_FLOAT`。
- 足迹使用 `R16G16_UNORM`，可信度使用 `R8_UNORM`。
- 可信度在派发前作为输入读取。
- 七级深度资源按实际层级边界导出。
- 活动瓦片必须唯一并处于输出范围内。
- 零派发保留输出初始内容，空反射案例验证实际写入。

正式图像、持续性能、原始崩溃归因和 NR 状态保持既有条件。
