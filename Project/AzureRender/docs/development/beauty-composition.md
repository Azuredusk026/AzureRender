# 照明组合精度

共享函数位于 `shaders/beauty_composition.glsl`。
职责是规定照明分量的累加及置换边界。
默认隔离着色与反射重组使用相同契约。
函数只消费参数并返回单精度三分量结果。

## 求值契约

`azureBeautySum` 接收八个照明分量。
求和按参数顺序从左向右执行。
`azureBeautyReplace` 接收总量、新分量及原分量。
它先计算分量差，再与总量相加。

函数内部使用 `precise` 声明结果。
表达式的收缩约束对应 `NoContraction`。
规则依据 [GLSL 精确求值定义](https://docs.vulkan.org/glsl/latest/chapters/variables.html)。
浮点舍入及特殊值行为服从所属设备的规则。

调用方提供有限值及已定义的输入计算。
输入表达式的精度边界由调用方声明。
输出继续使用三十二位浮点分量。
函数具有局部值语义及调用方所有权。

反射重组先计算辐射混合及响应乘积。
随后将完整乘积作为新分量传入置换函数。
缓存存储及读取的格式由所属机制定义。
该函数本身只规定分量组合语义。

## 验证入口

`AzureRender.BeautyCompositionGpu` 使用实际计算提交。
夹具含六十三组输入及三类调用。
每组运行核对 567 个有序单精度分量。
完整写入通过独立标记检查。

输入指数范围包含二十一档二进制尺度。
用例覆盖大数消减、参数顺序及反射分量置换。
CPU 参考逐步保存每次单精度结果。
同步验证错误及分配残留须为零。

设备检查覆盖 NVIDIA、Intel 及两种构建配置。
当前渲染程序通过全部字节绑定原图像证据。
新调用方仍按其所属输入和画质要求验收。
照明复用的状态见[精度边界验收](../acceptance/nr/radiance-precision-boundaries.md)。
