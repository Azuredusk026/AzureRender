# 资产源文件快照

## 归属与读取

资产数据库拥有项目内的 `.azure/cache/`。
缓存保存资产指纹对应的源文件快照。
旧数据库可继续读取其刷新时的有效内容。
项目打包从快照取得完整源字节。

`AssetSourceCache` 提供独立的无损编解码。
接口接收源字节、指纹及读取所需的内容摘要。
编解码调用拥有各自上下文，支持独立任务并发。
资产数据库负责文件发布和源内容核验。

缓存损坏或缺失时，从匹配原指纹的源资产重建。
源内容变化须通过资产刷新建立新的有效记录。
缓存通过独占暂存目录及原子替换发布。
项目移动后，缓存仍由项目内相对位置定位。

## 编码范围

| 输入范围 | 编码与存储 |
| --- | --- |
| 小于 64 KiB | 编码 1，原始载荷 |
| 64 KiB 至 256 MiB | 编码 2，记录压缩决策 |
| 大于 256 MiB | 编码 1，原始载荷 |

编码 2 使用 Zstandard 一级压缩及帧校验和。
压缩文件至少节省原编码大小的八分之一时保存压缩载荷。
其余输入保存原始载荷，并保留压缩决策。
编码使用一个输出缓冲，容量为源长度加四十字节。

暖缓存按内容核对后复用。
刷新先核对源内容摘要，再逐字节核对暖缓存。
暖缓存比较复用已验证的源字节。
范围内的单链接旧大缓存在刷新时进入编码 2。
具有多个硬链接名称的缓存继续共享其原有存储。
生命周期管理及按天清理见[产物管理](artifact-retention.md)。

## 文件格式

整数均为八字节小端无符号值。
编码 1 的固定头部为二十四字节。
字段依次为 `AZCACHE1`、资产指纹和源长度。
头部之后为完整源载荷。

编码 2 的固定头部为四十字节。
字段依次为 `AZCACHE2`、指纹、源长度、载荷长度及存储方法。
存储方法为零时保存原始载荷，为一时保存压缩帧。
每份压缩载荷包含一个带校验和的完整帧。

读取先核对格式、指纹及载荷长度。
编码 2 的源长度及声明窗口上限为 256 MiB。
压缩帧的声明长度须与固定头部相同。
解码后按资产记录核对源内容摘要。

截断、额外帧、未知方法及不匹配内容均视为缓存未命中。
解码容量在输出分配前完成核对。
编码 1 与编码 2 均受现行快照语义约束。
空间核验区分编码大小及卷实际释放量。
