# 保守层级深度剔除

`GpuConservativeOcclusion` 属于 RenderCore。
输入为间接命令、局部包围盒及逐命令裁剪矩阵。
输出保留命令顺序、索引范围及实例身份。
被遮挡的单实例命令将实例数量写为零。

## 输入契约

`GpuOcclusionBounds` 的逻辑步长为九十六字节。
矩阵与实际顶点阶段使用的矩阵保持相同字节。
局部包围盒覆盖当前姿态、编辑偏移及材质位移。
包围盒和矩阵中的有效数值须为有限值。

输入深度采用同帧、同相机的完整尺寸最大值层级。
深度值位于零至一，远端及清除值为一。
视口深度范围为零至一，支持正、负视口高度。
颜色、半透明覆盖和不同相机的深度各有独立用途。

层级由 `DepthPyramidGpu` 的最大值归约生成。
基础层保持输入图像的完整尺寸。
奇数尺寸采用该机制的重叠覆盖规则。
深度、视图及采样器由调用方持有。

## 保守判断

每个包围盒核对八个裁剪空间角点。
乘加、透视除法及屏幕矩形均保留误差扩张。
默认屏幕余量为一像素，深度余量为 0.00001。
层级读取覆盖完整矩形对应的网格单元。

多实例命令保持原值。
跨越相机平面、数值溢出及层级资格不足时保持可见。
深度相等的表面保持可见。
比较使用保守最近深度与层级最大深度。

## 资源与录制

构造参数声明命令容量及帧槽数量。
每槽逻辑存储为每命令一百一十六字节及五十二字节参数。
内部 GPU 缓冲逻辑总池至多为 128 MiB。
外部深度和源命令由各自所有者计量。

调用方退役帧槽后调用 `prepare`。
一次准备生成一次录制凭据，过期及重复凭据被拒绝。
调用方发布源命令和深度的读取依赖。
机制发布宿主输入及内部输出依赖。

输出处于计算可读状态，汇总计数处于宿主可读状态。
间接绘制、复制及其他队列的消费依赖由调用方发布。
全部消费退役后才能再次准备或销毁相应资源。
录制失败时放弃当前命令，退役后重新准备。

`retiredZeroCommandCount` 在槽退役后读取结果。
该值包含输入本身已为零实例的命令。
调用方在下一次准备之前读取，并保留来源解释。
该操作沿用已有帧槽等待和宿主缓存失效规则。

## 场景接入条件

调用方提供已完成的不透明覆盖深度。
主颜色通道前完成深度层级和命令生成。
阴影和快照拥有各自的绘制集合。
当前机制用于独立工具、深度夹具及主通道深度复用。

场景接入需证明包围盒覆盖实际变形及投影。
同一录制批次内的实例共同满足资格规则。
动态姿态、渐隐、编辑及特殊投影各有明确边界。
实际结果见[机制验收](../acceptance/nr/gpu-conservative-occlusion.md)。

场景接入的命令范围为 256 至 65536。
层级图像逻辑池至多为 96 MiB，资源按帧槽持有。
场景复用已有主通道预填及宿主深度图像。
实际收益和范围见[深度复用验收](../acceptance/nr/main-depth-reuse.md)。
