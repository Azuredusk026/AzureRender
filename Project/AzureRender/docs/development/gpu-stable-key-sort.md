# GPU 分段稳定排序

`GpuStableKeySort` 属于 RenderCore。
输入记录为两个三十二位无符号整数。
首项为升序键，次项为随记录移动的附属值。
相同键按输入顺序输出。

## 输入与预算

段长度数组按输入顺序划分全部有效记录。
空段合法，每段分别排序。
记录总数至多为 1048576，段数至多为 65536。
帧槽数量为一至八，内部缓冲总池至多为 64 MiB。

输入缓冲由调用方拥有，包含存储缓冲用途。
缓冲起点对应第一项记录，每项占八字节。
尺寸至少为总记录数乘以八。
输入缓冲与排序器的所有内部缓冲保持独立。

构造时声明容量及帧槽数量。
内部缓冲的逻辑容量为每记录每槽二十四字节。
其中包含两个记录缓冲和一个范围缓冲。
输入缓冲及驱动元数据由各自所有者计量。

## 录制与所有权

调用方发布输入的计算读取依赖。
`record` 验证范围、更新段信息并录制归并。
每轮采用独立输出位置，轮间发布计算读写依赖。
输出的有效范围为返回的记录数。

非空输出指向排序器拥有的槽内缓冲。
其内容已发布为计算着色器可读。
空输入返回空指针及零记录数。
缓冲有效范围以外的内容由调用方忽略。

调用方在帧槽退役后，才能再次录制该槽。
所有消费结束后，才能重建或销毁排序器。
外部复制、索引或其他队列的消费依赖由调用方提供。
录制失败时，调用方放弃当前命令并在退役后重试。

段范围通过宿主缓冲提供。
范围变化时更新映射内容，相同范围复用数据。
范围变更先准备宿主存储，再写入映射内容。
写入期间的范围登记处于失效状态。
上传成功后保存对应范围。
下一次合法录制按当前范围重新核对。

## 使用范围

该机制适用于稳定键排序和透明深度排序。
透明深度键的生成、变形精度及索引写入由适配层负责。
当前机制独立于具体场景、资产及材质名称。
场景宿主的透明索引准备继续使用既有路径。

同步边界依据 [Vulkan 同步示例](https://docs.vulkan.org/guide/latest/synchronization_examples.html)。
`GpuStableKeySortTests` 核对范围和生命周期。
`GpuStableKeySortGpuTests` 核对实际设备的顺序与稳定性。
所属目标的结果入口见[实施计划](../plans/2026-11-08-transparent-deformation-plan.md)。
