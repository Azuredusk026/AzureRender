# GPU 管线检查

管线检查器属于 RHI 的设备诊断服务。
设备创建者协商可执行程序查询扩展。
图形、计算、界面及后处理共用同一入口。
报告通过 `--gpu-timing-output` 保存。

## 运行方式

常规运行查询受支持管线的可执行程序元数据。
`--pipeline-statistics` 显式请求编译统计。
`--disable-pipeline-inspection` 关闭全部管线查询。
默认运行保持编译统计关闭。

```powershell
AzurePlayer.exe --project project.azureproject --smoke-frames 24 --pipeline-statistics --gpu-timing-output gpu.json
```

编译统计可能增加管线创建成本。
性能验收采用既定采样批次，并保存诊断开关。
驱动指标与实际 GPU 计时分别解释。

## 创建与查询

设备创建者通过 `PipelineStatisticsOptions` 声明请求及入口。
创建者将 `creationFlags()` 附加到管线创建信息。
`inspect()` 同时接收借用管线及其实际创建标志。
具备统计捕获标志的管线才进入统计查询。

缺少能力或入口时，保留可用的元数据。
缺少统计捕获标志时，执行元数据查询。
统计失败通过独立计数及结果码报告。
有效的可执行程序元数据继续保存。

检查器借用设备与管线，其关闭由创建者负责。
字符串、统计值和阶段身份复制到独立记录。
记录保存后清空驱动扩展指针。
设备释放后，已保存的报告仍可读取。

## 数据与预算

元数据保存名称、说明、阶段及子组尺寸。
统计保存名称、说明、格式和值。
布尔、有符号整数、无符号整数及双精度分别编码。
未知格式或非有限浮点数保存空值。

每条管线至多保存三十二个可执行程序。
每个程序至多保存十六项统计。
每条管线至多保存六十四项统计。
报告至多保留六十四条管线记录。

元数据枚举最多重试一次。
每个统计枚举至多调用两次驱动入口。
记录保存请求、入口、启用、捕获及截断状态。
管线数量上限保持后续检查计数有效。

## 指标解释

统计名称和单位由设备驱动提供。
统计保持驱动原值，内存占用另用分配器字节记录。
寄存器、指令或溢出数据用于定位编译成本。
实际帧、通道及场景计时提供运行成本。
优化同时复验图像、资源及性能门禁。

接口依据见 [Vulkan 管线统计](https://docs.vulkan.org/refpages/latest/refpages/source/vkGetPipelineExecutableStatisticsKHR.html)。
抗锯齿预算见[空间抗锯齿计划](../plans/2026-10-22-spatial-antialiasing.md)。
