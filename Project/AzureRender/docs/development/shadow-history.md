# 主颜色阴影历史

实验构建使用 `AZURE_ENABLE_SHADOW_HISTORY` 装配本功能。
默认构建采用完整阴影求值。
运行时接收资格由场景渲染器持有。
资源与失效契约分别由公共渲染模块提供。

## 设备与资源

设备须启用片元三角形身份和存储原子操作。
存储缓冲数量、单缓冲范围和采样数参与资格核对。
主颜色采用两个帧槽，每像素八字节。
历史池遵守 `ShadowHistoryCache` 的 128 MiB 上限。

绑定 45 读取前一帧，绑定 46 写入当前帧。
绑定 49 保存视图范围、脏区域、统计与实例范围。
输入缓冲在所属帧槽完成后增长并刷新描述符。
统计在同一完成边界回读。

## 接收与失效

普通主颜色的提前深度分支消费历史。
额外照明和覆盖分支使用完整求值程序。
快照持有独立求值路径。
固定表、索引表与投影顶点均有对应程序组合。

静态实例分配无碰撞的全局三角形范围。
骨骼、形变和运行时动画实例进入动态集合。
当前与前一位置的形变边界投影为级联脏区域。
过滤足迹和级联混合共同决定历史可用性。

视图按输入位模式和资源代次核对。
只有成功提交才能确认历史链。
放弃帧、输入变化及重建使历史失效。
未知资格沿完整求值路径处理。

## 同步与观察

当前帧槽在片元写入前完成 GPU 清空。
前一帧写入通过显式屏障发布给片元读取。
统计写入发布给主机，并在帧槽完成后读取。
销毁沿宿主既有 GPU 完成边界执行。

运行清单记录资源准备状态、容量与稀疏统计。
采样网格的横纵间距均为三十二像素。
该口径只描述采样位置上的请求、资格和命中。
冷启动与槽回收范围随所属结果记录。

机制检查和场景收益分别验收。
冻结四帧要求 RGB 零像素差。
采用条件同时包含画面、设备回退和有效净收益。
正式帧预算按[开发总计划](../plans/azure-engine-plan.md)执行。
