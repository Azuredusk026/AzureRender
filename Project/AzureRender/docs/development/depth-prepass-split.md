# 深度预填通道拆分

`DepthPrepassSplit` 属于 RenderCore。
机制将已有深度预填与颜色绘制分为两个兼容通道。
调用方在两者之间消费同一份深度图像。
已有帧缓冲、图像和管线由调用方持有。

## 来源描述

输入采用 `rhi::RenderPassDesc`。
通道包含一个子通道和一个可写深度附件。
附件采用单样点，来源操作为清除并保存。
深度格式为 D16、X8_D24 或 D32，采用纯深度存储。
颜色引用按附件顺序排列。

`rhi::describeRenderPass` 转换原生创建描述。
转换保留格式、样点数、引用及显式依赖。
输入附件、解析附件及保留附件具有独立的表示需求。
当前转换遇到此类描述时抛出 `std::invalid_argument`。

两通道保持原有格式、顺序及子通道依赖。
兼容性依据 [Vulkan 渲染通道规范](https://docs.vulkan.org/spec/latest/chapters/renderpass.html#renderpass-compatibility)。

## 录制顺序

调用方先使用 `depthPass()` 录制已有预填。
深度内容保存为深度只读布局。
颜色附件采用忽略加载及保存操作。
调用方随后发布深度到计算采样的依赖。

深度层级可用 `DepthPyramidGpu` 生成。
其来源布局参数采用实际的深度只读布局。
后续计算按各自契约消费层级并生成命令。

颜色开始前调用 `beforeColor`。
该操作将深度转为附件布局，发布读取及写入依赖。
颜色附件的连续写入也在此处发布。
调用方随后使用 `colorPass()` 录制颜色绘制。

颜色通道清除颜色并加载已准备的深度。
深度加载依据 [Vulkan 附件操作](https://docs.vulkan.org/refpages/latest/refpages/source/VkAttachmentLoadOp.html)。
原有预填只由深度通道执行一次。
颜色通道结束时采用来源描述的最终布局。

## 所有权与工作流

机制只拥有两个渲染通道句柄。
借用图像按颜色引用顺序提供，深度单独提供。
所有图像互不别名，采用单层、零级视图。
全部消费退役后才能销毁机制或借用资源。

`RenderContext` 提供当前帧缓冲的来源描述。
窗口宿主按交换链图像索引提供借用图像。
独立渲染视图按视图目标提供相同契约。
在途帧槽用于定位调用方拥有的计算资源。

描述、图像或样点资格不足时，场景使用原录制路径。
计算及间接首实例能力沿用宿主的 GPU 剔除资格。
资源重建由所属宿主与渲染器生命周期共同驱动。
