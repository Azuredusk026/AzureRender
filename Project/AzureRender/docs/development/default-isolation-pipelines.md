# 默认隔离材质管线

默认画面的隔离模式为零。
默认构建使用动态隔离程序。
实验策略通过构建选项显式启用。

材质管线由 `AzureRenderCore` 中的角色渲染器管理。
主窗口与独立渲染视图共用该选择入口。
效果模式、效果开关及材质输入保持动态。

构建选项为 `AZURE_ENABLE_DEFAULT_ISOLATION_SPECIALIZATION`。
默认值为 `OFF`，实验构建使用 `ON`。
默认清单包含 673 个程序，实验清单包含 737 个。
实际成本见[短时核对](../acceptance/nr/default-isolation-cost.md)。

## 资格与选择

专用策略适用于主通道的普通不透明材质。
材质须满足单采样、完整覆盖及早期深度资格。
片元专用常量零为真，常量四为浮点零。
完整管线描述及其他专用常量由原管线复制。

隔离模式零通过原管线句柄查找专用管线。
其他隔离模式选择动态诊断程序。
快照、多重采样、淡出及其他材质沿用所属程序。
效果切换通过动态输入生效。

专用程序包含普通、显式照明及覆盖纹理组合。
程序清单同时用于构建、分发及着色热重载。
运行时按实际材质需求准备额外管线。
每代映射上限为十六项。

## 精度边界

照明分量通过 `azureBeautySum` 按源码顺序累加。
环境分量置换通过 `azureBeautyReplace` 求值。
两函数以 `precise` 限定累加及置换表达式。
调用参数的照明计算保留所属表达式。
函数契约见[照明组合精度](beauty-composition.md)。

该定义限制分量组合处的浮点收缩。
约束范围依据 [GLSL 精确求值规则](https://docs.vulkan.org/glsl/latest/chapters/variables.html)。
专用编译标记为 `AZURE_STATIC_ISOLATION`。
动态程序继续采用所属表达式。
生产程序的兼容性以实际二进制及图像核对。

## 所有权与失败

映射拥有额外图形管线。
材质着色变体拥有对应的额外着色模块。
RHI、基础管线、布局及渲染通道由原宿主拥有。
创建工作在图形提交之前完成。

准备失败时释放本代已创建的额外管线。
本代使用动态程序，并保存失败原因。
交换链重建及卸载统一释放映射与模块。
录制期间只读取已准备的映射。

采集清单提供 `defaultIsolationPipelines`、
`defaultIsolationSelected` 及 `defaultIsolationFallback`。
启用证据要求管线数量、选择状态和失败原因一致。
图像比较与成本结论另按验收结果记录。

## 验证入口

`AzureRender.DepthPrefillRecording` 覆盖记录与生命周期。
该检查按构建选项验证专用管线数量。
资格包含材质、透明模式、淡出及多重采样。
诊断切换使用已准备的管线。
固定纹理表与索引纹理表均参与检查。

`AzureRender.DefaultIsolationViewGpu` 执行实际视图提交。
该检查随实验选项注册。
范围包含普通和显式环境照明材质。
隔离视图、效果开关及视图尺寸重建共同验证。
同步验证错误及 GPU 分配残留均须为零。

原生冻结四帧要求 RGB 零像素差。
性能按前参考、候选及后参考核对漂移。
原画质及完整帧预算保持有效。
