# 阴影分块批处理

## 配置与职责

配置选项为 `AZURE_ENABLE_BATCHED_SHADOW_BOUNDS`。
默认配置使用八分块程序，显式关闭时使用单分块程序。
`ShadowTileBounds` 由所属渲染视图的帧槽持有。
调用方提供匹配的着色程序及分块批量。

`initialize` 的 `tilesPerGroup` 支持 1 和 8。
非法批量在资源分配前报告错误。
同一实例保持固定批量，重建时更新所属资源。
`tilesPerGroup()` 可查询当前配置。

## 工作组映射

每个深度分块覆盖八乘八个源纹素。
十六个线程分别读取一组四纹素采样。
每个分块使用原有的局部最值归约树。
分块内的取样位置、比较顺序及输出索引保持一致。

八分块程序的工作组包含 128 个线程。
局部编号除以十六得到组内分块编号。
局部编号模十六得到分块内采样编号。
每个工作组使用 1024 字节共享存储。

横向工作组数量采用向上取整。
纵向工作组数量等于纵向分块数量。
尾组中的无效分块使用中性数据，并参与全部屏障。
写入阶段仅更新有效分块的所属索引。

## 缓冲与观察

分块最值继续采用一对单精度数。
对象阴影记录保存在原有的十六字节对齐后缀。
批处理保持缓冲容量及对象记录偏移。
图像读取、计算写入及片元消费沿用既有依赖。

元数据 `shadowBoundsTilesPerGroup` 保存实际配置。
数值结果、独立内核耗时及整帧净差分别验收。
性能比较遵守所属预热、功率及分辨率条件。
全部产物及精简证据存放在 D 盘项目内。
