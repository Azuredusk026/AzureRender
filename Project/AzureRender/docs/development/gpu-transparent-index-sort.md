# GPU 透明索引准备

`GpuTransparentIndexSort` 属于 RenderCore。
输入为不可变资产、透明拓扑及逐帧实例参数。
输出为分图元稳定排序的原始顶点索引。
场景渲染和独立资产工具共用该机制。

## 数据与容量

构造时复制选中顶点、形态差量及三角形。
实例提供模型矩阵、姿态、骨骼偏移及形态权重。
相机位置和朝向参与世界空间的三角形深度计算。
变形与深度计算保持 CPU 参考的单精度运算次序。

每个图元独立排序，相同深度保持输入顺序。
输出索引保留资产内的原始顶点编号。
世界位置和未排序深度键提供诊断读取入口。
诊断读取由调用方提供同步与回读存储。

构造参数声明顶点、三角形、实例及权重容量。
内部 GPU 缓冲的逻辑总池至多为 128 MiB。
资产加载内存和外部骨骼缓冲由各自所有者计量。
容量、非有限数值及姿态范围异常通过异常报告。

## 帧槽与同步

调用方在帧槽退役后调用 `prepare`。
该操作读取 CPU 姿态并更新槽内实例参数。
返回凭据包含槽号、代次及有效输出规模。
`record` 消费一次凭据，重复及过期凭据被拒绝。

调用方发布骨骼缓冲的计算读取依赖。
录制依次执行变形、深度键、稳定排序及索引写入。
机制发布内部计算依赖，输出处于计算可读状态。
索引、复制及其他队列的消费依赖由调用方发布。

GPU 骨骼内容须与准备时的 CPU 姿态相符。
全部消费退役后才能重建或销毁资源。
资产及拓扑变化时由加载生命周期重建机制。
录制失败时放弃当前命令，退役后重新准备。

## 场景策略

场景在顶点数达到 16384 时评估 GPU 路径。
同时要求三角形数达到 4096。
小任务、容量及资源资格不足时采用 CPU 路径。
加载后首次合格任务创建有界资源。

渲染图声明骨骼读取、索引写入及索引消费。
直接录制入口显式发布计算写入到索引读取依赖。
捕获清单记录路径、缓冲规模及回退原因。
运行结果见[专项验收](../acceptance/nr/gpu-transparent-index-sort.md)。
