# 黑洞优化准入验收

> 文档类型：验收记录
> 状态：生效
> 更新日期：2026-10-03

## 范围

验收目标为电影档整帧 GPU 时间低于 20 ms，并核验图像一致性与引擎开销。执行依据为 [G0 前置计划](../../plans/2026-10-03-blackhole-optimization.md)。

## 环境

本机 Windows 使用 i9-13900HX、RTX 4060 Laptop GPU 和驱动 32.0.15.9579。工具链为 MSVC 14.44.35207 与 Vulkan SDK 1.4.350.0。源码基准为 `7c5a7a0`。

## 实现与预算

盘采样在径向范围检查后执行保守高度判断。归一化径向形状与噪声厚度因子的上界为一，高度判定包含 0.01% 浮点安全裕量。

电影档保留四条射线、1800 步上限、0.48 近场步长比例、体积盘噪声和现行后处理。图像分辨率为 1280×720。

原版安装树的单轮 300 帧基线为 38.053319 ms，未通过 20 ms 门禁。优化筛查为 18.132694 ms。正式三轮 GPU 平均值为 17.291640、18.071215、18.334914 ms。

正式中位数为 **18.071215 ms**，严格低于 20 ms，通过。与单轮原版基线相比约降低 52.51%。单轮基线用于定位，最终预算依据三轮优化结果。

## 图像一致性

正面、左侧轨道、上方、近景和越肩相机各四帧对照通过。正面自动旋转的 60 帧序列对照通过。共 80 对输出图像的解码像素哈希逐帧一致。

对照使用原版 Release 安装树与优化后的 Release 可执行文件。捕获清单确认四射线、1800 步上限、电影档和 1280×720。

## 相机构图边界

其他相机各执行单轮 150 帧，作为性能范围记录。正式 20 ms 门禁适用于正面相机的三轮采样。

| 相机 | GPU 平均时间 | GPU 第 95 百分位 |
| --- | ---: | ---: |
| 左侧轨道 | 17.927481 ms | 19.832934 ms |
| 上方 | 17.504365 ms | 19.358307 ms |
| 近景 | 39.350431 ms | 43.262238 ms |
| 越肩 | 15.993964 ms | 17.703579 ms |

近景仍约 39.35 ms，盘体占屏比例与射线积分成本较高。相机性能差异属于当前效果负载边界，交互近景需要专项预算优化。

## 引擎开销核验

整帧 GPU 查询覆盖阴影清理、主场景与宿主后处理，排除 CPU、呈现和资源复用等待。黑洞主场景包含追踪、Bloom、时间累积与合成。

黑洞 CPU 图准备、任务等待与图执行计时分别记录于正式性能 JSON。它们约为亚毫秒开销，当前场景以 GPU 效果计算为主要瓶颈。

角色压力场景包含 32 个独立资源和 16 个点光源。串行与并行均完成 300 帧，实际间接调用有效，可见比例一致。

| 角色录制路径 | CPU 录制 | 图准备 | 工作等待 | 图执行 | GPU 平均 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 并行 | 0.449675 ms | 0.176988 ms | 0.179274 ms | 0.093359 ms | 7.504029 ms |
| 串行 | 0.338017 ms | 0.168596 ms | 0.000634 ms | 0.168741 ms | 7.839221 ms |

小负载下并行 CPU 录制增加约 0.112 ms，任务分发成本值得按负载处理。两条路径的 GPU 差异来自单轮采样，适用于开销记录。

帧槽 fence 在两帧在途资源复用前等待对应帧。GPU 查询使用结果可用性检查。普通渲染路径通过队列信号完成提交和呈现，截图等待对应帧完成，重载和交换链重建等待设备完成工作。

呈现优先采用 MAILBOX，设备支持不足时采用 FIFO。GPU 时间反映渲染工作，整机交互帧率需包含呈现与帧槽等待。

### G0 后续核验项

- 录制任务的粒度与线程唤醒成本：按实际 CPU 收益确定串行或并行策略。
- 提交计数器覆盖：当前 Character 显式累加绘制计数，Blackhole 全屏绘制尚需统一统计。
- 帧槽等待、取图和呈现的 CPU 时间：通用分析需要分别记录阻塞时间。

当前时间查询能够支持黑洞预算判定。绘制计数为零不能用于推断黑洞没有 GPU 工作。这些可观测性与调度问题进入 G0 的后续设计。

## 优化范围

保守几何边界已满足本次预算和图像条件。噪声查表、采样布局修改、时间重投影与测地线查表作为按需候选安排。内部 Pass 扩展计时在细分瓶颈需要时接入。

## 生命周期与回归

Debug 黑洞平衡档持续运行 120.610 秒，执行六轮窗口调整与最小化恢复。记录 12343 个 GPU 样本、25 次成功重建与对应历史帧重置。

窗口恢复、运行期截图和卸载通过，存活缓冲与图像均为零。恢复窗口与最小化关闭的既有回归通过。Debug 完整 CTest 为 38/38，通过。

Release 门禁覆盖完整 CTest、安装、资源、隔离运行、许可证和打包。最终发布结果保存于 `release-gate.json`。

黑洞优化准入任务为 Complete，G0 基础库拆分为 Ready。Debug 与 Release 各 38 项回归通过，安装、隔离运行、资源、许可证和发布包门禁通过。
