## 范围与环境

阶段覆盖公开游戏模板、编辑器构建入口、目录事务和独立游戏包。验收环境为 Windows、MSVC 14.44、Vulkan SDK 1.4.350、i9-13900HX 和 RTX 4060 Laptop。驱动为 595.79。

## 发布验证

| 项目 | 验证内容 |
| --- | --- |
| 模板 | 独立项目标识、两个关卡、角色、触发器、Lua、动画、RmlUi 与音效 |
| 编辑器构建 | 保存关卡、后台构建、日志与结果、等待完成 |
| 发布事务 | 验证源码与候选包、冲突保留、替换、失败回退 |
| 分发边界 | Player、Release DLL、着色器、字体、许可与挂载资源 |
| 移动运行 | 含空格目录、输入目录移走、系统 PATH、角色运动与切关 |
| 完整性 | SHA-256、文件大小、必需许可、篡改检测与运行后校验 |

实际编辑器执行 `build` 和 `wait-build` 两个生产命令。最终发布包包含 143 个不可变文件，构建耗时为 2773.879 ms。移动包运行 180 帧，固定模拟推进 179 步，关卡切换到 destination，修订号为 2。

角色最终位置为 `[7.350009918, 0.899999976, 0]`。界面绘制 900 次，动画帧为 180，声音启动 2 次。脚本与表现错误为空，Validation 和退出分配器检查通过。

缺失音效的真实项目验证失败，已有包清单保持一致。规则测试覆盖候选失败、未知用户目录、配置、私有目录与挂载边界。移动运行后的不可变文件校验与脚本篡改拒绝通过。

## 回归与交付

Debug 57/57、Release 58/58 完整回归和发布门禁通过。最终编辑锁定、发布边界与运行库检查另有定向回归。记录进入 `evidence/2026-10-04/`，Release 门禁通过 CTest 执行实际游戏包验收。

```powershell
ctest --test-dir build/ninja-msvc-debug --output-on-failure
cmake -DBUILD_DIR=build/ninja-msvc-release -P tools/run_release_gate.cmake
ctest --test-dir build/ninja-msvc-debug -R "Editor|GamePackageRules" --output-on-failure
ctest --test-dir build/ninja-msvc-release -R "AzureEngine.GamePackage" --output-on-failure
```

MSVC 可再分发 DLL 随最终包提供，Windows 系统运行库与 Vulkan 驱动由目标机器提供。编辑器和元数据生成器可执行文件进入引擎安装树，游戏包保留独立 Player 及运行依赖。

模板操作和构建说明见 [Windows 游戏发布](../../runtime/game-publishing.md)。引擎包位于 `build/ninja-msvc-release/AzureRender-0.1.0-rc1-Windows-x64.tar.gz`。交互游戏位于 `build/p0/AzureGame-Windows-x64.zip`。

## 性能与边界

P0 的改动集中于项目和发布流程。黑洞性能采用 [U0 测量证据](../u0/2026-10-04.md)，电影档 GPU 中位数为 18.728938 ms。20 ms 门禁保持有效。

Windows Debug 使用开发工具链回归，独立发布以 Release x64 为准。两种配置的测试数量因实际发布任务而不同。现行验收标准保持有效。

游戏模板使用公开测试模型。动画、矩形界面裁剪和音频设备边界见 [游戏表现说明](../../runtime/editor-game-ui.md)。Android 为 Deferred。

证据 manifest 记录源码、二进制、测试日志和附件哈希。游戏清单记录运行包内各文件的 SHA-256，交付清单记录 ZIP 与引擎包。
