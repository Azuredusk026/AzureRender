# 阶段完成与验收收尾

本页说明怎样把可用功能推进到完整阶段完成。
当前状态见[阶段状态表](../plans/current-stage-status.md)。
检查结果依据各阶段的实际来源记录。
项目最终交付由 P8 的全部必需门禁共同判定。

## 四种阶段状态

| 状态 | 机器值 | 使用条件 |
| --- | --- | --- |
| 完成 | `Complete` | 规定范围、自身检查和必需验收全部满足 |
| Ready | `Ready` | 前置条件满足，可开始实现或执行收尾 |
| 开发中 | `Active` | 当前正在执行该阶段，全局最多一个 |
| 待完成 | `Pending` | 尚未启动，必要条件或规格待落实 |

检查结果使用通过、失败、未执行或待验。
这些结果记录事实，阶段状态表示下一步能做什么。
实现通过而正式条件待验的阶段保持 Ready。
自身交付完成且外部复核另有归属的阶段可标完成。

## 状态的维护入口

`docs/plans/stage-status.json` 保存当前阶段状态。
总计划和 README 链接由该清单生成的状态页。
专项清单的 `currentStageStatuses` 与主清单一致。
`recordedStatus` 保存对应清单此前登记的状态。

历史运行日志、失败断言和候选布尔结果保持原值。
例如 `phaseComplete: false` 说明对应历史批次未收尾。
新批次必须给出自己的检查记录和产物指纹。
当前判断以规定范围、必需验收和实际证据为依据。

更新阶段后执行以下检查。

```powershell
python tools/check_stage_status.py --write-page
python tools/check_stage_status.py
python tools/test_stage_status.py
```

校验拒绝未知状态、依赖环、失效证据和状态漂移。
完成阶段必须通过自身检查。
阶段关联的必需验收也必须全部通过。
P8 的失败或未执行条目会阻止其标记完成。

## 集中收尾的执行顺序

验收条目保留原代号，由 P8 统一组织执行。
共享条件只执行一个批次，结果按范围关联各阶段。
每个阶段的必需项列于机器清单的 `requiredAcceptance`。
某项通过后，检查所有引用它的阶段是否具备完成条件。

| 顺序 | 任务代号 | 执行内容 | 完成要求 |
| --- | --- | --- | --- |
| 1 | P8.1 | 准备最终候选 | 核对源码、资产、安装树、项目包及许可指纹 |
| 2 | P8.2 | 整理失败归因 | P5-causality、UX-008-causality 和 UI8-directory-causality 有有效结论 |
| 3 | P8.3 | 复核关闭与持续运行 | P5-long-run 的标准与平台各运行 1800 秒，关闭和完整预算通过 |
| 4 | P8.4 | 正式性能 | P5-performance 的五类负载各三轮完整门禁通过 |
| 5 | P8.5 | 集中实体操作 | 全部人工条目及 UI8-input-ime 有操作者记录 |
| 6 | P8.6 | 汇总并完成阶段 | 全部必需项通过，来源、文档、清单与提交一致 |

P8.2 的调查按具体假设执行受影响检查。
P8.3 使用 B1 修复后的实际运行产物。
P8.4 需要稳定热状态，并在运行期持续观察。
P8.5 使用可交互桌面、输入法和实际声音设备。

独立调查和人工复核可以在候选准备期间推进。
实际 GPU、正式性能和长跑保持串行。
启动条件不足的任务登记具体条件和责任人。
满足条件后从对应任务恢复执行。

## 候选与证据的使用边界

UI8 的安装入口和 Monica 回放覆盖当前制作流程。
P8 的旧六包证据覆盖其原候选和设备范围。
两组证据分别引用各自源码和产物指纹。
最终同源交付必须完成目标范围的候选绑定。

P8.1 先核对既有来源，再列出需更新的产物。
运行时相关字节变化时执行受影响验证。
文档和状态工具变更按自身检查范围验证。
已有运行结果按其有效范围引用。

## 验收预算与完成判断

正式性能共十五轮，每轮预热 300 帧。
每轮采样 1800 帧，使用既定分辨率和负载。
标准与平台长跑分别实际运行 1800 秒。
内存、帧时间、设备状态和资源释放按原门禁判断。

人工复核按[集中复核表](p8/manual-review.md)记录。
二维与材质制作继续遵守各自支持范围。
历史超时调查与当前用例通过分别保存。
真实失败会保留在证据中，并进入修复与复测步骤。

P8.6 核对十八项延期条件及对应原始记录。
全部通过后更新受影响阶段为完成。
完成报告列出实际提交、证据和剩余候选功能。
Android 与尚未立项的候选保留各自范围。
