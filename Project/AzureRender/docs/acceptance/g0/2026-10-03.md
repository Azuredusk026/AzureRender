## 范围与环境

依据 [G0 实施计划](../../plans/g0-implementation.md)完成模块库、项目、独立 Player、生命周期和性能观测。实现契约见 [引擎基础](../../runtime/engine-foundation.md)。源码基准为 `df7d1b9`，阶段完成提交标题为 `feat(g0): 完成引擎基础与独立Player`。

本机为 Windows、i9-13900HX、RTX 4060 Laptop GPU，驱动 32.0.15.9579。工具链为 MSVC 14.44.35207、Vulkan SDK 1.4.350.0，使用 Ninja 的 Debug 和 Release 构建。

## 模块与项目

Foundation、Platform、Render Core、Runtime、Editor 与两个宿主构建目标通过。Debug 和 Release 的 Player 链接闭包包含运行时库，编辑器库和 ImGui 属于编辑预览的构建闭包。

项目创建、移动目录后校验与运行通过。版本化项目、虚拟挂载、启动场景、重复挂载、路径越界、未知选项和编辑命令错误处理通过。超出整数表示范围的未来版本被拒绝，启动模板声明可迁移的内置模型资源引用。

运行时 World 的场景变换、可见性、节点身份、延迟操作、暂停、单步和关闭通过契约测试。重复实体删除和编号复用通过回归检查。NullRHI 连续帧测试确认节点移出视锥、隐藏和删除后，实际绘制的可见实例数为零。

共享只读场景描述贯通 World、宿主帧输入与角色渲染器。

## 图像与性能

冻结的准入安装树提供参考输出。Sample、Character、Blackhole 各四帧，AzureRender 与 AzurePlayer 分别对照参考图像，共 24 对解码 RGBA 图像逐像素一致。黑洞使用电影档、正面相机、1280×720，保留四射线和 1800 步上限。

小角色场景各采集三轮 300 帧，比较 CPU 录制均值的中位数。

| 录制路径 | 中位数 |
| --- | ---: |
| 冻结基准 | 0.253181 ms |
| 自适应录制 | 0.197795 ms |
| 显式串行录制 | 0.214360 ms |

自适应录制较基准约降低 21.88%。当前小场景包含五个二级录制任务。任务数量在一至五之间时使用调用线程，较大批次通过工作池并行处理。该阈值依据本机采样和现有场景确定，跨设备收益由同机对照判断。

黑洞电影档的三轮整帧 GPU 均值为 18.306007、18.945068、18.794610 ms。中位数为 **18.794610 ms**，严格低于 20 ms，通过现行门禁。

GPU 采样使用相同的起始温度条件：每轮开始时温度至多 55°C，候选程序与参考程序交错运行。每轮保持 300 帧、1280×720 和电影档，三轮均值中位数须低于 20 ms。起始条件来自本机约 50–55°C 的空闲温度，便于控制连续测试造成的热积累。

影响为采样间增加冷却等待，帧数、画质和时间预算保持现行值。

连续采样记录中，GPU 温度达到 85–87°C，核心频率最低为 1740 MHz，候选程序三轮中位数为 20.639081 ms。该记录未通过预算，证据与参考程序的温度、频率和时间曲线一并保留。温控采样用于固定条件验收，持续热负载下的帧时间属于运行环境性能边界。

`cpuFrame` 记录帧槽、取图、提交、呈现与整帧 CPU 时间。隔离 Player 的黑洞 30 帧记录 90 次场景绘制。统计能够区分 GPU 效果计算与宿主阻塞。

20 ms 门禁适用于正面构图和三轮均值中位数。黑洞近景约 39.35 ms 的既有性能边界由效果专项管理。固定物理步长、通用组件反射、资产数据库、关卡替换与脚本按 G1 至 G4 建设。模块采用静态库与进程内接口，二进制插件 ABI 按独立设计安排。
