# 运行期间设备环境观察验收

> 状态：工具契约及两配置 CPU 完整回归通过。
> 范围：正式性能与两类长跑的环境观察。

## 契约与来源

环境记录版本二保存运行期间的周期观察。
单个自有线程查询驱动，默认间隔五秒。
线程退出时等待正在执行的查询并记录末次观察。
输入路由和内存观察使用各自原有入口。

原始 XML 与温度、热余量和降频状态一同保存。
功耗、功率上限和频率按驱动实际字段解释。
活动热降频、无效观察和查询失败均导致失败。
大于二十秒的观察间隔按覆盖缺口报告。

启动使用稳定空闲窗口与驱动热余量。
温度判断沿用设备实际限制。
版本一记录保留其端点覆盖含义。
新测量通过版本二执行周期检查。

工具为 `gpu_environment.RunEnvironmentMonitor`。
正式性能和共享长跑入口使用同一实现。
异常退出仍保存环境证据。
关闭操作等待线程，支持重复关闭。

## 测试与回归

二十项环境工具用例通过。
两配置各一百六十三项 CPU 回归通过。
本轮新增 GPU 回归执行数为零。
运行产物逐字节等价，沿用既有 GPU 关联证据。
新增用例核验中途降频、时间缺口和查询失败。
还核验线程关闭、异常保存及现代驱动功耗字段。
修复前失败与通过日志分别保存。

首次通用 unittest 发现命令遇到五项导入错误。
相关脚本依赖 CTest 提供的命令行参数。
项目回归通过正式 CTest 入口执行并另行记录。
该次错误日志保留其原始状态。

## 实际诊断观察

标准与探索负载按相同入口交替运行四轮。
画质、三百帧预热及一千八百帧采样保持规定值。
全部四轮观察到运行期间的软件热降频。
工作集在这组诊断中均未复现超限。

首轮启动温度为四十二摄氏度。
约十秒与十五秒观察到软件热降频。
退出观察恢复正常，证明端点覆盖存在限制。
驱动原文包含约八十瓦的功耗和功率上限。

第四轮结束时来源校验失败。
原因是运行期间修改了功耗字段的解析源码。
该轮按来源变化保存为无效诊断。
其观察保留，正式验收仅使用冻结来源结果。
