# 管线与驱动提交时序对照

> 日期：2026-10-11
> 状态：局部诊断对照通过，正式根因闭环待完成。

## 数据来源

原始材料见[诊断证据清单](pipeline-diagnostic-evidence/manifest.json)。
清单记录保存字节与解压后字节的哈希。
注入原型仅操作工具创建的子进程。
诊断数据与正常启动的正式测量分别验收。

源码基点为 `6ff888a`。
该来源正式测量十四轮通过、一轮失败。
探索第三轮的工作集增长为 9.898%。
既定工作集增长上限为 5%。

## 缓存与查询对照

| 实验 | 实际结果 |
| --- | --- |
| 显式缓存 | 成功载入 477510 字节，热缓存第二轮增长 6.015% |
| 执行信息查询 | 三轮绝对增长为 221184、2719744、417792 字节 |
| 查询覆盖 | 每轮覆盖十五条图形和六条计算管线 |
| 开启查询的时序 | 全部创建与查询在 2.358 秒结束 |
| 关闭查询的时序 | 创建在 2.439 秒结束，后台提交持续至 21.196 秒 |

关闭查询时，十二秒后出现多次大额提交。
其中一次提交大小为 14745600 字节。
相关调用栈包含 NVIDIA 驱动模块。
开启查询的对照随后无超过 1 MiB 的成功提交。

两次时序对照均完成 2100 帧并正常退出。
录制丢弃、重入排除及非法参数计数均为零。
未完成写入和 GPU 资源退出计数也为零。
分析以查询计时和返回调用为依据。

## 结论与覆盖边界

显式缓存不足以解决本次性能失败。
执行信息查询可作为公共能力的实施候选。
其有效性需由生产来源的正式测量验证。
本机时序对照按其设备和驱动范围解释。

NT 记录覆盖进程内虚拟申请与释放。
映射、堆子分配和内核申请有独立覆盖边界。
驻留变化使用前后包围的快照窗口。
地址复用与短暂页面峰值仍需分别核验。

系统级采集步骤见[内存归因操作单](system-memory-trace.md)。
