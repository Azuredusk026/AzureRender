# R4 阶段验收

> 文档类型：验收记录
> 状态：生效
> 更新日期：2026-10-03

## 范围

验收覆盖公开压力场景、黑洞三个质量档位、截图、长跑、窗口恢复、历史帧重置和资源卸载。执行依据见 [R4 执行清单](../../plans/2026-10-03-r4-execution.md)。

## 环境

Windows 本机使用 Intel Core i9-13900HX、RTX 4060 Laptop GPU、驱动 32.0.15.9579。工具链为 MSVC 14.44.35207 和 Vulkan SDK 1.4.350.0。设备信息随实际验收环境记录。

## 性能结果

Release 使用 1280×720 和固定模拟步长。复杂场景包含 32 个独立网格资源、32 个对象和 16 个点光源。每条路径采样 300 帧，黑洞各档采样 150 帧。

| 场景与路径 | CPU 录制平均值 | 整帧 GPU 平均值 | GPU 第 95 百分位 |
| --- | --- | --- | --- |
| 压力场景：并行、GPU 剔除 | 0.466154 ms | 7.615783 ms | 9.084731 ms |
| 压力场景：串行、GPU 剔除 | 0.344877 ms | 7.662695 ms | 8.967130 ms |
| 压力场景：并行、CPU 剔除 | 0.432094 ms | 7.998018 ms | 10.559632 ms |
| 压力场景：串行、CPU 剔除 | 0.367850 ms | 8.027271 ms | 10.648608 ms |
| 黑洞：性能档 | 0.203197 ms | 9.532025 ms | 11.138786 ms |
| 黑洞：平衡档 | 0.243003 ms | 9.865288 ms | 11.717894 ms |
| 黑洞：电影档 | 0.239859 ms | 40.477036 ms | 44.478130 ms |

CPU 指标包含图准备、工作等待和图执行。GPU 指标覆盖计时查询定义的全部渲染 Pass。逐帧 CSV 保存完整曲线，JSON 保存各 Pass、分配器和提交计数。

复杂场景并行 GPU 路径 CPU 录制比串行增加约 0.121276 ms。GPU 两路径平均值接近，当前负载宜依据 CPU 实测选择串行录制。R3 预算适用于其既定公共负载。

黑洞电影档的 GPU 平均值约 40.48 ms，适合质量优先输出。性能档与平衡档的 GPU 平均值约 9.53 ms 和 9.87 ms。实际整机帧率还受到 CPU、呈现和调度影响。

## 工作负载边界

压力场景复用自制公共立方体模型，覆盖多资源、Compute 蒙皮、材质、阴影和多光源路径。结果用于合成负载的本机验收，复杂生产资产的表现需按实际内容测量。

长跑验收的观察窗口为每场景至少 120 秒。阶段结果适用于记录的运行时段和设备环境。

## 生命周期结果

Debug 启用 Vulkan Validation。两场景分别运行至少 120 秒，每场景执行六轮尺寸变化和最小化恢复。窗口初始尺寸为 1280×720，实际重建尺寸记录于日志。

| 场景 | 持续时间 | GPU 样本 | 成功重建 | 历史帧重置 | 卸载存活资源 |
| --- | --- | --- | --- | --- | --- |
| 角色压力场景 | 120.016 秒 | 5978 | 26 | 0 | 缓冲 0、图像 0 |
| 黑洞平衡档 | 120.125 秒 | 5436 | 27 | 27 | 缓冲 0、图像 0 |

两场景日志均无 Vulkan 验证错误，运行期截图成功。黑洞每次成功交换链重建均有对应历史帧重置。压力场景四路径的两帧截图逐帧哈希一致。

## 复现与证据

执行命令见 [Windows 验收说明](../../runtime/windows-acceptance.md)。原始产物位于 `build/r4-performance/`、`build/r4-captures/` 和 `build/r4-lifecycle/`。归档目录为 `evidence/2026-10-03/`。

源码基准为 `f1029b2`，阶段提交标题为 `feat(r4): 完成Windows渲染核心验收`。证据清单保存源码哈希、设备信息、工具链和所有验收文件哈希。

## 阶段结论与发布

R4 的功能、图像和生命周期验收通过，Debug 完整回归为 37/37。Release 发布门禁覆盖完整回归、安装、隔离运行、资源、许可证和打包。最终发布结果由证据清单与 `release-gate.json` 记录。

R4 为 Complete，G0 为 Ready。Release 完整回归为 37/37，发布门禁通过。G0 的后续范围是引擎基础库边界、项目配置、资源挂载和独立 Player。

## 验收口径与影响

持续运行采用每场景至少 120 秒，覆盖六轮实际窗口恢复。该时长为本机可重复的阶段稳定性检查，小时级运行可靠性需专项持续测试。

R4 性能以整帧曲线与实际路径计数验收。质量档位用于测量成本与适用负载，60 Hz 适用性根据实测值说明。R3 的既定负载和预算继续独立执行。
