# 保守深度剔除机制验收

本页记录公共机制及独立深度候选的所属批次。
当前场景集成与成本见[主通道深度复用](main-depth-reuse.md)。

## 交付范围

本阶段入口为 `a6d16c1`。
RenderCore 提供 `GpuConservativeOcclusion`。
机制适用于独立可见性工具及实际深度夹具。
场景接入状态为净收益未成立。

输入、容量及所有权见[公共契约](../../development/gpu-conservative-occlusion.md)。
内部缓冲逻辑总池至多为 128 MiB。
输出保持命令身份、索引及顺序。
退役结果通过 GPU 汇总计数读取。

## 集中验证

Debug 与 Release 的所属目标构建通过。
两配置共十二项 CTest 通过。
其中六项覆盖公共机制及 NVIDIA、Intel 设备。
其余六项覆盖既有节点、蒙皮及深度预填录制。

每设备每配置检查四组、共 16432 条命令。
覆盖奇数尺寸、单像素轴、负视口高度及帧槽复用。
还覆盖透视、剪切、相机平面及重复深度。
逐命令结果与独立的稠密深度参考核对。

每设备另读取 491 项实际裁剪范围。
输入采用同一捕获的主颜色绘制前深度。
两设备均剔除 268 项，与非零片元调用的冲突为零。
命令字段、统计计数、同步及释放检查通过。

同步验证错误、卸载后缓冲及图像均为零。
模块边界核对十八个目标，违规数为零。
已有 669 份着色程序在两配置均保持原字节。
新增程序为独立的保守剔除计算程序。

## 场景候选

候选提供独立的不透明覆盖深度及命令生成。
窗口短运行准备 440 项，退役零命令为 212 项。
后续采样区间的退役零命令为 216 项。
原生捕获准备 435 项，退役零命令为 212 项。

两组冻结四帧的 RGB 差异均为零。
四张 PNG 的 SHA256 均与冻结参考分别相同。
每组核对 1729 项项目输入及程序指纹。
实际应用正常退出，卸载资源归零。

## 局部成本

每组采用参考、候选、参考的前后对照。
每端预热六十帧，选取后六十帧。
参考均值取前后两端的平均值。
全部数据属于电池条件下的局部诊断。

| 组别 | 参考 GPU 均值 | 候选 GPU 均值 | 参考 CPU 均值 | 候选 CPU 均值 |
| --- | ---: | ---: | ---: | ---: |
| 映射读取组 | 29.9043 毫秒 | 30.3335 毫秒 | 5.8753 毫秒 | 7.9846 毫秒 |
| 汇总计数组 | 29.8802 毫秒 | 29.9105 毫秒 | 5.8744 毫秒 | 6.5281 毫秒 |

第二组使用 CPU 矩阵副本及 GPU 汇总计数。
颜色附件采用忽略内容的覆盖通道。
两组参考端的相对漂移均低于 3%。
第二组仍未证明 GPU 净收益，CPU 增量约为 0.65 毫秒。

额外的深度遍历与层级准备仍有成本。
可剔除工作量只构成收益上限。
场景接入需具备复用既有主通道预填的方案。
该结构完成前，同类计时保持暂停。
