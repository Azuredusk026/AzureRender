# 多样点视图与质量验证

日期：2026-10-25。
范围为 MS2 的主辅视图装配、设置与回退。
契约见[多样点运行说明](../../runtime/multisample-shading.md)。
公共解析依据见[场景目标验证](multisample-scene-target.md)。

## 质量契约

渲染器 API 版本五传递实际样本数及可用能力。
设置版本十九提供模式四。
命令行、控制台与环境面板消费相同取值。
设置序列化、重读、部分覆盖及旧版本拒绝共同检查。

模式四使用原生场景尺寸和四个几何样点。
模式一保持默认值。
渲染器、设备或源预算不足时采用空间回退。
回退原因、实际格式、源槽及字节进入诊断。

## 视图生命周期

记录后端验证多样点与单样点视图独立装配。
两个在途源槽具有不同的帧缓冲。
尺寸重建同步更新图像、预算及渲染上下文。
资源仅在所属提交完成后退役。

主宿主的交换链与编辑视口重建共用目标创建。
多样点解析位于场景生产和调色之间。
单样点法线与深度供既有后处理消费。
辅助视图通过自身画质建立实际采样状态。

## GPU 检查

实际设备为 NVIDIA GeForce RTX 4060 Laptop GPU。
辅助视图并行声明四样点、单样点及回退输出。
测试分别渲染两组源槽，再重建输出尺寸。
所有 GPU 提交按顺序执行。

均匀 HDR 输入通过公共解析、调色与读回。
三轮共核对 22,528 个输出字节。
多样点与回退结果须等于单样点参考。
验证层错误及释放后的资源计数均为零。

Debug 与 Release 各通过十二项注册检查。
范围包括 API、设置、关卡、视图与公共目标。
既有时序视图 GPU 检查同时通过。
Player 与编辑器均通过两种构建。

## 实际角色范围

角色四样点能力由 MS3、MS4 的材质及覆盖接入提供。
本阶段核对该能力缺失时的正式回退路径。
两种构建各对比三张模式一与模式四的角色截帧。
两组输出须逐字节一致，并保留明确回退诊断。

原生 2560×1440 原图保留冻结指纹门禁。
八个头发边缘光控制点保持一字节误差门禁。
完整四样点角色质量继续消费 MS3 至 MS5。
专项收据见[验证证据](evidence/2026-10-25/multisample-view-quality.json)。
