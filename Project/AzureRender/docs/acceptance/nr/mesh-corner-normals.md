# 网格作者法线与角点

日期：2026-10-27。范围为 NR1-S4 的原生网格转换。
坐标与采样规则见[网格转换](../../development/native-surface-uvs.md)。

## 来源与对应

来源为官方 3534 帧的绘制 5134 和 5147。
两次绘制分别对应左右前方斜面，共用 Lit 玻璃分支。
每次绘制包含 663 个索引，像素历史确认可见三角形。
源 OBJ、实际顶点流、实例矩阵与导出网格分别保留。

源 OBJ 提供 406 个顶点，GPU 分配区容纳 408 个。
有效三角形的位置最大误差为 `5.97e-8` 米，UV 误差为零。
来源法线来自作者角点，几何面法线具有独立含义。
失败夹具包含大于 `95°` 的导出法线差异。

## 公共转换

转换器先完成来源 OBJ 的坐标与绕序转换。
作者法线按完整三角形、UV 和角点重新绑定。
X 反射及轴转换同时作用于方向。
源三角形与目标三角形采用明确的相反绕序。

公共角点匹配支持有限的多分量属性。
UV 适配器与法线适配器共同消费该机制。
绕序可区分重合的正反面三角形。
无法对应或仍有歧义的角点产生明确错误。

存在作者法线时，源面须提供有效的法线索引。
完整缺少 UV 的网格按位置和三角形对应。
完整缺少作者法线时使用导入器生成的法线。
错误输入在导入前校验，失败对象按所有权清理。

场景与样条入口共享 `import_native_obj`。
收据保存来源摘要、作者法线状态和角点匹配误差。
公共运行材质、GPU 数据布局及着色器变体保持现行契约。

## 数值与运行检查

十项角点及 UV 测试覆盖接缝、绕序和非法输入。
来源选择、LOD 及绑定共二十五项回归通过。
场景交换两项与样条数据八项回归通过。
Blender 夹具覆盖独立的两个法线面及五项错误。

控制网格使用直接设置的作者法线及相同 Blender 存储。
转换结果与控制网格的最大分量误差为零，预算为 `2e-5`。
Blender 存储相对理想法线的误差约为 `4.23e-5`。
该存储误差独立登记，源 GPU 的角差另行测量。

生产场景工具构建两份实例和六份共享网格资源。
六份资源的作者法线流均通过来源检查。
两份斜面资源的顶点法线最大角差为 `0.159°`。
最终代码重建的几何与实际采集几何逐字节一致。

独立两资源项目完成双配置各四次 GPU 采集。
法线与底色覆盖两种描述符路径，对应图像逐像素一致。
两个法线采样点与完整镜头的输出逐像素一致。
全部采集检查验证层诊断及卸载归零。

## 实际图像与边界

实际候选仅替换重建几何，材质与纹理载荷逐字节保持。
左右斜面的法线采样角差分别为 `0.63°` 和 `0.53°`。
对应失败诊断点的角差为 `9.09°` 和 `8.63°`。
角差包含八位输出及原生缓冲的量化误差。

完整候选的平均绝对图像误差为 `28.859`。
现行视觉参考的对应误差为 `28.657`。
候选用于照明及反射分项诊断，主项目晋升按正式门禁执行。
其余静态网格的作者法线、完整照明及物流继续实施。

结构化来源及输出见[角点收据](evidence/2026-10-27/mesh-corner-normals.json)。
