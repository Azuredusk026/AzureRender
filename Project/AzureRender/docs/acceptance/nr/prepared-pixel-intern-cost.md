# 不可变像素载荷准备成本

载荷池先以完整字节查找存活对象。
匹配的输入共享同一载荷。
缺少匹配时，池按现有压缩策略创建载荷。
弱引用释放和分桶碰撞沿用公共契约。

## 定向配对

本次使用 `587b484` 作为运行源码基线。
两端以 Release Player 加载同一联合场景。
每端核对 1,729 项输入及 NVIDIA 595.79 驱动。
两端各运行四帧并正常释放资源。

| 指标 | 参考 | 候选 |
| --- | ---: | ---: |
| 载荷申请 | 1,446 次 | 1,446 次 |
| 完整内容命中 | 1,096 次 | 1,096 次 |
| 载荷构建 | 1,446 次 | 350 次 |
| 重复载荷构建 | 7.519 秒 | 0 秒 |
| 载荷池计时合计 | 13.102 秒 | 9.784 秒 |
| 场景 CPU 准备 | 52.658 秒 | 47.594 秒 |

载荷池计时包含分桶、构建和完整匹配。
匹配阶段计入压缩载荷的还原成本。
实测净收益为 3.318 秒，降幅约 25.3%。
场景 CPU 准备差额属于该次配对样本。
