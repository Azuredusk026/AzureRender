## 实现与来源

源码基线为 `48b04c7`。
会话持有未变化刷新结果及退休资产数据库。
下一后台工作先释放该持有区，再执行当前准备。
数据所有权及边界见[运行说明](../../runtime/level-refresh-retirement.md)。

主线程继续发布当前资产数据库，保持场景版本。
持有区最多包含一个已完成结果。
后台函数显式清空数据，异步共享状态按原生命周期销毁。
场景提交、预加载及取消继续按原流程执行。

## 实际失败及夹具

夹具使用含 1,048,576 字节文档字段的最小关卡。
观测范围为逐次轮询中单块至少 524,288 字节的内存释放。
失败控制每轮主线程释放 2,560,434 字节。
三轮累计为 7,681,302 字节，未变化场景保持初始版本。

首轮临时目录检查因路径末尾分隔符失败，原记录保留。
目录规则按绝对路径、规范父目录及独占名称核对。
目标创建前检查目录尚不存在，清理限定在该临时目录。
实际释放失败在合法夹具启动后独立取得。

## 生命周期及回归

Release 的三轮主线程大块释放均为零。
Debug 的三轮主线程大块释放也均为零。
当前场景版本和实体数量保持稳定。
会话关闭后，全部被观测的大块拥有分配释放。

Release 稳态持有量为 4,657,824 字节。
Debug 稳态持有量为 4,657,856 字节。
三轮结果分别保持相同数值，包含一份待释放结果。
这些数字属于夹具范围，实际负载内存按原生记录判断。

两配置各二十八项 CPU 检查通过。
范围包括资产、启动、预加载、取消、呈现、脚本及组件。
任务、平台游戏流程和渲染相关机制共同回归。
整帧收益及完整用户画质继续按原标准验收。
