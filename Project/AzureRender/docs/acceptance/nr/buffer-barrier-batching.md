# 缓冲屏障批量提交验证

## 实现范围

渲染图编译每个过程的连续缓冲依赖集合。
公共记录器提供逐条回退。
Vulkan 后端合并同阶段、独立句柄的连续屏障。
重复句柄及阶段变化保留分组边界。

资源范围、访问掩码及队列族条件逐条保留。
零阶段沿用单条路径的默认阶段。
空集合记录零次命令。
详细规则见[同步契约](../../runtime/rhi-synchronization.md)。

## CPU 检查

检查通过 CPU 夹具截获实际后端的 Vulkan 命令。
夹具持有虚拟句柄，命令截获入口直接记录参数。
该过程没有创建设备或调用显卡驱动。
结果只用于验证描述转换与提交位置。

失败控制覆盖公共接口缺失及逐条图提交。
两个过程各持有两份兼容依赖的夹具中，
实际后端截获结果应为每过程一次命令。
每条依赖继续具有独立的资源和访问描述。

## 设备验证范围

双设备同步、资源释放及原生四帧对照待复测。
完整场景的实际屏障数量和性能收益待测量。
既有 4,934 次调用包含图像和缓冲屏障。
该数量用于原始帧诊断，候选收益由后续实际帧确认。

GPU 检查按用户安排延期。
完整画质、CPU、GPU 和热状态验收保持原状态。
本候选的 CPU 结果独立于完整设备验收。

Release 与 Debug 的运行产品及所选目标构建通过。
两配置各七项受影响 CPU 检查通过。

两配置各五百三十五份生产着色程序与基线一致。
