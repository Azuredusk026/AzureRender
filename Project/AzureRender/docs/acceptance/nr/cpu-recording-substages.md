# CPU 更新与录制归因

## 输入与方法

本单元使用 `845c22f` 的源码入口及 `c3def68` 的运行时输入。
私有渲染器对象在生产代码上附加分段计时。
诊断 Player 复用主着色器、运行库和原联合项目。
生产源码及主产物保持原字节。

原生进程执行 160 帧，分段窗口为第 21 至 140 帧。
窗口包含 120 份渲染器更新与 CPU 工作样本。
该窗口用于归因，正式功率条件及性能资格未测量。
正式预热三百帧、统计一千八百帧的要求持续有效。

## 帧内成本

| 范围 | 每帧均值，毫秒 |
| --- | ---: |
| CPU 工作 | 6.60385 |
| 渲染器更新 | 3.73253 |
| 实例准备 | 1.27618 |
| 透明索引准备 | 1.10655 |
| 运动数据准备 | 0.63147 |
| Uniform 准备 | 0.41413 |
| 录制快照 | 0.18856 |
| 场景字段复制 | 0.05769 |
| 主颜色录制 | 0.38700 |
| 阴影录制 | 0.33719 |
| 覆盖录制 | 0.30178 |
| 渲染器图构建 | 0.29955 |

更新子阶段包含在渲染器更新总量中。
快照内部的可见范围和不透明度复制另有原始计时。
录制阶段按工作线程的方法调用累计，线程间存在重叠。
表中各行不能直接相加为主线程墙钟耗时。

更新约占 CPU 工作的 56.5%。
实例、透明索引及运动准备合计约为 3.01 毫秒。
后续帧内优化优先处理这些阶段的共享形变与准备工作。

阴影录制约占 CPU 工作的 5.1%。
既有捕获含 864 次纯深度阴影绘制及 255 次带片元阴影绘制。
纯深度路径中的材质状态写入具有可省略空间。
当前整段阴影录制仅约 0.34 毫秒，热点门槛未成立。
状态写入候选未进入实现及原生兼容测试。

## 启动成本

| 加载任务 | 本轮耗时，秒 |
| --- | ---: |
| CPU 场景准备 | 44.013 |
| 材质上传 | 14.094 |
| 管线准备 | 117.408 |

管线任务包含图形管线、运动初始化及场景状态准备。
RHI 的图形和计算创建入口当前传入空管线缓存。
持久缓存是后续启动候选，实际收益尚未测量。
跨运行复用依据为 [Vulkan 管线缓存示例](https://docs.vulkan.org/samples/latest/samples/performance/pipeline_cache/README.html)。

## 验证与状态

原生进程正常退出，卸载后图像与缓冲计数为零。
主程序、着色器和全部挂载项目输入摘要一致。
本单元没有生成截图，也没有重建生产运行时。
CPU 八毫秒、GPU 16.6 毫秒及整体画质要求继续有效。
