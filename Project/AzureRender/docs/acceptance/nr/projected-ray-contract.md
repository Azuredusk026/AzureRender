# 投影反射射线公共接口验证

日期：2026-10-31。阶段为 NR5-R8-R4。
公共数值及资源接口已通过，主场景装配继续实施。
范围见[专项计划](../../plans/2026-10-31-projected-ray-contract.md)。

## 公共实现

`ProjectedReflectionRayGpu` 归属 RenderCore。
实现通过现有 RHI 创建计算管线并录制命令。
调用者借出六份采样视图、瓦片缓冲及三份输出。
计算对象持有每槽位参数、描述符及共享采样器。

参数由具名的变换、尺寸和射线设置组成。
打包结果为三十个四分量向量，共 480 字节。
捕获编号、来源常量索引及适配逻辑归属测试层。
接口、编码和生命周期见[使用说明](../../runtime/projected-reflection-ray.md)。

算法及立即数依据用户提供的原始 GPU 捕获重建。
数值来源、指纹及顺序控制见[Vulkan 参考](native-ray-vulkan-reference.md)。

## 数值验证

来源为已有冻结载荷，完整输出共 8,294,400 字节。
Debug 与 Release 分别运行正序和逆序瓦片。
各次均实际调用公共计算对象。
三份完整来源输出的差异字节数均为零。

| 输出 | 字节数 | 公共接口差异字节数 |
| --- | --- | --- |
| 颜色 | 3,686,400 | 0 |
| 双通道足迹 | 3,686,400 | 0 |
| 可信度 | 921,600 | 0 |

原始来源布局通过独立路径再次检查。
双配置的正序与逆序输出继续逐字节一致。
编译命令、源文件、程序及载荷均记录指纹。
GPU 执行前后各核对一次载荷长度及 SHA-256。

## 独立场景与槽位

公共路径在同一提交中执行两个不同尺寸的任务。
槽位零处理来源图像，槽位一处理 17×9 空反射表面。
第二任务使用 35×19 颜色及运动输入。
六个瓦片覆盖部分超出图像尺寸的边缘线程。

第二任务的三份输出共 1,377 字节。
初始颜色及足迹含非零内容，完整参考为零。
所有有效像素均实际完成清零。
两个任务通过同一公共计算对象录制。

双配置另覆盖 8×8 空反射和零派发。
零派发保留初始图像，错误参考的一字节差异被识别。
每个配置的公共与来源路径各含十个独立案例。
验证层、同步及资源释放均通过检查。

## 错误与回归

公共 API 红测命中预期的缺失接口。
零输出程序通过公共路径产生预期的完整图像差异。
该控制的验证层和资源计数均为零。
数值门槛保持逐字节零差异。

CPU 检查覆盖非有限参数、尺寸及设置范围。
槽位越界、缓冲容量、缺失视图及视图别名分别拒绝。
错误输入与零派发保持命令录制状态。
各槽位的参数缓冲和描述符集合保持独立。

Debug 与 Release 各通过十六项受影响检查。
范围包括模块边界、深度、射线及历史过滤。
同机来源控制及公共路径均完成正逆瓦片回归。
构建并行度为二，GPU 检查按串行执行。
