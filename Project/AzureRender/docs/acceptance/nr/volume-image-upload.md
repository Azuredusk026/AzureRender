# 三维体积上传验收

日期：2026-10-27。范围为 NR4-G6 的资源上传基础。
公共规则见[三维纹理上传](../../runtime/volume-image-upload.md)。

## 上传契约

分配结果保存实际深度，上传按每级三维尺寸计算偏移。
GPU 逐字节核对 5×3×4 体积及其三个层级。
同一夹具核对六面立方体的三个层级。
两种资源均通过公共接口创建对应视图。

Debug 与 Release 的上传和既有纹理缓存检查通过。
空设备检查覆盖深度、完整载荷及释放后的计数。
真实角色和主场景保持冻结图像一致。
测试启用 Vulkan 同步校验并检查资源释放。

首次设备红测报告三维层级与切片内容不符。
失败日志与后续验证分别保存在任务目录。
正式 NR4 和抗锯齿预算保持所属待验条件。

首次 Debug 主场景已生成图像，进程触及六百秒工具时限。
关闭可选管线统计后，完整重跑通过图像与释放检查。
重跑使用九百秒工具时限，正式图像预算保持一致。

## 官方体积输入

来源为官方中庭截帧 3534，照明事件为 8944。
六份纹理的原始载荷合计 50,331,648 字节。
每层包含 128×64×128 浮点幅度和三倍高度方向场。
来源、格式、尺寸、采样器及载荷哈希均保存收据。

幅度使用线性重复采样，方向使用线性钳制采样。
常量缓冲保存参考原点、三层中心偏移及默认球谐。
中心偏移消费逆观察矩阵 Z 轴，比例为 13、52、144。
该轴与同缓冲中的实际相机位置分别登记。

四项 CPU 采样检查与二十四项组合检查通过。
七个输入点覆盖三层、两个内层过渡和外层回退。
点位明确处于法线偏移和时间抖动之后。
原生像素的分项 GPU 结果仍需与参考对应。

## 主场景成本

冻结程序在 1920×1080、模式一运行三组九十六帧。
各组排除前十六帧，统计其后八十帧。
完整场景帧耗时均值为 54.43 毫秒。
关闭反射和局部光源的均值分别为 38.48、46.21 毫秒。

成本对照用于定位后续反射与光照工作。
正式候选保持全部照明设置，60 帧预算继续待验。
