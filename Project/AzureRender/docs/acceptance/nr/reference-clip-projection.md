## 参数与范围

版本一配置使用四列矩阵和归一化 UV 抖动。
GPU 参数为八十字节，CPU 版本头单独校验。
矩阵投影按声明顺序保存单精度边界。
每次融合乘加保留显式的运算归属。

九类投影拒绝覆盖版本、保留值及非法数值。
五类程序拒绝覆盖截断、非法头部及缺失标记。
程序准备器具有重复调用的字节幂等性。
准备后的程序通过 Vulkan 1.0 字节码校验。

## 原生来源与工具场景

原生输入来自既有顶点及常量缓冲捕获。
共有 11564 个相机相对位置及裁剪向量。
全部四分量由原生实际 GPU 输出持有判据。
配置包含原生矩阵和抖动，采用统一公共算法。

另有正交和透视各 4096 个解析输入。
两种工具场景使用独立的双精度解析式给出期望。
每批共 19756 个点及 79024 个分量。
全部输入按原有位精度标准核对。

两配置、双设备的四批检查全部通过。
总计 316096 个 GPU 裁剪分量逐位一致。
CPU 同时核对解析场景及全部原生向量。
验证层无错误，资源销毁后的验证计数为零。

## 指令归属

缺失 C++ 和 GLSL 接口检查先于实现并失败。
普通乘加形态在 NVIDIA 满足完整输入门槛。
Intel 的原生首点深度有一个末位差异。
中间值控制与拆分乘加的结果逐位一致。

私有控制只增加三处 `NoContraction` 装饰。
该控制使 Intel 全部输入满足位精度门槛。
公共 GLSL 标记三个具名局部乘加结果。
公共准备器把标记归属到对应的算术指令。

首次编译与重新加载使用相同准备入口。
该入口处理调用方显式选择的参考程序。
默认场景沿用所属设备程序和创建路径。
浮点规则依据 [Vulkan 规范](https://docs.vulkan.org/spec/latest/appendices/spirvenv.html)。
