# 关节缓冲容量验收

日期：2026-10-22。
范围为角色渲染器的关节与顶点缓冲容量统计。
Debug 与 Release 的 CPU 验证均已通过。
原生大场景的宿主加载由主流程另行实测。

## 容量契约

渲染器按资源布局的网格键统计实例数。
资源身份通过 `ResourceLayout::meshKey` 解析。
归一化路径及材质绑定共同确定网格键。
同一网格的资源别名共享计数。

多节点场景的每个有效资源引用贡献一份容量。
隐藏节点同样保留姿态与输出切片的容量。
未知资源和空引用按布局的无效键处理。
未使用的网格保留一份容量。

单节点场景为每个网格使用 QA 实例数。
该数值由加载上下文配置，至少为一。
空场景为每个网格保留一份容量。
加载清单公开以下容量结果：

```text
effectiveInstances[k] = max(instanceCount[k], 1)
jointCapacity = sum(jointCount[k] * effectiveInstances[k])
vertexCapacity = sum(vertexCount[k] * effectiveInstances[k])
```

统计只创建一份资源布局，并遍历节点一次。
每个在途帧分配独立的关节缓冲区。
缓冲大小为 `jointCapacity * sizeof(array<float, 16>)`。
主资产缺少关节矩阵时，加载抛出运行时错误。

## 公共加载路径

正式夹具调用渲染器的公共 `prepareLoad`。
预解码网格通过 `RenderContext::preparedMeshes` 提供。
零预算调用执行一个完整加载任务。
缓冲任务完成后读取加载清单中的容量。

夹具在容量检查后调用公共 `onUnload`。
每组结果均检查图像及缓冲区存活计数归零。
资源布局和加载任务使用生产实现。
NullRhi 提供 CPU 后端及主机缓冲分配。

## 自动检查

两种配置均完成 `AzureRenderNullRhiPassTests` 构建。
Debug 与 Release 各通过四项受影响 CTest。
测试范围为缓冲容量、切片、批次及场景可见性。
正式设备的耗时与画面仍需宿主验收。

| 检查 | 覆盖内容 |
| --- | --- |
| `AzureRender.NullRhiPass` | 容量、加载、提交及资源释放 |
| `AzureRender.SkinningBatch` | 独立关节与输出切片 |
| `AzureRender.ViewBatching` | 视图批次 |
| `AzureRender.SceneVisibility` | 场景可见性 |

容量夹具使用字面量期望值。
小夹具包含三份关节数与顶点数不同的网格。
大夹具包含 367 个资源和 1,764 个节点。
其中两个网格没有实例引用。

| 夹具 | 关节容量 | 顶点容量 |
| --- | ---: | ---: |
| 别名、隐藏、未知引用与未使用网格 | 25 | 33 |

| 367 资源、1,764 节点 | 3,532 | 5,298 |

大夹具的缓冲任务包括均匀缓冲与关节缓冲创建。

## 分配预算探针

独立探针将生产函数原文编译进字段夹具。
资源布局使用引擎实际实现。
缓冲分配器记录请求的大小。
大夹具容量完成记录为 4,678 次分配。

探针设置 100,000 次分配预算。
结构化证据保留预算触发记录及函数指纹。
预算中止的计时范围止于中止点。
完整容量记录的耗时为 0.5895 毫秒。

这些数值用于核验局部统计成本。
原生资源解码、上传与渲染具有独立计时。
完整加载性能以生产宿主的阶段记录为准。
