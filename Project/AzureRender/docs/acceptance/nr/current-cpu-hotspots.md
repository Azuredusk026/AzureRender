# 当前原生 CPU 热点观察

## 来源与方法

源码基线为 `2fad7ef`，实际运行当前 Release Player。
原生六百帧诊断在两份帧资源完成初始化后采样。
采样观察独立于正式 CPU 性能验收。
来源规则见[任务计划](../../plans/2026-11-06-current-cpu-hotspots.md)。

首轮十二份调用栈只具有绝对地址。
该轮缺少进程模块基址，原始结果完整保留。
修正采集在首次采样前记录基址及程序摘要。
修正轮取得十二份带实际模块来源的调用栈。

私有链接只增加映射输出，代码段与正式程序逐字节一致。
正式程序和源码在两轮运行前后均保持一致。
映射提供最近的符号及偏移，内联位置具有适用边界。
样本数表示观察次数，不能作为函数独占耗时比例。

## 观察结果

六份样本的应用栈位于帧入口，原始栈包含设备等待。
其余样本涉及相机选择、资源解析、录制及关卡轮询。
两份样本包含 `resolveGameCamera`。
其中一份直接位于场景文档的渲染描述转换。

一份样本在帧资源解析中执行文件状态查询。
另一份位于关卡轮询的 JSON 对象释放。
蒙皮录制及缓冲屏障转换各有一份样本。
各路径的实际耗时需后续独立控制或计时验证。

## 实施顺序

当前相机入口接收已经插值的场景文档。
呈现入口还需要物化后的渲染描述。
下一单元让两种消费者共享同一份物化输入。
相机优先级、跟随回退及插值语义共同保留。

资源路径解析与关卡轮询按独立单元处理。
原 CPU 八毫秒与 GPU 十六点六毫秒预算保持有效。
完整角色、反射及 GI 画质保持未通过。
