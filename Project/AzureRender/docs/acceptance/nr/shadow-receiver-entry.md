# 阴影接收面入口计算

## 机制与范围

本单元归属于 RenderCore 的级联阴影片元着色。
普通场景、角色主颜色及反射快照使用同一接收面机制。
接收面梯度与曲率属于当前片元调用。
`prepareShadowReceiver` 在片元入口计算这些值。
覆盖判定、材质提前退出及级联选择消费既定的调用状态。

导数计算遵循 [Vulkan 控制流规则](https://docs.vulkan.org/spec/latest/chapters/shaders.html)。
数据保存在调用私有存储中，采样及比较继续使用原算术契约。
无光照雾入口沿用其所属路径。
模块接口、宿主所有权与原时序测试要求保持有效。

## 定位证据

Intel 原用例在独立零历史输出一致性检查失败。
独立回读确认 TAA 输入与零历史解析结果逐字节一致。
重复渲染的阴影深度及范围表保持一致。
关闭阴影贡献后，HDR 和最终输出均为零差异。

浮点诊断将梯度、曲率和可见度写入独立附件。
梯度出现零值、有效值及 NaN 之间的重复差异。
同次曲率及阴影深度保持一致。
该证据限定了执行位置相关的接收面问题。
具体驱动触发条件尚未完成独立归因。

| 隔离候选 | 重复输出结果 |
| --- | --- |
| 细粒度导数 | 十二个像素不同，最大通道差为 21/255 |
| 片元入口计算 | HDR、最终输出、深度及范围表逐字节一致 |

入口计算候选通过原 Intel 时序用例。
原测试代码与阈值保持原状。
RenderDoc 在打开基线捕获时达到一百二十秒上限。
该次重放未执行候选替换，结果记为工具执行限制。

## 生产验证

Debug 与 Release 的所属运行及测试目标编译通过。
两个设备各执行四项检查，两种配置合计十六项通过。
检查覆盖时序视图、阴影过滤、对象阴影过滤及范围表。
时序用例覆盖两个资产、独立历史、移动和缩放。
独立四倍分辨率参考及原平坦区域要求通过。
静态边缘误差比至多为 0.8，平坦区误差至多为一个输出字节。

两配置的六百六十三份着色程序摘要一致。
全部程序通过 SPIR-V 静态校验。
七十五份相关程序与独立候选字节一致。
双配置构建来源核验及用户差异保护按结果清单记录。

原生联合场景采用原冻结机位、灯光和四帧命令。
四帧全部满足 RGB 零像素差条件。
一千七百二十九份项目输入摘要一致。
验证层日志正常，卸载后缓冲与图像计数为零。
