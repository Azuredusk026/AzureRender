# 阴影范围查询评估

本单元归属于 RenderCore 的保守深度查询。
候选为独立 GPU 机制，生产源码保持受检状态。
整体画质及原帧预算继续验收。

## 实际工作量

原捕获为 1280×720 的完整联合场景。
四份快照程序对应三百五十四次绘制。
统计范围为最终可见的不透明快照。
被覆盖的片元及其他着色阶段分别解释。

可见快照包含 957,010 次级联查询。
其中约 85.69% 由范围判断直接结束。
平均每次查询读取约 11.39 个范围块。
后续滤波合计请求 8,917,141 个深度四元组。

原像素附件在移除诊断替换后逐字节一致。
两次功能重放均正常退出，调试消息为空。
本轮没有修改捕获或生产资源。

## 精确分层机制

基础表保留每个 8×8 深度块的完整浮点范围。
两个附加层分别汇总相邻 2×2 和 4×4 个基础块。
每层的起点仍对应基础表中的一个格点。
查询以重叠方块精确覆盖原矩形。

合并仅采用最小值及最大值。
完整矩形的深度范围保持逐位一致。
512×512 的基础表需额外四 MiB 存储。
两个附加层均计入候选的局部耗时。

实际输入保留每个像素最后一次级联查询。
921,445 个矩形的范围读取量减少约 68.41%。
混合区域中较早的 35,565 次级联查询未进入该序列。
独立边界夹具另覆盖 2,304 个矩形。

NVIDIA 与 Intel 的全部结果均匹配独立 CPU 归并。
两个设备的同步验证及资源释放检查通过。
主构建、公开接口和对象阴影记录格式保持现行状态。

## 局部效率

首轮逐次提交和回读之间存在长空档。
NVIDIA 的进程耗时约 39.33 秒，GPU 合计约 24.10 毫秒。
修正夹具采用连续预热及集中提交。
首轮原始结果及修正源码均保存在归档中。

修正后的 NVIDIA 基线前后均值相差约 0.09%。
各阶段末尾四个样本的范围差均小于 3%。
下面数字只适用于该独立计算夹具。
当时主机为交流供电，驱动功率上限为 75W。

| 查询，毫秒 | 0.296960 | 0.097280 |
| 附加层构建，毫秒 | — | 0.032256 |

该局部阶段的合计降幅约为 56.66%。
Intel 的计时仍有明显漂移，仅确认功能结果。
独立查询的绝对收益尚不能证明整帧显著收益。
原生片元执行、覆盖及完整渲染仍需分别评估。

生产接入需形成足够的整帧成本依据。
