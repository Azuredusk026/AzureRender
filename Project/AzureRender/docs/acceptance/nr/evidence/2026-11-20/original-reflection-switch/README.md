# 检修站交互回放

原创检修站用同一次按键触发状态、光照和反射变化。
技术员按 F 启用导光路线。
导光板与检修灯同时移至右侧。
画面中的反射和受光区可按固定坐标复算。

## 场景与输入

场景复用屏幕空间反射夹具的镜面、机位与解析投影。
导光板、反射地面和检修卡由程序生成。
图形资产使用夹具声明的 CC0 许可。
交互采用公共输入系统和 Lua 回调。

Player 以 320×240、60 帧每秒记录十二帧。
三组使用相同关卡与固定时间步。
两组在帧 4 按 F，在帧 5 释放。
静止对照使用空输入记录。

用正常成片同时检查两种反馈。
反射隔离画面复核导光板的镜面位置。
静止对照核对无按键时的关卡状态和反射。
亮度指标使用解码后的线性颜色。

## 验收结果

| 图像帧索引 | 场景状态 | 正常成片左侧反射 | 正常成片右侧反射 | 右侧检修卡亮度 |
| --- | --- | ---: | ---: | ---: |
| 3 | 初始 | 0.547568 | 0 | 0.000543 |
| 4 | 启用 | 0 | 0 | 0.999096 |
| 5 至 11 | 启用 | 0 | 0.545261 | 0.999096 |

两份按键回放均消费两个输入事件。
状态在帧 4 切换，导光板和灯的最终位置均匹配。
右侧反射在帧 5 达到门槛，并稳定至序列结束。
静止对照十二帧的反射指标均为左侧 0.547643。

反射检查沿用夹具的 0.003 红色差门槛。
检修卡亮度增量门槛为 0.015。
正常成片在帧 5 同时达到两项门槛。
帧 4 的接收结果见[反射过渡归因](../reflection-switch-transition/README.md)。

各例执行 11 个固定步，历史输入提交编号为 11。
批次 2293 在 NVIDIA GeForce RTX 4060 Laptop GPU 上通过。
加载器确认启用 Vulkan 验证层，运行启用同步验证。
脚本、呈现、验证、存活缓冲及存活图像计数为零。

## 来源与复算

验证绑定冻结 Player、895 个着色器和三组输入。
先期门禁分别记录脚本导入、属性范围和验证层问题。
通过批次启用了外部 Vulkan 验证层。
可查[结构化收据](qualification.json)中的批次与指纹。

解压[验证归档](validation.zip)后运行 `python verify.py`。
复算需要 NumPy 和 Pillow，直接读取留存 PNG。
相机、区域、状态时序及三个画面序列随归档保存。
归档中的 `switch-beauty` 目录包含可启动项目。

手动运行可向配套 Player 传入以下参数。

```powershell
AzurePlayer.exe --project switch-beauty/project.azureproject --qa-camera scene --qa-light scene
```
