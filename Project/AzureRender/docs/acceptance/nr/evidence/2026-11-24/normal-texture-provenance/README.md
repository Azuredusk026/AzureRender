# 默认法线来源契约

状态为双配置资产检查和实际 Player 验证通过。
资产解码以 `normalTexturePresent` 声明法线来源。
缺少法线贴图时，运行时保留插值几何法线。
显式贴图继续采用原有线性解码及切线基底。

## 数据与渲染

glTF 解码按法线纹理声明填写来源字段。
材质参数覆盖保留源声明，完整替换按纹理集合填写。
公共材质表为版本 23，共二十三行、368 字节。
新增行保存缺图标记，推送常量布局保持有效。

光栅化、轮廓及分层材质统一消费该表布局。
路径追踪以零宽度法线输入保留几何法线。
缺图路径使用原有图元朝向及双面规则。
自定义材质构造器按实际来源填写字段。

## 实际附件

两组原创检修站使用相同几何、相机及固定输入。
一组缺少法线贴图，另一组使用显式中性纹理。
中性纹理为 2×2 的 `[128,128,255,255]`。
实际 Player 第 4 帧的表面准备输出用于复算。

| 法线来源 | 右侧接收点 | 相对几何法线的角差 |
| --- | ---: | ---: |
| 无贴图 | 97 | 0° |
| 显式中性贴图 | 97 | 0.317760° |

两组完整准备附件的粗糙度分量精确相等。
普通 Player 的两次启动通过同步及退出释放检查。
独立路径追踪项目完成 4 个累计样本并释放资源。
像素、程序及输入身份保存在结构化收据。

缺失来源字段及路径追踪接口分别由失败测试暴露。
实现后 Debug、Release 的相关 CPU 检查均通过。
两配置、两设备的材质表和反射检查见集中回归。
匹配参考输入及 592.82 四帧沿用延期状态。

诊断夹具由已封存归档校验后恢复。
捕获环境仅注入目标程序，GUI 使用独立环境。
