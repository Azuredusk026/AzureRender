# 对象接收输入与附件核验

## 来源与范围

本单元生产入口为 `18b66cf`。
参考为帧 10401 的深度、压缩法线、对象深度及可见量。
原生深度为 `R32_FLOAT`，法线为 `R10G10B10A2_UNORM`。
对象图集采用原始十六位归一化整数，输出为 `R8G8_UNORM`。
参考及四处控制点见[采样边界](hair-sampling-boundary.md)。

全部原始输入从保留目录直接读取，逐项核对摘要。
坐标采用左上原点，参考纹理行号为 `1439-y`。
完整遮罩沿用原有 17017 个像素，边界为 `[1140,130,1430,440]`。
本单元验证同输入下的可见量，完整头发颜色和场景集成分别验收。

## 接收位置与运算

CPU 控制按原指令顺序计算深度重建、法线及投影。
相对位置加回绝对原点后，仍有约 30.5 微米的分量差异。
单独改变坐标原点没有形成一致的控制点改善。
法线来源和各阶段的浮点舍入分别影响投影与过滤。

GPU 模型直接消费原生矩阵、原始法线格式和对象深度。
重建、偏置和投影保留指定的乘加次序。
四处控制点的可见量为 239、86、95、255，均与参考相同。
第三点的 CPU 模型为 116，实际 GPU 模型为 95。
因此 CPU 近似结果只用于定位，实际 GPU 结果承担该分项判据。

## 完整遮罩与附件转换

计算模型输出完整单精度可见量，再独立检查整数舍入及图形附件。
图形对照使用无混合的真实 `R8G8_UNORM` 颜色附件。
该阶段读取已保存的计算值，接收和过滤结果保持原字节。

| 输出方式 | 逐字节一致 | 一字节以内 | 最大误差 |
| --- | ---: | ---: | ---: |
| 计算值显式整数舍入 | 16912 | 17017 | 1 |
| 真实八位图形附件 | 17017 | 17017 | 0 |

显式舍入的 105 处差异全部高一个色阶。
其中 28 处的完整精度值为 0.5，实际附件均保存为 127。
本设备及该格式下，附件生产是精确可见量链路的一部分。
规范中的整数转换规则与容许精度见
[Direct3D 11.3 第 3.2.3.6 节](https://microsoft.github.io/DirectX-Specs/d3d/archive/D3D11_3_FunctionalSpec.htm#FLOATtoUNORM)。
本次实际结果来自设备对照，格式规则的跨设备行为继续单独验证。

两次接收对照及附件对照均在 NVIDIA GeForce RTX 4060 Laptop GPU 执行。
同步验证错误为零，图像及缓冲在释放后均归零。
主程序、663 份生产着色程序、源码及只读输入摘要保持一致。
本单元未重建主程序，也未进行原生性能采样。

## 实施边界

公共机制按深度、法线、对象身份和类型化投影记录生产屏幕可见量。
完整精度计算与八位附件拥有各自的状态和同步边界。
原生矩阵和资源标识归属于校准数据，公共代码消费明确定义的输入。
独立机制及场景集成完成后，再核对完整颜色和既有场景。

当前成果为同输入可见量模型，生产接入尚未实施。
完整头发的一字节颜色门槛、CPU 八毫秒及 GPU 16.6 毫秒要求持续有效。
整体画质继续为 `failed-user-review`。
