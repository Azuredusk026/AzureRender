日期：2026-10-31。归属为 NR5-R8-R2 的冻结数值参考。
状态：参考内核逐字节验证通过，生产接入待实施。

## 输入与输出

输入为官方 3534 帧的原始捕获。
计算事件为 8702，输出尺寸为 1280×720。
捕获、原始程序、编译输入和策略均绑定 SHA-256。
比较覆盖三份完整输出，共 8,294,400 字节。

| 输出 | 格式 | 比较字节数 | 工具结果的差异字节数 |
| --- | --- | --- | --- |
| 压缩颜色 | `R11G11B10_FLOAT` | 3,686,400 | 0 |
| 表面与过滤足迹 | `R16G16_UNORM` | 3,686,400 | 0 |
| 可信度 | `R8_UNORM` | 921,600 | 0 |

默认编译控制保留一、九千三百一十二及零字节差异。
单字节篡改控制被严格比较识别。
替换结束后，原始程序的三份输出再次全部一致。
正式比较采用零差异门槛。

## 算术顺序

矩阵计算先产生一个舍入后的乘积，再执行乘加。
编译器可为相同的实数表达式选择另一项独立乘积。
点积的分量排列也会影响浮点累计顺序。
当前策略固定十组矩阵乘加及三处点积的顺序。

| 冻结对照 | 颜色差异 | 过滤输出差异 | 可信度差异 |
| --- | --- | --- | --- |
| 默认编译 | 1 | 9,312 | 0 |
| 矩阵顺序 | 0 | 465 | 0 |
| 矩阵与基向量长度点积 | 0 | 418 | 0 |
| 矩阵与足迹点积顺序 | 0 | 54 | 0 |
| 矩阵与全部点积顺序 | 0 | 0 | 0 |

常规优化等级的计算程序字节相同。
全局及局部精确计算声明均保留未通过记录。
关闭优化的程序仍有十、二百一十及零字节差异。
这些对照用于定位顺序对当前输入的实际影响。

## 工具契约

实现位于 `tools/native_render/shader_arithmetic_order.py`。
公共入口为 `normalize_shader(data, policy)`。
输入使用计算着色模型 5.0 的 DXBC 容器。
工具仅依赖 Python 标准库。

容器大小上限为十六 MiB。

策略版本为一，以计算程序指纹锁定来源。
矩阵项声明相邻乘法和乘加的字偏移。
工具从这两个重建指令中提取乘积及累加器关系。
临时量掩码与累加器排列决定分量映射。

乘积临时量与输入寄存器保持独立。
矩阵项使用直接临时量或常量缓冲操作数。
列入策略的矩阵项交换两项乘积的计算位置。

点积项指定四分量源排列，前三项构成点积顺序。
负号修饰及直接寄存器索引继续保留。
容器校验、来源、边界及重复目标均在输出前检查。
错误输入产生 `ValueError`。

规范化过程使用重建程序和策略数据。
其他指令、反射资料及容器区域保持原始字节。
输出重新计算官方容器校验值。
命令行只创建新的输出文件。

## 工具检查

十一项自动检查完成红绿验证。
附加的容器填充边界检查通过官方签名夹具核对。

独立舍入夹具以四个常量验证乘积顺序。
两种顺序分别得到一和零，符合单精度乘加的预期。
该夹具与原生射线使用同一公共工具。

检查还覆盖原始容器、规范化容器及来源拒绝。
损坏校验值、重复目标、错误偏移和非法排列均被拒绝。
非计算程序区域保持字节一致。
Debug 与 Release 的 CTest 注册均已通过。

命令行验证确认现有输出文件保持有效。
来源指纹错误时，目标文件保持空缺。
最终 GPU 检查使用工具实际生成的程序。
其 `SHEX` 计算程序段与独立成功对照逐字节一致。

## GPU 观测边界

额外观测覆盖九千一百一十五个活动瓦片。
对应五十八万三千三百六十个像素。
两次十六位观测使用实际颜色格式中可精确表示的整数。
已知位模式 `0xfedcba98` 在活动范围内完整还原。

各次观测的活动瓦片集合均相同。
原有表面和可信度输出保持字节一致。
观测结束后，原始输出完整恢复。
直接按 RGBA8 解释颜色槽的初始方案保留拒绝记录。

观测值属于带观测指令的实际 GPU 程序。
量化输出一致的范围由上述完整字节检查确定。
尚未观测的内部位值保持独立判断。
CPU 量化模型仅作为诊断，硬件输出构成数值依据。

## 复现步骤

以下命令在引擎目录执行。
普通工具检查使用已安装的 Python 环境。

```powershell
python tools/test_shader_arithmetic_order.py
```

规范化命令的输出路径须指向新的文件。

```powershell
python tools/native_render/shader_arithmetic_order.py `
  --input tests/fixtures/shader_arithmetic_order/compiled-ray-mirror.dxbc `
  --policy tests/fixtures/shader_arithmetic_order/ray-policy.json `
  --output build/runs/<任务目录>/ordered-ray.dxbc
```

GPU 复现使用 RenderDoc 1.46 和原始捕获。
先使用产物管理工具创建任务目录。
输出子目录由验证脚本创建。

```powershell
python docs/acceptance/nr/evidence/2026-10-31/ray-arithmetic-order/run_replay.py `
  --engine . `
  --renderdoc <RenderDoc目录>/qrenderdoc.exe `
  --capture <原始捕获>.rdc `
  --output build/runs/<任务目录>/gpu-order
```

脚本核对捕获指纹并执行默认编译控制。
随后验证规范化输出、单字节控制和原始输出恢复。
格式及接口依据见 [RenderDoc 1.46 源码](https://github.com/baldurk/renderdoc/blob/v1.46/renderdoc/driver/d3d11/d3d11_replay.h)。
