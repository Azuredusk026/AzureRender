# 完整覆盖阴影验证

## 实现与范围

Vulkan RHI 在片元模块为空时只提交顶点阶段。
场景渲染器分别持有级联及对象图集的纯深度管线。
每个节点透明度连续区间按实际材质覆盖选择管线。
接口与资源规则见[运行契约](../../runtime/depth-only-shadow.md)。

完整覆盖策略遵循阴影片元程序的标志优先级。
裁切、混合、平方根覆盖及节点淡出继续计算片元覆盖。
几何覆盖标志与透明模式的组合具有独立检查。
常量、形变、绘制顺序及实例来源保持现行规则。

## 构建与自动检查

源码基线为 `fe0f074`，候选字节见构建收据。
Release、Debug 的实际宿主与所选产品均构建通过。
两配置各十二项受影响 CPU 检查通过。
检查包含级联、对象、透明度、覆盖及交换链重建。

实际 Vulkan 描述截获先复现空片元仍提交两阶段的失败。
通过结果核验顶点单阶段与常规两阶段入口。
材质策略先复现公共函数缺失，再验证合法组合及非法透明度。
这些失败控制与实际命令共同归档。

独立 GPU 夹具使用现有顶点及空片元测试程序。
D16、D32 的两种入口均产生相同深度字节。
三组偏移、重叠遮挡、裁剪边界及清屏共同检查。
Release、Debug 在 NVIDIA、Intel 的四组检查全部通过。

GPU 夹具启用同步验证，并检查卸载资源归零。
首轮夹具缺少清屏，边界内容未定义，原日志保留。
显式启用清屏后，两种格式全部通过。
该夹具修正保持深度字节一致及原有覆盖门槛。

## 原生场景

NVIDIA Release 的四帧与原冻结参考 RGB 逐字节一致。
两配置各五百三十五份生产着色程序保持基线字节。
一千七百二十九份挂载项目文件在采集前后保持一致。
原生进程正常退出，卸载后的缓冲与图像计数均为零。

原生应用日志无验证错误，正式应用未启用验证层。
同步验证的结论由独立 GPU 夹具持有。
四帧兼容用于保留候选，完整用户画质仍未通过。
脸部、头发、角色阴影、反射与 GI 继续按原标准验收。

## 短时性能

本轮使用原生一千九百二十乘一千零八十负载。
预热三百帧，统计一百二十帧。
阴影 P95 为 4.50 毫秒，GPU 帧 P95 为 33.93 毫秒。
CPU 工作 P95 为 23.91 毫秒。

交流供电、八十瓦功耗状态及短时热状态检查通过。
原 CPU 八毫秒与 GPU 十六点六毫秒目标保持未通过。
本轮统计范围独立于正式一千八百帧验收。
相邻历史负载记录用于定位，因果收益仍需成对控制。
