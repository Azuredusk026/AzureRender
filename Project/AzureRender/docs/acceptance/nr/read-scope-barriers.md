# 命令准备与缓冲同步优化

## 同步与所有权

生产来源为 `956f501`，所属运行产物与 `35cc28f` 一致。
渲染图将连续缓冲读取合并为完整的可见性范围。
首个读取前的屏障将生产者写入发布到该段的全部读取阶段与访问类型。
后续写入等待前一段全部读取阶段。
新的写入开始独立的可见性范围。
图像布局及图像屏障继续按各自状态处理。

Vulkan 命令后端按阶段组合分组独立缓冲。
各组保留源、目标阶段及资源范围。
重复缓冲句柄会先提交全部已有组，再处理下一项访问。
潜在重叠范围因此保持保守的顺序边界。
空输入、非法指针及数量上限按公共接口报告。

加载及场景复用上下文持有场景描述。
主视图录制上下文消费渲染器已经准备的不可变帧。
场景世界坐标标志继续来自该帧输入。

同步依据为 [Vulkan 规范](https://docs.vulkan.org/spec/latest/chapters/synchronization.html)
与[官方示例](https://docs.vulkan.org/guide/latest/synchronization_examples.html)。

## 局部控制

当前帧捕获记录 4913 项缓冲屏障与 1525 次屏障调用。
九个连续 API 区间提供实际资源、范围、阶段及访问位。
私有候选的范围控制得到 768 项屏障与十五次调用。
该数量属于控制程序，原生候选的 API 数量尚未重新捕获。

| 所属操作 | 基线均值，毫秒 | 候选均值，毫秒 |
| --- | ---: | ---: |
| 屏障命令转换 | 0.361 | 0.043 |
| 原生场景的录制上下文复制 | 0.446 | 0.0002 |

控制使用两百轮交替顺序。
场景包含 1679 个节点与 374 个资源。
屏障转换计时排除图编译、读取范围准备及 GPU 驱动延迟。
对应的两份场景描述复制在录制上下文中具有相同生命周期。
两项已测操作可减少约 0.764 毫秒，作为集中评估的预期收益依据。

## 原生结果

完整联合场景以 1080p 固定步长运行。
基线与候选各预热三百帧，采样一百二十帧。

| 指标 | 基线 | 候选 |
| --- | ---: | ---: |
| CPU 均值，毫秒 | 12.166 | 9.023 |
| CPU P95，毫秒 | 14.393 | 10.309 |
| GPU 均值，毫秒 | 21.777 | 21.822 |
| GPU P95，毫秒 | 22.801 | 22.297 |

CPU 短时均值减少约 3.14 毫秒，读数改善约 26%。
全部 420 帧的命令录制均摊为 4.015 与 1.811 毫秒。
其中图准备为 1.837 与 0.791 毫秒，图执行为 1.587 与 0.455 毫秒。
阶段均摊包含预热帧，与最终一百二十帧的 CPU、GPU 样本分别记录。
GPU 收益未成立，663 份着色器保持相同字节。

原生 1440p 四帧冻结图像均为零像素差异。
运行后缓冲与图像归零，验证日志保持清洁。
候选环境记录包含一次软件热限速，全部观察八十瓦条件未通过。
CPU P95 八毫秒、GPU P95 16.6 毫秒及完整画质门槛继续有效。
正式性能和整体画质继续待验收。
