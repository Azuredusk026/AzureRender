# 透明排序临时分配验证

## 实现与范围

渲染器在准备透明临时数据前筛选实际透明网格。
不透明网格沿用几何和材质的既有提交路径。
透明图元的变形取样和排序算法保持现行规则。
该机制适用于混合场景中的通用网格实例。

## CPU 分配检查

夹具使用实际 Character 渲染器和 NullRHI。
输入同时包含小型透明网格及不透明网格。
绘制索引固定，不透明顶点容量扩大至 65,536。
检查统计预热后的帧更新动态分配量。

Release 失败控制从 119,362 字节增至 913,480 字节。
该控制在第一种描述符路径触发原定分配门槛。
候选的两种描述符路径均保持容量扩展前后的分配量。
两配置的实际数值保存在结构化收据。

两种描述符路径的录制命令序列保持一致。
卸载后缓冲与图像的存活计数均为零。
这些检查验证 CPU 转换及测试后端的资源所有权。
实际驱动行为和像素输出按设备用例另行验证。

## 构建与回归

Release 与 Debug 的运行产品及所选目标构建通过。
两配置各十二项受影响 CPU 检查通过。
检查覆盖材质、透明度、运动、阴影和反射提交。
两配置各五百三十五份生产着色程序保持基线字节。

## 延期范围与证据

原生四帧、双设备同步及实际帧收益按用户安排延期。
完整画质和性能门槛保持既有验收状态。
夹具的分配改善用于定位，原生 CPU 目标保持八毫秒。
