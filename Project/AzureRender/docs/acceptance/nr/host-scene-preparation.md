# 宿主场景准备优化

## 实现与所有权

生产来源为 `723286a`。
`RuntimeSceneSnapshotCache` 按源身份保留静态字段及实体代际。
每帧刷新变换、可见性和对象阴影。
场景替换与节点新增会更新源身份。
失效实体、父级和灯光引用按原快照契约过滤。
组件移除时恢复作者声明的变换和可见性默认值。

`RuntimeRenderSnapshotCache` 持有资源绑定、节点顺序及父级索引。
动态节点和灯光空间数据按相同运算刷新。
三个复用槽位通过共享所有权保护已经发布的帧。
额外保留帧由调用者独立持有，所属复用池保持有界。
Player 发布文档时同时交换对应的快照状态。
公开独立副本接口保持原语义。

## 成本控制

二十帧宿主记录中，游戏场景快照约为 1.54 毫秒。
场景描述及资源路径解析约为 2.02 毫秒。
固定步进约为 1.44 毫秒，摄像机约为 0.47 毫秒。
本项机制归属快照、描述及路径准备。

实际原生文档包含 1679 个节点及 374 个资源。
一百轮交替控制消费同一 ECS 状态。
完整节点、资源、材质、灯光和环境描述保持一致。
保留的初始帧在后续运动中保持原值。

| 所属操作 | 均值，毫秒 |
| --- | ---: |
| 独立快照及完整描述准备 | 1.517 |
| 专用快照及描述复用 | 0.246 |

局部运算减少约 84%，缓存路径准备一次静态资源。
按已测宿主阶段估算可争取约 2.98 毫秒的 CPU 收益。
该估算用于集中验证门槛，整帧结果单独记录。

## 原生结果

完整联合场景采用 1080p、固定步长及三百帧预热。
基线和候选各记录一百二十帧短时样本。

| 指标 | 基线 | 候选 |
| --- | ---: | ---: |
| CPU 均值，毫秒 | 17.911 | 13.807 |
| CPU P95，毫秒 | 21.847 | 15.278 |
| GPU 均值，毫秒 | 21.474 | 21.521 |
| GPU P95，毫秒 | 21.967 | 21.856 |

CPU 短时均值减少约 4.10 毫秒，读数改善约 23%。
局部机制控制与整帧读数具有各自的归因范围。
GPU 基本持平，663 份着色器保持相同字节。
原生四帧 1440p 冻结对照均为零像素差异。
运行后缓冲和图像归零，验证日志保持清洁。

候选记录中有一次软件热限速。
全部八十瓦观察条件也未通过。
本项保留 CPU 实现，正式性能及整体画质继续待验收。
CPU P95 八毫秒、GPU P95 16.6 毫秒及正式样本要求保持有效。
