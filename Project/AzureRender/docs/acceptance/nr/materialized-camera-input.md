# 相机物化输入共享验证

## 实现与来源

Runtime 相机服务接收调用方持有的渲染描述。
Player 与编辑播放将同一份描述交给相机和几何消费者。
宿主资源服务负责路径解析，输入生命周期归属于本帧。
接口与取样规则见[呈现快照](../../runtime/game-render-snapshot.md)。

源码基线为 `f05f22e`。
当前原生[调用栈](current-cpu-hotspots.md)包含相机中的渲染描述转换。
候选前的 Player 副本与来源指纹用于同负载控制。
完整阶段要求见[实施计划](../../plans/2026-11-06-materialized-camera-input.md)。

## 构建与兼容

缺少新重载时，实际测试首先触发编译失败。
通过结果覆盖文档及物化描述两种入口的等价性。
父级变换、插值、快照隔离、优先级及跟随回退共同检查。
缺省相机与当前组件的启用状态继续遵循运行时规则。

Release、Debug 实际宿主与所选产品均构建通过。
两配置各十四项受影响 CPU 检查通过。
回归覆盖呈现、相机、物理、平台玩法及探索设计。
既有的无参数和场景文档入口继续通过原有用例。

NVIDIA Release 四帧与原冻结参考 RGB 逐字节一致。
一千七百二十九份挂载项目文件在采集前后保持一致。
两配置各五百三十五份生产着色程序保持基线字节。
实际进程正常退出，卸载资源计数归零。

本单元调整 CPU 输入共享，RHI 及着色源码保持受检版本。
双设备深度机制按[纯深度阴影](depth-only-shadow.md)的来源范围引用。

## 成对短时成本

控制顺序为基线、候选、同一基线。
三次进程使用同一项目、分辨率及显式生产资源目录。
每次预热三百帧，统计一百二十帧。
三次供电、功耗及热状态检查全部通过。

| 项目 | 前置基线 | 候选 | 后置基线 |
| --- | ---: | ---: | ---: |
| CPU 工作均值，毫秒 | 20.99 | 19.47 | 20.46 |
| CPU 工作 P95，毫秒 | 23.31 | 21.79 | 23.45 |
| GPU 帧 P95，毫秒 | 34.95 | 34.43 | 34.96 |

两次基线 CPU 均值的相对漂移为百分之 2.58。
候选相对基线平均值降低约百分之 6.06。
约 1.26 毫秒差异满足本轮预先声明的诊断收益条件。
该结论限定于当前固定负载及短时样本。

原 CPU 八毫秒与 GPU 十六点六毫秒目标继续未通过。
正式一千八百帧及交付长跑按原门槛验收。
角色、阴影、反射和 GI 的用户画质仍未通过。
资源路径解析与关卡轮询继续按独立单元定位。
