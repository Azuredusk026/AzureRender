# 有界图像解码评估

候选归属于 RenderCore 的 glTF 导入器。
当前生产使用既有同步解码及二进制材质准备。
并行候选保存在隔离证据中。

## 成本与机制

既有角色及地面加载序列约为 11.77 秒。
其中图像解码约 7.81 秒，占比约 66%。
像素转换约 0.85 秒，约占 7%。
这些数据属于先前同输入的 CPU 局部定位。

候选对至少六十四 KiB 的 PNG 并行解码。
全进程至多持有三个额外工作。
每次调用至多保留三个待合并结果。
主线程按图像索引合并像素、层级和诊断。

各工作拥有其压缩输入和解码结果。
导入返回前等待全部工作。
小图及其他格式走同步解码。
公开接口、材质因子及图像精度保持既有契约。

## 集中评估

单次批次采用串行、并行、并行、串行顺序。
全部控制使用同一私有程序和相同实际输入。
每次均检查两份地面及十四份角色材质。
十三组像素、打包参数和导入策略摘要均一致。

| 顺序 | 控制 | 加载墙钟 | CPU 工作 |
| --- | --- | ---: | ---: |
| 1 | 串行 | 40.240 秒 | 25.953 秒 |
| 2 | 并行 | 22.876 秒 | 20.813 秒 |
| 3 | 并行 | 9.359 秒 | 10.047 秒 |
| 4 | 串行 | 9.103 秒 | 8.891 秒 |

串行样本相差约 4.42 倍，漂移原因尚未确认。
分组均值的表面降幅为 34.67%。
该均值不具备稳定控制，不能证明优化收益。
末尾相邻样本中，候选墙钟高约 2.81%。

进程工作集峰值约为 1.44 GB，按十进制计。
实际原生资产与公开夹具的内存预算分别解释。
一百一十五份输入及生产源码摘要保持一致。
本轮没有启动原生帧测试或额外回归批次。
