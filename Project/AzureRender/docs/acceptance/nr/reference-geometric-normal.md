# 参考几何法线

版本二材质画像的 `referenceNormal` 使用 `schemaVersion: 1`。编码 `geometry` 取插值后的几何法线，归一化后应用片元朝向和参考坐标轴。编码 `sampled-rg` 读取标准法线纹理的两个通道并重建正向 Z。

原生眉部事件 296 和脸部事件 345 在取基础颜色前写入压缩法线。参考夹具的两份对应材质声明 `geometry`，通过原生法线附件核对受检位置。

## 解析对照

64 × 64 对照使用方向向量 `(1, 2, 4)` 归一化后的值，避开 10 位编码的中点。固定绑定、索引绑定和无贴图用例均输出 `[585, 804]`。采样后重建对照输出 `[675, 777]`。无效编码由材质加载器拒绝。[Vulkan 定点转换规范](https://docs.vulkan.org/spec/latest/chapters/fundamentals.html#fundamentals-fixedconv)

## 实际附件

| 设备 | 眉部法线逐位一致 | 脸部法线逐位一致 | 完整接收超差 | 新增接收超差 |
| --- | ---: | ---: | ---: | ---: |
| NVIDIA | 496 / 496 | 3,576 / 3,825 | 284 | 10 |
| Intel | 470 / 496 | 3,503 / 3,825 | 632 | 21 |

两块设备的眉部法线均相差至多一个编码步长，脸部各有 3,823 处满足该条件。接收超差沿用原有逐通道一字节门槛。NVIDIA 和 Intel 的原超差集合分别有 136 处和 131 处进入门槛。

新增接收超差全部位于两份受检材质。两块设备的这些位置在新路径均满足法线一编码步长，分别有 8 处和 19 处法线逐位一致。最大新增可见量差为 17 字节。深度与对象标识的完整附件逐字节一致，冻结头发的颜色和可见量在各设备逐字节复现。

MSVC 在 Release 和 Debug 下核对了材质结构的全部既有字段偏移。两配置的尺寸分别为 3,720 和 4,296 字节。场景扩展使用 API 17。

## 构建与验收

Release 和 Debug 分别通过 8 项和 7 项 CPU 检查，两配置各在 NVIDIA 和 Intel 上通过 5 项 GPU 检查。程序集清单包含 895 份着色器，固定及索引绑定的参考法线片元程序使用核对后的摘要。同设备的两配置在五类附件和三帧 PNG 上逐字节一致。原始场景四帧逐字节匹配冻结参考，回归用时 255.125 秒。

整体状态为 `failed-user-review`。完整接收差异和 Intel 头发颜色按原门槛继续验收。
