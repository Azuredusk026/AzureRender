# CPU 长时执行状态诊断

## 来源与范围

受检生产源码为 `a295e09`。
私有程序在宿主、场景准备及计时收集中插入记录。
两次采集使用相同私有程序及冻结输入。
生产源码、运行产物和图形程序保持原字节。

每次记录两千一百帧。
细分窗口为第 310、910、1510 及 2070 帧起的各二十帧。
节点数量均为一千六百七十九，资源数量均为三百七十四。
结果用于阶段归因，原生验收继续引用所属生产采集。

## 阶段观察

下表为系统托管执行状态下的阶段均值。
首段和末段分别为第 310 与 2070 帧起的二十帧。
子项包含在对应父项中，分别解释。

| 阶段 | 首段均值 | 末段均值 |
| --- | ---: | ---: |
| 场景准备 | 9.02 毫秒 | 18.52 毫秒 |
| 渲染器更新 | 9.17 毫秒 | 20.10 毫秒 |
| 命令录制 | 3.97 毫秒 | 8.37 毫秒 |
| CSV 写入 | 0.31 毫秒 | 0.48 毫秒 |
| 命令池重置 | 0.039 毫秒 | 0.048 毫秒 |

相同输入规模下，多个 CPU 阶段同步变慢。
计时文件写入及命令池重置的增量较小。
系统处理器性能计数在后段下降。
现有证据更支持执行状态变化这一方向。

系统计数使用 PDH 的英文计数接口。
采样间隔约为一秒，并保留计数路径与状态。
整体计数不能单独确定主线程频率或 CPU 温度。
接口适用范围见[微软性能计数说明](https://learn.microsoft.com/en-us/windows/win32/perfctrs/about-performance-counters)。

## 单变量控制

候选只为本任务的测试进程请求高性能执行状态。
设置前为系统托管，设置后为显式 `HighQoS`。
进程身份和设置前后的状态均已核对。
系统电源计划、优先级及处理器亲和性保持原有配置。

该候选仍在末段出现多个 CPU 阶段同步变慢。
末段场景准备均值为 19.51 毫秒。
末段渲染器更新为 21.05 毫秒，录制为 8.78 毫秒。
候选不进入生产或正式采集工具。

两批均出现 GPU 软件热降频。
CPU 温度、功耗及核心调度的具体原因继续独立核对。
执行状态的控制依据为[微软 QoS 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/quality-of-service)。
本单元没有 CPU 温度或内存泄漏的确定结论。
