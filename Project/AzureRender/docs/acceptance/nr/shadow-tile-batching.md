# 阴影分块批处理验收

## 实现与结果

八分块工作组已接入默认配置。
每组使用 128 个线程，并保留分块内原有归约树。
两设备、两配置及默认入口核对共二十八项通过。
一组原生严格四帧保持 RGB 及 PNG 摘要零差异。

独立内核均值降低约 43.24%。
一次整帧比较的 GPU 均值减少约 0.108 毫秒。
同步日志无错误，卸载分配残留为零。
整体画质与正式帧预算继续待通过。

## 数值与调度

每个分块仍覆盖八乘八个源纹素。
十六个线程保持相同的四纹素采样与最值顺序。
八个分块按局部编号划分共享存储。
尾组中的有效范围与对象记录后缀均通过实际 GPU 检查。

普通程序继续支持单分块配置。
非法批量在资源分配前报告错误。
元数据确认原生使用 `shadowBoundsTilesPerGroup=8`。
全部 674 份原有程序保持摘要一致，仅新增一份批处理程序。

对象主阴影特化的负载范围先按既有报告核对。
当前原生元数据的对象主阴影接收项为零。
本单元选择工作组批处理，并复用已有输入。
范围核对使用既有报告，专用原生进程数量为零。

## 独立效率与预热

独立进程使用 4096×4096 D32 输入。
有效比较的每个区间预热 2048 次，再统计 128 次。
两个候选区间由前后参考包围。
输出继续按精确最值及对象记录逐位比较。

参考内核均值约为 0.500149 毫秒。
候选均值约为 0.283902 毫秒，减少约 43.24%。
前后参考漂移约为 0.02%。
该结果满足局部减少 20% 及漂移 5% 的门槛。

首轮采用 256 次预热，参考漂移约为 9.91%。
该轮单独登记为预热校准，未计入有效收益。
预热调整后仅复核一次独立内核。
原生四帧及整帧比较均在有效门槛通过后启动。
