# GPU 透明索引验收

## 实现范围

本阶段入口为 `3b4fa9d`。
`GpuTransparentIndexSort` 提供有界透明索引准备。
GPU 完成顶点变形、深度键、稳定排序及索引写入。
场景与独立资产工具共用[公共契约](../../development/gpu-transparent-index-sort.md)。

场景按实际工作规模选择执行路径。
合格任务通过 GPU 生成逐图元索引。
小任务及资源资格不足的任务使用 CPU 路径。
实际路径、缓冲规模和回退原因进入捕获清单。

骨骼输入由调用方发布，内部计算依赖由机制发布。
场景渲染图声明骨骼读取及索引写入、消费。
索引绑定使用实例快照中的实际缓冲。
帧槽退役、准备凭据及卸载顺序保持明确所有权。

## 集中检查

Debug 与 Release 所属目标构建通过。
两配置合计十二项 CTest 通过。
检查覆盖机制、双设备及三项既有录制行为。
模块边界检查覆盖十八个目标，违规数为零。

每设备每配置核对三组独立合成输入。
每组结果按 CPU 参考逐项检查位置、键及索引。
真实角色资产另覆盖三组姿态及形态组合。
相关设备为 RTX 4060 Laptop 和 Intel UHD Graphics。

真实资产每设备核对 466812 个世界位置。
排序索引每设备核对 1673856 项。
位置的单精度字节、深度键和索引均完全一致。
同步验证错误、卸载后图像及缓冲均为零。

录制用例包含不透明主资产及透明附加资产。
一千个透明实例按各自范围绑定 GPU 索引。
节点透明度、静态蒙皮及深度预填回归通过。
原生四帧的 RGB 像素差异为零。
四张 PNG 的 SHA256 与冻结参考分别相同。
场景实际准备 33015 个顶点，内部缓冲约 28.8 MiB。
捕获过程的输入、程序及着色产物保持原字节。

## 局部 CPU 成本

冻结项目的 1729 项输入保持相同字节。
两侧各运行四十帧，选取第五至四十帧。
样本用于准备阶段的短时对照。
绘制绑定的修复由录制及画面结果单独核对。

| 阶段 | 参考均值 | GPU 准备均值 |
| --- | ---: | ---: |
| 透明准备 | 1.03873 毫秒 | 0.05071 毫秒 |
| 渲染器更新 | 3.57155 毫秒 | 2.32428 毫秒 |

透明准备减少约 0.988 毫秒，即 95.12%。
渲染器更新的观测降幅为 34.92%。
其他阶段存在约 0.26 毫秒的波动。
本批归因范围为透明准备所省去的 CPU 工作。
