# G8 共享机制与应用分层验收

> 文档类型：验收记录
> 状态：通过
> 更新日期：2026-10-06
> 适用范围：Windows x64、编辑器与 Player

## 来源与采用范围

本阶段落实 A1 的系统装配与 B8 的机制边界。依据见[gkNextEngine 架构评估](../../research/2026-10-06-gknextengine.md)。来源提交由研究清单固定。实现消费 F4 的类型与生命周期契约。

`AzureGameplay` 提供角色、物理、动画与相机系统。`AzureProjectRuntime` 提供探索默认配置和任务策略。核心 Runtime 通过系统接口调度实例。两种应用组合共用同一调度循环。

## 装配与配置

`SystemRegistry` 注册工厂并创建独立实例。配置声明版本、动作绑定与系统数组。未知系统、重复实例和非法字段明确拒绝。失败初始化按逆序关闭已创建的运行服务。

角色组件版本为 4，动画组件版本为 3。配置名分别选择动作映射与动画状态映射。迁移补齐合法默认值。共享机制根据配置读取动作名和状态名。

通用交互负责距离、遮挡、平局与边沿分派。可用性回调由应用提供。探索策略读取任务组件状态。检视工具选择普通资产并调用项目脚本。

调度、输入与失败规则见[运行系统装配](../../runtime/system-composition.md)。检视项目位于 `assets_public/scene_inspector/`。它只装配轨道相机与交互系统。世界包含观察者和两个普通资产。

## 专项验证

`AzureEngine.SystemComposition` 验证注册扩展和不同组合。用例覆盖初始化恢复、场景通知与空调度器。自定义箭头键和动画状态证明配置生效。非法重绑定保持既有输入与按键状态。

`AzureEngine.SceneInspectorHost` 验证正式编辑宿主与 Player。生产命令完成保存、重开、Play 与 Stop。输入回放选择资产并操作轨道相机。报告检查脚本、视口控件与编辑态恢复。

验证采用生产操作与输入回放。实体键鼠验证的执行范围单独记录。检视项目使用公开 CC0 方块资源。私有动画与派生媒体保持本机。

## 失败复现与修复

通用交互夹具复现任务注解对普通目标的过滤。应用策略安装后，通用目标按合法状态选择。依赖夹具复现 Runtime 的逆向引用。实际构建图与 include 检查覆盖该边界。

生命周期夹具复现初始场景版本零的通知遗漏。调度器显式维护首次通知状态。延迟切场景在取消当前帧前通知系统。下一帧使用新世界继续执行固定步。

动作夹具复现未绑定配置未被拒绝。角色系统在初始化时检查动作。完整构建复现聚合初始化的字段顺序要求。配置字段位于组件尾部，兼容既有初始化。

真实宿主复现 Stop 后的报告采集崩溃。报告采集检查运行实例是否仍有效。修复后的检视宿主验证正常退出。视口断言按实际界面所属系统检查。

## 性能与设备

标准、编辑器和压力负载各测三轮。每轮预热 300 帧，再采样 1800 帧。九轮均满足主计划的严格预算。采样期间生产源码保持冻结。

下表为三轮 P95 的中位数，单位为毫秒。设备为 RTX 4060 Laptop。标准与压力分辨率为 1920×1080。编辑器使用同尺寸窗口和九个默认面板。

每轮编辑器使用独立的空配置目录。报告保存退出后的布局和面板状态。实际渲染尺寸保存在 GPU 计时记录中。持久化状态证据用于核对默认工作区。

Intel 核显在 960×540 完成完整任务。测试使用完整材质与四级阴影。两次重开、退出释放与错误检查通过。设备、驱动与能力记录保存在核显报告中。
