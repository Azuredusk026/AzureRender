# 项目启动快照验证

日期：2026-10-31。归属为恢复任务 P0-startup。
状态：双配置构建及受影响检查通过。

范围见[实施计划](../../plans/2026-10-31-project-startup-context.md)。

## 公共机制

`ProjectStartup` 持有项目、资产索引和启动关卡。
准备成功后，宿主通过只读接口消费完整内容。
Player 配置与运行会话共用该准备结果。
项目检查使用同一份索引和场景。

运行会话持有自己的活动状态及运行世界。
初始提交安装已准备关卡中的组件。
后续切关及热刷新在会话副本中扫描和提交。
传统场景通过当前候选索引解析材质与雾引用。

`Project::loadScene(path, assets)` 要求索引已刷新。
项目文件、项目身份与挂载目录须与索引归属一致。
单参数入口按内容需要准备独立索引。
使用及所有权见[运行说明](../../runtime/assets-levels.md)。

## 独立契约

测试使用真实项目、雾资源和组件关卡。
红测在索引准备后写入无关的损坏关卡。
场景加载触发额外扫描并报告 JSON 解析错误。
借用已准备索引的场景加载通过相同输入检查。

独立入口仍校验当前资产清单。
未刷新索引、错误身份、错误文件及挂载均被拒绝。
传统场景的雾引用解析为对应资源路径。
组件关卡的初始位置为七、八、九。

快照准备后，源关卡写入损坏内容。
准备新的快照会报告输入错误。
已有快照可创建两个独立运行会话。
修改一个世界的位置保持另一个世界和快照有效。

实际 Player 使用刚体地面和角色组件验证组件作用。
一百七十九个固定步长后，角色高度在 0.8 至 1.2 之间。
该检查消费真实项目的启动快照和运行世界。

恢复源文件后，请求新的目标关卡。
会话成功读取新内容，节点位置为十一、十二、十三。
已共享的启动快照与另一个会话保持原有内容。
既有取消及提交失败恢复使用资产关卡回归检查。
