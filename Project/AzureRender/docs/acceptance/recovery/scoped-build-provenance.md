# 构建流程验证

## 实现范围

日常构建选择运行产品及指定的可执行测试目标。
完整构建按配置执行全部目标。
每份收据明确记录构建范围、源码和产物摘要。
调用方式见[构建范围与来源核验](../../development/build-scopes.md)。

所选测试程序、着色程序及模块均按字节核验。
产物缺失或源码途中变化时，既有收据保持可追溯。
大文件摘要使用固定大小的数据块。

## 验证结果

十八项 Python 检查通过。
范围涵盖目标选择、缺失产物、篡改及失败收据。
三十二 MiB 输入的摘要符合预期 SHA-256。
该用例的 Python 跟踪分配峰值低于四 MiB。

真实 CMake 与 Ninja 夹具完成三种模式检查。
夹具验证实际命令编排，产物为显式测试文件。
所选模式和运行模式均保持所需产物完整。
完整模式同时构建夹具中的额外测试目标。

实际工程的 Release 与 Debug 增量构建通过。
两配置分别核验 602 份产物。
两配置各两项相机及来源核验检查通过。
两配置各 535 份生产着色程序保持受检字节。

本轮工程增量构建约耗时十九秒与十八秒。
时间按本次输入与缓存状态记录。
冷缓存的构建收益需要相同修改和环境下的测量。
