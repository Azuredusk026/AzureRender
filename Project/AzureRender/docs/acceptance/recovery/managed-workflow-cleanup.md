# 托管发布目录恢复验证

日期：2026-10-31。归属为 P0-tools。

实施范围见[目录恢复计划](../../plans/2026-10-31-managed-workflow-cleanup.md)。

## 目录恢复契约

验证工具移动自身生成的发布包，并在结束时恢复目录。
恢复操作的等待期限为两秒。
Windows 错误五、三十二及三十三允许有限等待。
持续占用及其他错误继续报告失败。

目标目录必须为空缺路径。
目标已有内容时，源与目标均保持有效。
成功结果记录实际尝试次数。
生产运行和发布完整性检查沿用既有规则。

## 真实目录租约

独立夹具使用 Windows 目录句柄持有共享约束。
直接恢复时，延时释放用例命中错误三十二。
有限等待实现通过全部三项检查。
两种配置的 CTest 注册及实际调用均通过。

检查覆盖租约释放后移动、持续占用及目标已存在。
持续占用按期限失败，并保留源目录。
目标内容与源内容分别核对。

## 实际工作流

Debug 和 Release 各验证 CoreCLR 与 NativeAOT。
四项实际流程均正常退出。
两种脚本分别验证注解及角色控制。
编辑预览验证停止后的编辑态恢复。

两份 Release 发布包均包含六百七十四个文件。
发布包移动后，原项目及引擎目录暂时隐藏。
启动路径只保留系统目录。
CoreCLR 使用外部运行时，NativeAOT 使用隔离配置。

两份发布包均通过脚本运行、资源卸载及完整性检查。
篡改托管程序集均被拒绝。
两份目录均在首次尝试时恢复成功。
