# 渲染性能架构

## 范围与实测

目标为完整联合场景的 1080p 原生分辨率、每秒六十帧。
画质、角色材质、反射及 GI 按原门禁验收。
GPU P95 目标为 16.6 毫秒，CPU 工作目标为八毫秒。
调研日期为 2026-11-05，实现状态由开发总计划持有。

当前采集均预热三百帧，并统计一千八百帧。
场景含 374 份网格、1,679 个运行时节点。
实际可见场景约为 71 万个三角形。
计时覆盖阴影、场景及后处理，热状态独立记录。

| 采集 | CPU 工作 P95 | GPU 帧 P95 | 状态 |
| --- | ---: | ---: | --- |
| 受检基线 | 56.46 毫秒 | 42.43 毫秒 | 时间与热状态未通过 |
| 每帧资源键候选 | 46.35 毫秒 | 42.99 毫秒 | 时间与热状态未通过 |
| 实体身份候选 | 38.30 毫秒 | 40.38 毫秒 | 交流供电稳定，时间与热状态未通过 |
| 运动向量绑定候选 | 33.85 毫秒 | 38.94 毫秒 | 交流供电稳定，时间与热状态未通过 |
| 帧数据与批量屏障候选 | 24.83 毫秒 | 39.81 毫秒 | 交流供电稳定，时间与热状态未通过 |

六份 CPU 原生采样保留调用地址与符号映射。
五份位于资源键查询，一份位于运行时实体身份查询。
候选证明资源键查询存在成本，完整帧预算仍未达到。
GPU 场景阶段的成本继续按实际事件分解。

## 方案比较

| 方案 | 适用瓶颈 | 接入范围 | 验证边界 |
| --- | --- | --- | --- |
| 帧数据直接索引 | 资源键及实体身份的重复检索 | 场景实例构建、运行时身份读取 | 身份复用、保存重开及既有图像 |
| 持久渲染注册表与增量快照 | 每帧完整文档转换及静态数据重建 | 运行时、渲染快照及资源修订 | 结构变更、动态变换及多视图隔离 |
| 统一几何区与 GPU 批处理 | 提交及几何绑定成本 | 几何分配、间接命令及材质批次 | 透明顺序、蒙皮、覆盖层及设备回退 |

执行先完成直接索引，再核对完整帧的剩余成本。
增量快照消费明确的结构修订和动态数组。
几何批处理按实测热点进入对应模块。
原生透明发片、衣料覆盖和深度条件各自保留顺序契约。

现有引擎具备 GPU 剔除、多重间接绘制及并行记录。
新增能力需说明当前批次边界及对应的性能收益。
GPU 事件计时用于区分着色、重复绘制与提交成本。
来源重放计时与正常运行帧耗时分别记录。

## 落地顺序

1. 复用实体已有的身份组件，完成直接查询和失效检查。
2. 保存资源键候选的四帧图像与全部失败控制。
3. 补齐 CPU 各阶段与 GPU 事件的成本分解。
4. 按实际热点确定增量快照及几何批次的修改单元。
5. 每个单元完成双配置、公共场景及原生联合回归。

运行时身份组件由所属实体拥有。
查询须同时核对实体存活和文档身份的对应关系。
资源键数组由单帧实例构建持有，结构变更逐帧生效。
设备资源继续按帧完成状态退役。

## GPU 事件分解

实际联合帧包含 3,786 个可计时事件。
重放计时总和约为 39.23 毫秒，按独立用途解释。
最昂贵的六十四个事件已读取程序身份及字节摘要。
其余事件的耗时保留为未分类部分。

| 已识别程序组 | 选中事件耗时之和 |
| --- | ---: |
| 普通表面的探针与辐照 | 9.09 毫秒 |
| 快照表面的探针与辐照 | 5.04 毫秒 |
| 普通表面的照明接收变体 | 2.48 毫秒 |
| 快照表面的照明接收变体 | 1.68 毫秒 |
| 反射射线分发 | 0.99 毫秒 |

这些结果将后续诊断指向探针遍历与表面着色复用。
局部探针采用保序的体积混合及来源自适应。
分簇候选筛选需使用保守范围，保持有效探针的顺序。
着色特化及重复着色的收益按独立候选实测。

NVIDIA 的[管线建议](https://developer.nvidia.com/blog/vulkan-dos-donts/)说明特化及状态绑定的优化方向。
[着色建议](https://developer.nvidia.com/blog/advanced-api-performance-shaders/)覆盖寄存器压力及数据访问。
资料提供待验证的方向，当前实例以实测事件决定接入次序。
完整原件与未分类范围见[事件收据](../acceptance/nr/evidence/2026-11-05/performance-architecture/event-results.json)。

## 编译优化分项

四个主要表面程序已做隔离重放。
实验使用原 GLSL、原宏与原资源绑定。
唯一变量为 `glslc -O -fpreserve-bindings`。
四份程序均通过 Vulkan 1.0 的 SPIR-V 校验。

[Shaderc 文档](https://github.com/google/shaderc/blob/main/glslc/README.asciidoc#452--o0--os)规定 `-O` 的性能优化含义。
三次重放的最终 RGB 输出逐字节一致。
基线、候选、基线的事件耗时和为 42.75、45.09、39.25 毫秒。
基线漂移约为 8.20%，本次实验未证明性能收益。

该编译候选保留在隔离目录，生产程序保持受检字节。
耗时和用于本次重放诊断，完整运行帧耗时独立解释。
源程序与原始结果见[编译分项收据](../acceptance/nr/evidence/2026-11-05/shader-optimization/results.json)。

## 节点快照复制

运行时在场景文档副本上更新并稳定压缩节点。
一千零二十四节点的分配夹具具有四组材质槽。
Release 失败控制分配 8,512,487 字节。
候选分配 4,301,847 字节，等于一次场景值复制。

两配置各十五项 CPU 检查通过。
输入、预算和范围见[节点快照验证](../acceptance/nr/runtime-snapshot-copy.md)。
