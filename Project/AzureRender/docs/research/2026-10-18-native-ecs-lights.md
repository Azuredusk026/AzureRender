# 当前场景的 ECS 灯光读取

此调查属于 NR1 原生来源同步。
当前灯光保存在 ECS 列与序列化记录中。
读取器按实体配对初始化块和流式块。
入口为 [lighting_ecs.py](../../tools/endfield_native/lighting_ecs.py)。

## 读取范围与结果

来源为本机 `base01_lv001` 的静态流式目录。
读取覆盖 90 个配对文件，包含全局块与各层级。
VFS 读取经过摘要认证，游戏目录保持只读。

| 对象 | 数量 |
| --- | --- |
| 含灯的 ECS 列组 | 23 |
| 跨空间块的物理灯记录 | 280 |
| 按实体去重的灯 | 232 |
| 点光源 | 122 |
| 聚光源 | 109 |
| 方向光源 | 1 |
| 带原生 Cookie 引用的灯 | 6 |

名称用于核对来源，灯类型来自原生字段。
同一实体的重复记录须具有相同序列化属性。
各次出现的位置与占位列字节分别保留。
动态流式目录另有一个灯列组，另行解析。

旧读取器只选择原生类型 1 和灯组件掩码。
当前灯使用序列化 ECS 类型 2。
该筛选条件导致当前灯目录返回零条。
原生类型 1 中的 `0x10000` 是反射探针。

## 列与属性契约

初始化块的并行分组保存实体标识与列描述。
灯组包含类型 42、类型 63 和名称类型 21。
三者的步长分别为 244、448 和 64 字节。
固定列主要保存运行时占位数据。

同实体的类型 2 记录保存实际序列化参数。
记录字段 3 指向属性表。
属性表的字段 3、4、5 保存标识、类型和值。
类型 17 的值通过两层表包装字节向量。

| 属性标识 | 字节数 | 对应数据 |
| --- | --- | --- |
| `0xff000000` | 236 | 类型 42 的字节 8 至 243 |
| `0xff010000` | 448 | 类型 63 的完整数据 |
| `0xff020000` | 8 | 流式侧的 Cookie 路径标识 |

读取器保留全部属性标识、类型和原始字节。
路径标识通过当前 `StringPathHash.bin` 解析。
六条引用均解析到唯一 Cookie 纹理路径。
未知附加字段保留原字节，等待专项语义核对。

## 原生字段依据

静态依据来自 `UnityPlayer.dll`。
命名入口为 `UnityEngine.HGSharedLightData` 的取值函数。
名称数组含 4112 项，对应函数地址均位于执行节。
对应关系仍需运行时注册路径独立确认。

组件解析函数分别使用第 42 位与第 63 位掩码。
颜色、强度和矩阵通过类型 42 读取。
灯类型、形状、范围和锥角通过类型 63 读取。

| 字段 | 组件 | 组件内偏移 |
| --- | --- | --- |
| 颜色 | 42 | `0x08` |
| 强度 | 42 | `0x18` |
| 色温 | 42 | `0x1c` |
| 色温开关 | 42 | `0x20` |
| 世界矩阵 | 42 | `0x74` |
| 灯类型 | 63 | `0x0c` |
| 形状 | 63 | `0x10` |
| 范围 | 63 | `0x18` |
| 外锥全角 | 63 | `0x24` |
| 内锥全角 | 63 | `0x28` |
| 线光长度 | 63 | `0x90` |
| 包围盒开关 | 63 | `0x5c` |

矩阵按列保存，平移位于最后一列。
局部正 Z 列表达灯的世界方向。
灯参数允许保留线光长度的负值哨兵。
已解码浮点字段须有限，强度与范围须非负。
