## 研究结论

gkNextEngine 的价值在于界面有清楚的主次。
场景占据主要空间，工具围绕当前任务出现。
深灰结构色、少量强调色和统一控件形成整体感。
这些效果由公共基础层与应用装配共同实现。

AzureRender 已有停靠、主题和编辑服务。
本轮应补齐基础控件边界，并逐步统一产品界面。
操作逻辑遵循已确认的 Unity 式习惯。
视觉组织借鉴 gkNextEngine 与 UE Starship。

## 从 gkNextEngine 吸收什么

以下路径相对参考仓库根目录。
每项均已检查对应源码。

| 设计原则 | 实现位置 | AzureRender 的落地方式 |
| --- | --- | --- |
| 背景保持中性，强调色表达状态 | `src/Modules/NextUI/UI/UiTheme.cpp` | 区分背景、面板、浮层、悬停、选中和焦点 |
| 字体、缩放与宿主能力集中提供 | `src/Modules/NextUI/UI/UiContext.hpp` | 项目中心和编辑器共享只含呈现信息的上下文 |
| 控件使用语义变体 | `src/Modules/NextUI/UI/UiWidgets.hpp` | 主按钮、普通按钮、图标工具、危险操作各有规则 |
| 禁用控件仍说明原因 | `src/Modules/NextUI/UI/UiWidgets.cpp` | 原因由命令状态提供，悬停和键盘焦点可读取 |
| 容器保证样式栈与布局收尾 | `src/Modules/NextUI/UI/UiScopes.hpp`、`UiContainers.hpp` | 补齐窗口、子窗口、工具条和浮层作用域 |
| 外壳返回操作意图 | `src/Modules/NextUI/UI/AppChrome.hpp` | 绘制只返回动作，宿主处理关闭、保存和窗口命令 |
| 品牌资源具备缩放与降级策略 | `src/Modules/NextUI/UI/DesktopUI.cpp` | 原创矢量标志，安装图标与绘制回退共用形状 |
| 视口工具按宽度取舍 | `src/Application/Render/gkNextRenderer/RendererViewportToolbar.cpp` | 测量内容宽度，低频选项进入更多菜单 |
| 设置按组组织，字段对齐 | `src/Application/Render/gkNextRenderer/RendererSettingsPanel.cpp` | 中文分类、属性搜索、两列对齐与局部重置 |
| 工作区有稳定面板标识 | `src/Application/Editor/gkNextEditor/EditorInterface.cpp` | 保持面板 ID，提供布局保存、恢复与重置 |
| 面板通过上下文与动作协作 | `src/Application/Editor/gkNextEditor/EditorContext.hpp`、`EditorActionDispatcher.hpp` | 复用 `PanelContext`、`EditService` 与 `EditorSession` |
| 属性呈现由字段描述驱动 | `src/Application/Editor/gkNextEditor/Panels/PropertyWidgets.cpp` | 属性控件归编辑器，基础控件保持业务无关 |
| 资源操作集中在内容浏览器 | `src/Application/Editor/gkNextEditor/Panels/ContentBrowserPanel.cpp` | 统一目录树、面包屑、搜索、列表和缩略图模式 |
| 控件目录可以独立审阅 | `src/Modules/DevTools/UI/UiCatalog.cpp` | 增加开发用控件样例页，集中检查所有状态 |
| 后端与界面职责分别维护 | `src/Modules/NextUI/ImGuiContextHost.cpp`、`ImGuiVulkanRenderer.cpp` | 优先提取共享字体与样式，保留现有 Vulkan 后端 |

实际界面中的侧边模式栏适合渲染查看器。
编辑器已有层级、属性和内容区，应按制作任务布局。
帮助浮层中的玩法按键属于其演示应用。
AzureRender 的默认帮助只呈现编辑操作。

参考项目仍有需要谨慎采用的实现。
`PropertyWidgets.cpp` 存在局部颜色常量。
`TitleBarOverlay.cpp` 的部分保存逻辑直接访问场景导出。
我们采用其视觉与组织原则，业务修改沿本项目服务执行。

参考项目使用 SDL3，并拥有定制 Vulkan UI 渲染器。
相关平台和后端代码仅用于理解边界。
AzureRender 的落地接口基于 GLFW 与现有 ImGui 后端。
直接复制模块会引入额外的引擎与平台依赖。

## 从 UE 吸收什么

以下路径相对 UE 的 `Engine/Source/`。
本轮采用设计方法，资产与实现由 AzureRender 自己维护。

| 设计原则 | 源码位置 | 具体采用方式 |
| --- | --- | --- |
| 按用途命名颜色 | `Runtime/SlateCore/Private/Styling/StyleColors.cpp` | 颜色表达输入、面板、焦点和选择状态 |
| 控件拥有完整状态 | `Runtime/SlateCore/Private/Styling/StarshipCoreStyle.cpp` | 普通、悬停、按下、禁用和焦点分别呈现 |
| 样式有统一入口 | `Runtime/SlateCore/Public/Styling/AppStyle.h` | 业务面板读取公共设计参数 |
| 工具栏围绕命令组织 | `Editor/LevelEditor/Private/LevelEditorToolBar.cpp` | 菜单、工具栏和快捷键共用操作状态 |
| 标签页与工作区可以恢复 | `Editor/LevelEditor/Private/SLevelEditor.cpp` | 稳定面板 ID、布局版本与损坏回退 |
| 项目选择是完整工作流 | `Editor/GameProjectGeneration/Private/SProjectBrowser.cpp` | 最近项目、搜索、选中、详情与明确主操作 |
| 布局和生命周期有独立所有者 | `Runtime/SlateCore/Public/Widgets/SWidget.h` | 将呈现、文档状态和平台资源分别归属 |

UE 的大量工具入口面向其完整产品规模。
AzureRender 的默认界面只呈现已交付的制作能力。
专用技术由扩展和项目代码声明。

## AzureRender 当前的具体差距

| 发现 | 源码依据 | 用户影响 |
| --- | --- | --- |
| 主题参数与局部颜色并存 | `src/editor/EditorTheme.cpp` | 修改主题需要追踪多处状态色 |
| 公共控件头文件依赖属性编辑业务 | `src/editor/ui/Widgets.hpp`、`Widgets.cpp` | 项目中心复用控件时带入编辑器领域依赖 |
| 图标仅有项目、成功和错误 | `src/editor/ui/Icons.hpp` | 工具栏主要依赖短文字按钮 |
| `AppChrome.cpp` 实际承载卡片和消息辅助函数 | `src/editor/ui/AppChrome.cpp` | 顶栏、底栏与浮层缺乏独立组合边界 |
| 顶栏使用固定居中偏移 | `src/editor/EditorToolbar.cpp` | 文案与缩放变化依赖额外布局分支 |
| 项目中心三条路径分散在标签页 | `src/editor/projects/ProjectCenterView.cpp` | 新建、打开和最近项目缺少统一主次 |
| 每帧获取最近项目会读取项目文件 | `ProjectCenterView.cpp`、`ProjectOpenService.cpp::recent` | 磁盘检查与绘制频率绑定 |
| 模板选项在界面中另写一份 | `ProjectCenterView.cpp`、`ProjectOpenService.cpp::templates` | 名称和支持能力可能分离 |
| 面板文件仍通过捕获宿主调用成员函数 | `src/editor/ImGuiEditorLayer.cpp` | 目录拆分后仍需继续明确状态所有者 |
| 菜单与面板存在中英文混用 | `EditorToolbar.cpp`、`EditorWorkspace.cpp` | 新用户难以形成统一的操作记忆 |

现有 ImGui 为 1.92.8，源码含停靠分支标记。
构建使用仓库内 GLFW 与 Vulkan 后端源码。
现有版本具备本计划所需的停靠与绘制能力。
字体沿用项目已有 Noto Sans CJK 资源。

## 采用边界

公共 UI 提供颜色、尺寸、字体、图标和容器。
工作台决定菜单、停靠、状态区和视口工具位置。
业务面板负责呈现领域状态与收集操作意图。
项目、场景、撤销和发布由既有服务负责。

运行查看器、项目中心和编辑器可以复用基础控件。
每种宿主分别决定可用能力与可见入口。
游戏内 UI 继续遵循自己的运行时契约。

本轮产物为研究、设计提案和实施计划。
Logo 与预览页面尚未接入引擎。
完整输入、中文输入法和多屏体验留到集中复核。
