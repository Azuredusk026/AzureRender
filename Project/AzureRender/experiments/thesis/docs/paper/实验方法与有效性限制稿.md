# 实验方法与有效性限制

## 研究设计与共同负载

本研究使用受控的非真实感渲染负载，比较传统多遍、Vulkan 子通道及动态渲染局部读取（Dynamic Rendering Local Read，DRLR）的执行时间和时间波动。三条路径执行几何缓冲、卡通着色和屏幕空间轮廓三个阶段。场景使用静止的过程球网格、固定橙色材质、方向光和正交相机。低复杂度网格包含 960 个三角形，高复杂度包含 16,128 个三角形。实验对几何复杂度的解释限于这两档网格及共同着色负载。 [共同负载契约](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/docs/workload.md)

传统多遍路径通过独立渲染通道执行前两个阶段，卡通阶段从纹理读取几何附件。子通道路径在同一个渲染通道内完成几何与卡通着色，并通过输入附件传递同像素数据。DRLR 路径在动态渲染范围内配置附件映射及局部依赖。三条路径的轮廓阶段均使用共同的独立渲染通道，读取中心像素及四个相邻像素的法线与深度。轮廓的邻域读取需要附件在前两个阶段之后继续存活。 [路径实现](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/src/benchmark.cpp) [共同负载契约](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/docs/workload.md)

## 区组与测量

实验使用 1920 × 1080 和 2560 × 1440 两种分辨率。设备、分辨率、复杂度与路径构成 24 个条件，每条件安排 5 次独立进程运行，共 120 次。一个区组固定设备、分辨率、复杂度和重复轮次，并相邻执行三条路径。五轮共形成 40 个区组。冻结清单使用随机种子 `20261112`，每轮打乱八个设备与负载组合的顺序，并为同一组合安排五种不同的路径排列。 [冻结计划](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/evidence/2026-11-12-pixel6/formal-plan.json)

每次独立进程预热 300 帧，再测量 1,000 帧。GPU 时间戳覆盖几何缓冲开始至轮廓结束，包括阶段间依赖及布局转换。CPU 录制时间覆盖共同绘制命令的录制。图像读回与文件保存位于测量区间之外。基准逐帧等待 GPU 完成，因此测量对应这一提交策略下的三阶段执行区间，吞吐和端到端交互延迟需要各自的观测。 [冻结计划](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/evidence/2026-11-12-pixel6/formal-plan.json) [计时与提交实现](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/src/benchmark.cpp)

采集关闭验证层、呈现和捕获，使用共享调度中的独占正式测量窗口。每次运行前后核对供电和热状态。Pixel 6 要求 Android 系统热状态为 0，RTX 4060 要求软件及硬件热降频标志均未激活，供电状态与合格试运行一致。热状态越界时保留排除记录，环境恢复后最多重试一次整个三路径区组。温度、时钟及供电来自运行边界观测，测量区间内部的瞬时波动仍可能影响结果。 [冻结门槛](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/evidence/2026-11-12-pixel6/formal-plan.json) [当次冻结采集脚本](D:/Projects/FYP/Project/AzureRender/build/runs/20261112-215615-thesis-pixel6-experiment-b05cd7/experiment.py)

## 统计单位与假设口径

每次独立进程分别计算 GPU 时间和 CPU 录制时间的均值、中位数、P95、P99 及样本方差。分位数采用排序后的线性插值。对一次运行的 GPU 时间序列，样本方差为各帧相对运行均值的离差平方和除以 `n − 1`，单位为 ms²，其中 `n = 1,000`。每个进程提供一个方差观测，路径比较以独立运行为单位。同一进程的连续帧用于估计该次运行的统计量，其自相关可能影响估计精度。 [统计实现](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/tools/analysis.py)

条件表汇总各独立运行统计量的中位数，保留实际运行数和计划运行数。同一区组内以传统路径或子通道为基准，计算运行平均 GPU 时间的百分比变化，再汇总配对差异的中位数、最小值和最大值。方差比较同时保留各次运行的值及低于同一区组传统路径方差的运行次数。当前统计工具提供描述性汇总，显著性检验、区间估计及拟合需在完整矩阵基础上说明所用方法。 [矩阵审计与结果表实现](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/tools/audit_experiment.py) [统计方法](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/docs/analysis.md)

H1 按已声明的附件模型比较估算量，并明确局部保留假设。H2 在固定分辨率和复杂度下比较 DRLR 与子通道的配对相对表现，再按设备解释差异。设备型号、驱动和平台共同变化，平台效应的外推受这组设备限制。H3 使用用户已确定的关联性表述，在设备、分辨率和复杂度内比较模型水平与运行方差。局部路径和模型值共同变化，两条局部路径又共享同一模型水平，因此模型值与方差的关联解释须包含路径机制和硬件因素的混杂。三项假设的正式结果由完整冻结矩阵产生。 [假设与统计口径](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/docs/analysis.md)

## 附件模型与硬件事务

令像素数为 P。共同负载的未压缩全帧等效附件访问模型包括几何阶段 16P 字节、卡通阶段 16P 字节及轮廓阶段 48P 字节，合计 80P 字节。局部复用场景假设反照率写回及再次读取、卡通阶段法线读取由局部交换覆盖，合计减少 16P 字节，场景估值为 64P 字节。轮廓阶段所需的法线存储及邻域读取继续进入模型。两条局部路径采用同一场景值。 [附件模型实现](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/tools/analysis.py)

模型结果的单位为未压缩全帧等效附件字节每帧。实际 GPU 硬件事务还受到覆盖率、缓存、压缩、驱动合并及事务粒度影响。硬件事务数量需要记录独立计数器、工具、单位和采样区间。本批数据的模型字段为 `hardwareMeasured=false`，可观测结果包括时间戳、命令计数和附件模型。H1 与 H3 对流量的解释须注明这一证据范围。 [模型字段与假设](D:/Projects/FYP-worktrees/thesis-paths/Project/AzureRender/experiments/thesis/tools/analysis.py) [检查点运行级统计](D:/Projects/FYP/Project/AzureRender/build/runs/20261112-215615-thesis-pixel6-experiment-b05cd7/analysis-checkpoint-2026-11-16/checkpoint-run-summary.json)
